# 再帰型グループへ状態識別を移す仮説

2026-10-19、実装前の計画。copy全域可換条件とは別に、Wasm GCの型同値性を制御状態の識別へ使う候補を検査する。暗号学的秘匿性・解除不能性は目標にしない。

検討した方向は、(A) copy操作集合に合わせた状態表現合成、(B) copyを履歴DAGへ遅延する表現、(C) 型グループの所属で状態の意味を決める表現。Aはdata refinementと前回の制約の延長、Bは永続配列・copy-on-writeと要約解除に近い。今回Cを早期実装するが、これらを独創性を確認済みの新発明3案とは数えない。

Cの具体案：有限状態機械の状態番号を、形の同じ空のGC structの参照へ置換する。rec group内の位置により型を区別し、同一groupの別複製にある型をref.testで照合する。group内に実行上使わない兄弟型を含め、その型同値性がgroup全体に依存する構造を検査する。cloneでの同値性を保ちつつ型番号と意味状態の一対一の対応を崩す。手動binary writerを使い、assemblerの事前canonicalizationを避ける。

既に読んだGC提案MVP.mdは、groupのrollingとbottom-up canonicalizationによって型同値性を効率的に判定できると明記している。したがって「再帰だから解析困難」は採用しない。数値状態、単一groupのGC状態、複製groupと兄弟型を持つGC状態を比較し、方式既知のcanonicalizationと状態機械抽出を実装する。

保護目標は、配布binaryから等価な有限状態機械を回復する費用を増やすこと。原型の名前、行順、生成seedの同定は要求しない。実行側はpacked tableと条件分岐版も比較する。原プログラムは2文字の最大16状態scannerで、公開関数run(x,n)はxの下位からn&31 bitを読む。memory/import/trap/外部参照を持たない。一般Wasm変換を装わない。

成功条件：値保存・最適化後の保存に加え、通常GC状態版に対して型group機構が追加解析費用を生み、その費用がファイルの単なる増大と区別できること。近い既存研究から独立した技術差の確認も必要。全条件を回復できても費用を測る。通常の型正規化だけで同じ状態数へ戻るなら、その事実と費用を記録し主発明として採用しない。

Node/V8で境界・全短語・乱数による差分検査、Binaryen O3、可能なら別の実行器、同値groupを壊す負の対照を実施する。GC未対応のツールを耐性としない。実行時間・サイズ・線形memoryとprocess RSS・変換時間・解析時間を保存し、生成物とsource hashを再現確認する。
