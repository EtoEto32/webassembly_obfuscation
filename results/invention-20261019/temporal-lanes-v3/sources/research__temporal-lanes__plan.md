# 時間の異なる状態を同じSIMD命令へ詰める候補

2026-10-19、実装前。前回のcone-patchは局所更新を高速化できたが、固定のEを抽出した後に状態全体を逆変換できた。今回の候補は値の符号化ではなく、元ループの時間対応を変更する。

候補を比較した：(1)コピー履歴を遅延表現する方式は既存の永続データ構造・copy-on-writeとの差が薄い。(2)通常SLPによる異種処理の混載はlane単位のscalar化で元のDAGに戻る。(3)状態を持つ直列段の各laneを異なる論理時刻で更新する方式を、今回の実装対象とする。これらを新発明3案と主張しない。

対象は、i32状態を持つ直列cascadeをT回評価し、最後に全状態をmemoryへ書き出すWasm関数。状態iの次値は自分の旧値と、同じ論理iterationで更新済みの直前段を使う。物理tick tで段iの論理iteration t-iを実行すれば、前tickの直前段が必要値となる。fill/drainをmaskで処理し、4段をi32x4へまとめる。更に各4段のlane配置を入れ替える。全演算は実際の状態更新で、偽の処理の追加ではない。

仮説：元のiteration境界が一つのsnapshotから消えることで、元の段順・更新則の回復に追加費用を課し、SIMDで実行負荷を抑えられるか。比較は元の逐次loop、scalarの時間変更、SIMDの自然配置、SIMDのlane混在配置。元の順序付き段更新を再構成する方式既知の解析を試す。公開バイナリしか渡さず、元の係数や生成seedを使わない。

software pipelining、retiming、SLPは既知。Leiserson/Saxeのretiming、Tristan/Leroyのsoftware pipelining検証、ベクトル化を含む既存難読化特許との照合が必須。Wasmへ実装したことや時間軸をずらしたことだけを新規性としない。fill/drainのphaseが元段順をそのまま明かす場合は、その回復費用と実行費用を測って棄却を判断する。

意味保存はsealedな非共有領域に限定する。途中のhost callback・trap・メモリ観測を持つ任意loopへ一般化しない。回数上限の元trapと終了時の全memoryを維持する。有限差分試験、別実行器、誤maskの反例、source hashとbinary再現を保存する。
