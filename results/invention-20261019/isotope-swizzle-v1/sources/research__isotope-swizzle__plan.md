# SIMD 内の符号化された演算表：反証実験

2026-10-19、実装前に固定。新規性を確認済みの発明ではない。

前回の型同値性による状態識別は標準的な型正規化で解除できた。今回検討した原理は、コピーの履歴へ値を移す方式、有限の非線形表へ演算を移す方式、型の所属へ制御状態を移す方式。最後は前回実装済みであり、新しい三候補として数え直さない。履歴方式は永続配列と要約解析に近い。非線形表も Chow らの白箱実装と重なるため、主発明に採用する前の小さな反証実験に限定する。

対象は各 byte の下位 4 bit 上の add/sub/xor とその小さな DAG。各値に独立な 16 要素の置換を与え、二入力演算を入力復号・演算・出力符号化を合成した 16×16 表へ置換する。Wasm の i8x16.swizzle と bitselect で、線形メモリを使わず表を評価する。暗号鍵や暗号学的な秘匿性は導入しない。外部 ABI は i32 入力と i32 出力。

Wasm における小さな SIMD 表参照そのものは 2017 年の公式 proposal issue に既に記載されている。ランダム全単射を合成した表も既知である。今回の独立な問いは、この実装形式を通常の最適化がどこまで保存し、方式を知る解析者が小さな群の同位体を正規化してどれだけ安く演算を戻せるか。肯定的な発明の根拠として、命令数の増加や最適化後に表が残ることだけを使わない。

比較は plain、同じ置換を decode/op/encode として実行する対照、表へ合成した table。raw/O3、複数の式・seed を用いる。解析者は配布 Wasm と方式を知り、生成 seed・元の演算式・置換表の生成記録を使わない。表の部分式を抽出して、同値な「三つの小さい置換＋群演算」へ変換し、配布 Wasm 全体を再出力する。元の置換そのものの回復は要求しない。

正当性は WABT validation、独立な JS 参照、全 nibble 入力と byte 境界・乱数、raw/O3 の差分で調べる。可能なら別の実行器でも照合する。有限検査を emitter 全体の形式証明とはしない。解析費用・実行時間・サイズ・線形メモリ・process RSS・変換時間を保存する。単に全件回復しただけで無効とはせず、費用の増分と先行研究との差を別に判断する。

表の正規化は principal isotope の既知の構成に基づく。16 の小さな群なら全 4096 三つ組で結合律を確認できる。C16 と (C2)^4 を認識し、全 256 対で復元を検証する。その他の群・非結合的 Latin square・表の破損を拒否する対照も必要。未対応は耐性ではない。
