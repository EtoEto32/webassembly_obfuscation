# 等式条件からhost入力を直接構成する反例生成

2026-10-24。may-write閉包の実装・array検査後に固定した次の計画。Kとは別の発明数に加えず、限定解析器の構成的な反例生成として評価する。

## 仮説

等式連言Rについて、任意部分書込みの閉包は`R ∧ close_all(R)`である。このため有限API列の不一致があるなら、各importのmaskを「書かない」または「対象全cellへ書く」に制限しても、同じAPI列での不一致が存在する。API列の各境界からの逆伝播が等式連言に閉じることを使う。値に依存する制御や一般Boolean条件ではこの主張はしない。

非自明な等式を破る任意代入も、各sortに二つの異なる代表値があれば構成できる。全部のhost値をSMTで探索する代わりに、失敗したWPのatomを選び、対応する一つ/二つのfresh入力に異なる値を与える。その他は既定値でよい。ただし定数との不一致ではその定数と異なる代表を選ぶ必要がある。

## 実装

各APIの区間ごとの後続等式を逆向きに保持する。失敗したrankからAPIを選び、区間を具体的に実行する。read観測が既に違えばそのAPIを反例として記録する。may-writeで後続Rが既に偽ならno-opを選ぶ。そうでなければ全書込みでRを偽にする具体値を構成する。必須全書込みでは後者だけを使う。終了時の局所観測が同じなら後続状態と一つ小さいrankへ進む。parser・固定点表現は既存Kと共有するが、反例入力の探索にZ3を使わない。

途中で観測差が確定しても、そのAPI内の残る必須書込みは契約通り実行できる入力を補う。実行が返る/trapする位置とhost traceの差も確認する。元のSMT生成器を残し、反例長の一致を必須条件にはしない。

## 検証

旧256契約、may-write128契約、2-import対照の全否定storeで直接反例を生成する。具体BFS/SMTと否定判定が一致し、生成列をNode/Wasmtimeで再生できることを成功条件にする。反例について新たな最短性は主張しない。未対応や構成失敗を成功へ含めない。可能なら正式性能測定を別に固定するが、一回の試行時間を速度差の結論にしない。

独立した一般探索原理ではなく、等式言語の特殊化である。自然な用途や先行研究との差が未確立という全体判定は、この拡張だけでは変更しない。
