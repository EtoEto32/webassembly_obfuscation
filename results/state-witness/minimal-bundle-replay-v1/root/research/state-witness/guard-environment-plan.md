# 公開storeへのhost書込みを含む診断：事前計画

2026-10-24。既存Kは閉じたAPI列を対象とし、呼出し間の外部書込みを除外した。この前提は明記済みだが、exportされたmemory/tableを利用者が書き換えられる埋込みでは契約が弱い。初期一致条件を満たしても、両側への同じhost書込みがそれを壊す場合を調べる。

## 仮説と非主張

限定constant bulk APIの等式モデルでは、公開cellへの任意の共通書込みについて条件を閉じる操作を厳密に計算できる。通常APIの逆伝播と交互に固定点を取ると、host書込みを挟む全列についての初期一致条件を得られると仮定する。環境入力を共有する二項検証、contextual equivalence、普遍量化・不変条件は既知であり、別の一般的検証原理を発明したとは扱わない。既存Kの対象を現実的な埋込み契約へ広げる可否の検査である。

公開memory/tableのみに、各callの間で任意の同じ値を両側へ書けるhostを対象とする。非共有、停止中、容量固定、外部growなし。publicの観測だけでなくfull/returnsにもこの入力権限を独立に指定する。private cellへは書けない。hostが異なる値を左右へ与えるケースは比較対象にしない。tableは参照identityの等式モデルで扱い、任意参照の呼出し効果は対象外。

## 構成

左右cellの等式関係Rに対し、書けるcell xの左右を同一の新しい変数u_xへ置き換え、全u_xを普遍量化する。等式クラスに、異なる自由なu同士、uと定数、uと書けないcellが含まれるなら充足不能。同一cellの左右だけの等式は自動で成立する。書けないcellだけの等式は残す。この操作をE(R)とする。1回のhost書込みは公開footprint全体への任意代入で、書かないことも含む。

各寿命状態対qについて、G_0(q)=trueから、G_{n+1}(q) = E(G_n(q)) AND 各guest APIの一段観測一致 AND （継続可能なら）左右効果をG_n(q')へ逆代入、を反復する。host辺は寿命を変えない。trap終端後にはhostもguestも続けない。終了直前の公開store差は従来どおり観測に含める。

不成立storeからはrankの減るAPI又はhost代入を選び、反例を生成する。長さはguest callと一括host書込みを各1とする。これはguest呼出し数だけの最短性と異なる。host代入は等式に反する具体値を選ぶ。実装上の候補値探索の完全性は、値領域に少なくとも2値があることと、演算がcopy/constantだけであることから説明する。初期はbytesの0/1とtableのnull/外部定数関数を使う。

## 検証・採否

1. host書込みなしでは旧結果が変わらないこと、書込みあり条件が旧条件より弱くならないことを確認する。
2. 元exportだけの到達可能状態から、同じ公開書込みを挟む反例と、private又は上書き対照をNode/Wasmtimeで実行する。追加observer由来差と区別する。
3. 普遍量化する環境閉包を別のZ3式で検査する。任意Wasm全体の証明とはしない。
4. 前向き混合96 moduleを新契約で分類し、元の条件との変化を記録する。自然な実アプリの不具合件数にしない。
5. 既存の汎用CHCによる環境入力の符号化と比較する。単に既知の環境遷移を追加しただけなら、限定診断の拡張として採用し、強い新原理とは主張しない。

条件が全て充足不能へ崩れて診断上の区別を失う場合、又はhost書込み禁止契約しか実対象にない場合は、主成果への昇格を見送る。
