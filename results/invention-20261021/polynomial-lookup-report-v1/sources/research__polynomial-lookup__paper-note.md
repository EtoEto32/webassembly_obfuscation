# 静的データ構造の消去と意味回復の費用を分ける

## Abstract

読み取り専用連結リストの検索を、有限体上の集合多項式と値の補間多項式へ
変換する限定Wasmパスを実装した。ポインタを含まない生成物でも、公開係数の
因数分解から全辞書を回復できた。回復費用の増加は観測したが、実行負荷の増加と
既知構成の先行性を伴う。新しい難読化原理を確立した結果とはしない。

## Motivation / Related Work

過去の表現変換は独立decoderや通常の元演算が残り、そこから回復された。
本実験ではlookup全体を別の計算へ置き換え、node形式そのものを消した。
集合のroot表現はFreedman–Nissim–Pinkas (EUROCRYPT2004) §4.1に先行する。
同研究は暗号化した係数を扱う二者間protocolで、公開係数を配る本案の保護保証に
流用できない。補間とHornerも既知。NTL公式文書は有限体でのroot探索・因子分割を
説明する。こうした既知の処理がそのまま利用可能かを、実binaryから検査した。

追加検索ではEP1675031A1 *Watermarking computer program code by equivalent
mathematical expressions*の一次検索抜粋に、情報を多項式の根へ入れる説明と
factorizationへの言及が見つかった。本文open/findは取得できず、請求項の精査は
していない。近接する調査先として保持し、新規性否定や特許範囲の確定根拠にしない。
https://patents.google.com/patent/EP1675031A1/en

Galbraith–Liの代数集合のinput-hiding研究も要旨のみ確認した。多項式を使うという
共通点だけで本案と同一視しない。一方、Wasm移植やprime選択・u32端点処理だけを
独立した発明とする積極的根拠も得ていない。文献と読了範囲はplan.mdに記載。

## Threat Model / Proposed Method / Implementation

攻撃者は全binary・方式・実行仕様を知る。key/value辞書の回復が解析タスク。
元ソースのレコード順序まで再現する必要はない。方式はalgorithm.mdに固定した。
strictなsource AST照合、u32全域の分割、first-matchの保持を伴うPython生成器と
Wasm i64 Hornerを実装し、binaryのみを受け取る既知方式の回復器を別processで測る。
原データの秘密性を仮定したhostや暗号鍵は使わない。

## Evaluation

7入力集合の70条件、92,230呼出しで返り値が一致。別engine210probe、独立BigIntの
積・剰余4,312比較、3誤変換反例と4拒否対照を保存。raw/O3とpruningを含む28条件を
回復した。全binary/全入力の形式証明ではない。

128件でprunedのhit実行時間約623ns、配列対照約16.6ns。因数分解を含む解析は
読取込み約670ms、配列対照約22ms。前者はNode/V8、後者はPython専用解析器の
実測で、両値を直接割って保護強度を定義しない。Pruningによる約33%短縮は
既知の零多項式除去に由来し、新規性の根拠とはしない。

## Discussion / Limitations

回復できること自体は難読化の否定ではない。今回、有限の追加解析費用はある。
ただし単変数の公開多項式にすべての情報が集まり、既知の因子分割で全内容が
回復する。最適化された数式処理libraryによる最短攻撃費用は未評価。
さらに構造の消去は配列化でも達成できる。同じ辞書の異なる配置が同一binaryに
なる事実を、追加の意味回復耐性と混同してはいけない。

固定辞書だけを扱い、可変構造・共有memory・pointer副作用や汎用型回復器を
評価していない。3つの既存入力は1百万未満のkey、全u32域の乱数入力は64件の
1集合。境界・重複・空集合は正当性対照であり、7種の実アプリと称さない。
一つのWindows/V8環境、3processの性能測定である。CPU固定・周波数制御は未実施。

## Conclusion

局所decoderを消す変更は実装でき、解析費用の増加も測定できた。しかし今回の
具体則は既知の集合表現・補間からの独立性が弱い。主発明には採用せず、構造回復と
等価な計算の回復を分ける実験資産として保存する。特許性の結論は出さない。
