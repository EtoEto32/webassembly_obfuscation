# 係数回路の構成と成立限界

R=Z/(2^32)とする。受理する実バイナリは、export run(i32,i32)->i32を持つ単一関数、
純粋なadd/sub/mul、定数、local、分岐を持たないblockである。
各ノードは形式的に斉次で、加減算の両辺は同次数、積の次数は和とする。
局所定数畳込み・零/一の簡約はするが、任意の意味的斉次性を判定する実装ではない。

出力次数d、1<=k<=min(d,32)、c=binom(d,k)が奇数であることを検査する。
次数上限は4096。memory、global、call/import、浮動小数、bit演算、一般制御フローを拒否。
custom/debug sectionの保存は保証しない。

```
jet(input x,j) = x if j=0 or 1, otherwise 0
jet(constant a,j) = a if j=0, otherwise 0
jet(A +/- B,j) = jet(A,j) +/- jet(B,j)
jet(A * B,j) = sum_{i=0..j} jet(A,i) * jet(B,j-i)
return inverse_mod_2^32(c) * jet(root,k)
```

要求された(node,order)をmemo化し、最終出力から到達できる演算だけWasmへ出す。
これは既知の打切り係数算術。零次係数を禁止する構成ではなく、必要な元の中間値を保持する。
上位係数だけを返すことから、実行中に元の値が出ないとは主張できない。

帰納的に各jetは `F((1+t)x,(1+t)y)` の係数を計算する。
形式斉次性からこれは `(1+t)^d F(x,y)` なので、出力は厳密にFである。
整数環での恒等式は剰余化と両立し、i32のwrapをそのまま使える。
奇数cには逆元がある。偶数cには一般的な逆元がなく、本プロトタイプは拒否する。
この説明はコンパイラ実装全体の機械検証済み証明ではない。

同じ議論は次数eの中間ノードにも成立する：第j係数は `binom(e,j)*v`。
したがって係数回路への持ち上げ自体を、新しい隠蔽原理として説明するのは弱い。
ただし、この恒等式だけから、未知の変換済みバイナリを常に線形時間で元DAGへ戻せるとは結論しない。

## 実装した解析

攻撃者は方式と配布Wasmを知る。生成元DAG、次数d/k、係数ログは回復器へ渡さない。
WABTで読取ったlocalをSSA式へ変え、各節点を指数対(i,j)から係数への辞書へ評価する。
積は疎畳込み、加減算は係数合併。定数left shiftはmod32の乗算へ直す。
最大4096項/次数4096で打ち切り、対応外はunsupportedとする。
これは一般Wasm解析や任意多変数の多項式時間解析ではない。

回復目標は係数表とそれを評価するHorner実装。元の因数分解・変数名・元DAGは対象外。
同じ解析を未変換版にも実行する。元の係数表は事後の採点にだけ使う。
本体の解析時間は11反復、読取は別に1回、コンパイル時間は解析本体に含めない。

## 有限環の関数と形式微分の区別

`N(x)=2^(w-1)*x*(x-1) mod 2^w` は任意の整数xで零である。
一方、その形式微分 `N'(x)=2^(w-1)*(2x-1)` は常に2^(w-1)である。
同じ零関数の表現 `0` の微分とは異なる。
従って「同じWasm関数なら形式微分も同じ」という意味関数上の操作にはできない。
今回の構成は特定の形式式を検査して変換するので、この反例で正当性が否定されるわけではない。
一般的な微分変換の拡張で表現の違いを無視してはいけないという制約である。
この初等的反例を新しい定理とは主張しない。

## 今回の判定

最適化前後とも係数表を回復できるが、回復版は元の因数分解を失うため実行速度を改善しない。
解析費用の増加は測定上存在する。これを「何の効果もない」と否定しない。
それでもHasse係数算術と斉次性の直接利用から独立した生成規則は確立できず、主発明には採用しない。
次数変更や一般的なjet表現への再移植だけを別原理の新案に数えない。
