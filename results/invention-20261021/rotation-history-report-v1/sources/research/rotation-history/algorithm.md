# 観測履歴の構成と、入力依存回転に対する制限

## 固定回転の履歴生成

w-bit語に対し、Aをk-bit左回転、Mを非零の観測maskとする。元の状態更新は
`y[t+1]=A(y[t]) xor u[t]`、公開出力は`o[t]=y[t]&M`。
rotateとxorはbitベクトル上で線形である。この既知の性質を使う具体的生成器であり、新しい線形化の理論ではない。

次の出力に必要な現在のbit集合はN=A^-1(M)。各bitを、それが現れる最も近い過去の観測に割り当てる。

```text
remaining = A^-1(M)
for age = 0 .. w-1:
    S[age] = remaining & A^age(M)
    remaining &= ~S[age]
    T[age] = A(S[age])
    if remaining == 0: stop
H = number of ages
U[0] = M
U[j] = union(T[age] for age >= j), 1 <= j < H
```

回転の位数はwを割り、age=w-1ではA^age(M)=A^-1(M)になるので、全bitを遅くともこの時点で割り当てられる。
Tは互いに素で、その和集合はM。履歴長Hは1..wの範囲である。

```text
o[t+1] = (u[t]&M)
         xor XOR_age (A^(age+1)(o[t-age]) & T[age])
         xor XOR_j>=1 (A^j(u[t-j]) & U[j])
```

理由：`A^age(y[t-age])`と`y[t]`の差は、それ以降の入力を回転してxorしたもの。
各Sの範囲でその入力寄与を補い、最後にAと観測Mを適用する。異なるSの重複がないので、入力項のmaskをUへまとめられる。
この導出はすべての語に適用できる代数的な説明であり、変換器全体の機械検証ではない。

開始前の入力を仮想的に零とし、履歴を`o[-age]=A^-age(seed)&M`で初期化する。
元のload順序を維持し、履歴はWasm localに置くため、公開memoryの副作用を追加しない。
sourceとhistoryは同じwrapしたアドレスを同じ順にloadする。範囲外アクセスでは同じ時点でtrapする。

## 公開seed APIからの回復

対象profileは`run(seed,pointer,length)`を公開する。このAPIを使う方式既知の解析者には、
長さ0で各基底seed `1<<j` を問い合わせるとMが分かる。
入力wordを零にして長さ1で同じ32基底を問い合わせると、`A(1<<j)&M`が得られる。
0..31のk候補を列挙し、その全応答と一致するものを選ぶ。
Mが非零なら、観測bitの一つへの入力位置がkを決めるため一意になる。

合計64問い合わせ。sourceとhistoryの両方へ同じ手順を適用する。
これは既知のsource familyを識別する算法で、64個の値が一致した任意のWasmが全入力で同じだという証明ではない。
回復後には元とのbyte一致と有限差分テストを別に実施した。任意seedを受け取らないAPIへこの回数を一般化しない。

## 入力依存回転では一定長の実際の履歴だけで足りない

次を別の入力付き系とする。M=2^m-1、5<=m<32、初期状態y=0。

```text
y' = rotl32(y, u&31) xor (u&~M)
o  = y'&M
```

任意の有限Hを固定する。最初の入力zをMの外だけにbitを持つ値とし、その後H個の零を入力する。
zの下位5bitも零なので、最初も後続も回転は起きず、状態はzのまま、全出力は零となる。
この時点の最後のH個の入力・出力、時刻、初期seedは、すべてのzについて同一である。

異なるz,z'には異なるbit b>=mがある。共通の次入力を`u=32-b`とすると、
下位m bit内の入力なので追加注入は零、bit bが出力bit0へ移り、二つの次出力は異なる。
従って、最後のH個の実際の入出力だけを状態にした決定的な実装は、どの有限Hを選んでもこの全入力挙動を再現できない。

さらに2^(32-m)個のzは、適切な同一の将来入力で互いに区別できる。
最後のH個の入出力以外に保持する状態には、少なくとも2^(32-m)個の区別、すなわち32-m bit相当が必要である。
制御位置などへ情報を移した場合も、その追加状態に含める。

これは**一定長の実際の観測履歴だけへの置換**に関する制限である。
符号化した隠れ状態、入力全履歴の再実行、別の情報を蓄積する状態変数を持つ実装まで不可能とは言っていない。
有限個の実行例がこの全Hの論証の代わりになるわけでもない。
入力依存rotateを入れるだけでは、固定回転の履歴式をそのまま拡張できないことを示す。
