# 回復費用の追試と判断の訂正

2026-10-18。[改訂した評価方針](../evaluation-policy.md)、[実行前の計画](cost-reassessment-plan.md)、[全比較表](../../results/invention-20261018/connectivity-cost-reassessment-v1/summary.md)、[生データ](../../results/invention-20261018/connectivity-cost-reassessment-v1/analysis.json)。

**難読化に解除不能性を要求しない。前回の全75条件の復元成功だけを、保護効果がない理由にしない。** 元の式とグラフ表現の差、頂点消去を追加した差、方式を知る解析者がアルゴリズムを変えた差を分離した。この追試は新しい難読化方式ではない。

## 過去の結果から言えたこと

前回のO3測定では、グラフ表現の解析時間は元の式に対して6.24～1,989.94倍だった。同じ条件の実行時間は4.30 / 7.11 / 3.67 / 419.70 / 3.85倍、サイズは8.59～41.10倍だった。解析時間の倍率だけを保護強度や実用性と解釈しない。3回の同一プロセス内測定であり、微小な時間差の統計的な有意性も未確認である。

消去は前回の伝播解析を短縮した。したがって、**追加した消去規則が、その解析法に余分な費用を与えたという仮説**は支持されなかった。一方で、グラフ表現自体の解析費用増加をゼロと扱うのは誤りだった。

## 追加した適応的解析

[cost_reassessment.py](cost_reassessment.py)は配布Wasmの公開descriptorとlabel DAGを読み、端点以外の頂点を最小次数順または最小fill-in順に消す。二つの隣接辺の条件のANDを、既存の辺の条件へORする。この既知の接続代数は、実行時の反復伝播を追跡せずに出力条件を求められる。元の構文木を取り戻す必要はない。

元式、seed、対応表、fixture、期待するhashは解析関数へ渡さない。結果照合でのみ旧hashを使う。固定したABI変数順のBDDを用い、100,000ノードの上限を継承する。familyを知る解析であり、任意WasmからのVM自動同定ではない。解析器の開発時間は測定していない。

ラベル処理、memory/bodyモデル構築、BDD処理、頂点選択の費用を含む。WABT逆アセンブル、結果hashの計算、Wasm生成を除く。各条件1回warmup後、cacheを毎回破棄して5回測定。処理順は固定seedでshuffle。旧性能測定は再利用し、新たなWasm性能測定を行ったとは記載しない。

## 結果

75本について、plain/MBAの直接解析30条件、グラフ群45本×3解析法の135条件、計165条件の解析が成功した。予算超過・未対応・例外・意味hash不一致はいずれも0。新しい2解析法の復元Wasm90本は、以前の復元バイナリと全てbyte単位で一致した。

[V8実行結果](../../results/invention-20261018/connectivity-cost-reassessment-v1/correctness.json)は90条件・83,088呼出し・不一致0。既存の境界値、random、n≤12のpacked全Boolean入力を再利用した。新しい独立入力数へ加算しない。別途、自己辺・並列辺・孤立端点を許す280の小グラフを、3変数の全8入力で独立のBoolean BFSと照合し、2解析法で4,480比較・不一致0。不正descriptorの4対照を拒否した。有限試験を全系の証明とは呼ばない。

代表値（O3、中央値）：

|式|元の直接解析 ms|グラフの伝播 ms|グラフの最小次数消去 ms|最小次数消去 / 元|
|---|---:|---:|---:|---:|
|Ch|0.0138|0.0909|0.0627|4.54倍|
|Maj|0.0174|0.1580|0.0937|5.39倍|
|mixed12|0.0595|1.1604|0.1150|1.93倍|
|parity16|0.0941|216.6324|4.1124|43.70倍|
|blend24|0.3229|11.3996|0.4178|1.29倍|

この表は最小次数法を一律に選んだ比較で、各行の最速法を無料で事前選択できたとは仮定していない。例えばblend24は最小fill法で0.3835 msとなった。最小次数法のグラフ解析には1.29～43.70倍の時間増加が残るため、「解析費用の増加がない」とは結論しない。ただし絶対時間は0.063～4.112 msであり、実行・サイズ増加やtoyの学習可能性も踏まえると、実用的な独自の保護方式の確立を支持するには足りない。

頂点消去の効果も解析法で異なる。mixed12では80%消去後の最小次数解析は0.1639 msで、消去前の0.1150 msより長い。一方、実行は旧測定で591.4→286.7 ns、サイズは799→1,037 bytesとなる。これを「全解析を常に速くする」と一般化するのも誤りである。少数の同一プロセス試料、3種類の実装済み解析法に限定した観測であり、新規性や実用性の実証ではない。

## 研究上の判断

グラフ表現を採用しない判断は維持するが、理由を限定する。既知代数からの具体的な新規差分、現実的な保護対象、負荷を揃えた既存方式への優位性が未確立である。全件回復できること自体は棄却理由にしない。元の中間表現を隠す変換では、解析者が別の表現へ移る費用まで比較する必要がある。

次の候補では、主たる解析タスクを先に固定し、実行・サイズの複数予算下で解析時間または問い合わせ数の曲線を比較する。特定の解析器がわざわざ高価な実行順序を追跡し続けることを前提にしない。解除できる候補でも、費用増加が実測され、新規差分と実用上の価値があれば採用対象とする。

## 再現

リポジトリrootで実行。Python 3.9、Node 24.15.0、ローカルWABT 1.0.42 / Binaryen 133。元の結果ディレクトリを入力とし、新しい出力先を指定する。既存出力先は拒否する。

```powershell
python research/connectivity-elimination/cost_reassessment.py results/invention-20261018/connectivity-elimination-v1 results/invention-20261018/connectivity-cost-fresh
node research/connectivity-elimination/cost_verify.cjs results/invention-20261018/connectivity-elimination-v1 results/invention-20261018/connectivity-cost-fresh
```

元の入力も作り直す場合は[元の再現手順](README.md)を先に実行し、両コマンドの入力ディレクトリを置き換える。今回の結果には使用したソースのsnapshotを保存した。現時点でこの追試を別出力先に再実行したとは主張しない。
