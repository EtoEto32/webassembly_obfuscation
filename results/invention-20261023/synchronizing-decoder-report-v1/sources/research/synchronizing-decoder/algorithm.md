# 重みを伴う同期語による計算の生成

2026-10-23。新規な難読化の完成ではなく、仮説を実装して反証した記録である。同期語・重み付き同期は既知であり、今回の主な作業はmod2^32の重み生成、実Wasmへの変換、方式既知の回復との比較である。

## 仮説と限定profile

分岐履歴に依存する解釈状態を可逆更新だけで一意に合流させる以前の条件には矛盾があった。本案では非可逆な遷移を使い、未知の入口状態qから、同じ算術結果と終状態へ到達する命令列を作る。個々の命令を固定の算術命令に対応づけられないことが、解析に追加作業を要求するか検査する。

試作は任意CFGの合流処理まで実装していない。未知の入口qを引数から計算するhelperに同期の原始操作を実装し、元Wasmのifは維持する。qを元の全basic block間で持ち回るコンパイラではない。局所helperの意味回復が安いという反証が得られたため、その大規模化には進まない。

入力は単一の`run(i32,i32)->i32`をexportし、i32 local、if、totalな算術を使う実`.wasm`。memory、global、table、import、call、浮動小数、division、その他の命令は受理しない。`x+a*y+b`（x,yはlocal、a,bは定数）の部分式を置換する。変換後は固定1pageの非公開memoryとhelper一つを追加する。OOM、時間、fuel、debug位置は意味保存の観測に含めない。

## 同期と重みの生成

R=Z/(2^32)、q∈{0,...,n−1}、n=4,8,16とする。二文字の遷移はA(q)=(q+1) mod n、B(n−1)=0、その他のB(q)=q。語

`w = B (A^(n−1) B)^(n−2)`

は全入口を0へ送る。最初のBで状態集合は{0,...,n−2}となり、続くA^(n−1)Bごとに上限が一つ減るためである。長さは(n−1)^2、Bはn−1回現れる。既知のČerný型同期語を用いており、この構成自体を新規としない。

各入口から語を読むときに通る各辺の回数を行列C∈N^(n×2n)へ記録する。辺eで`z←z+α_e*y+β_e`を実行するため、全入口でCα=a·1、Cβ=b·1がmod2^32で成立すれば、語全体が元の更新になる。

```
C := 全入口からwを実行した辺訪問回数
V := Cの有理nullspaceを分母払除して得た整数basis
α0 := A辺0、B辺 a/(n−1) mod2^32
β0 := A辺0、B辺 b/(n−1) mod2^32
α := α0 + Σ random_i * V_i mod2^32
β := β0 + Σ random'_i * V_i mod2^32
全入口の結果係数と終状態を検査
辺の(next, α, β)と語をprivate memoryへ出力
```

n−1は奇数なので逆数が存在する。整数basisはmod2^32のkernel全体を列挙するとは限らないが、生成した全vectorはCにより0になる。均等分布や最適な難読化を主張しない。

syncでは入口q=(x XOR y) rem_u n、fixed対照ではq=0。実行は公開される遷移表を読み、各文字について算術更新とq更新を行う。秘密鍵、暗号学的な非可読性、外部の秘密は仮定しない。

## 意味保存と単純な補正形との差

helperの各prefixの値は、元xに、それまでのαの和×yとβの和を加えたものになる。語の末尾では係数制約によりx+a*y+b、q=0。全ての整数演算はWasmと同じmod2^32。表アクセスは有効なqと文字から計算され、固定memory内に収まる。x,yの読取りは副作用がないlocalなので、呼出しへの置換によって元の観測を変えない。

生成した96個のgateではBの二つの自己loopに異なる(α,β)があった。従って辺重みが常に`φ(q')−φ(q)+c_letter`となる単一の加算potentialでは説明できない。自己loopではpotential差が0になるためである。これは任意の非線形表現への還元が不可能という証明ではない。

## 方式既知の回復

回復器はbinaryだけを読み、helperをaffine抽象値(c_x,c_y,c_0)で解釈する。文字、q、counter、表アドレスは具体値、xとyは記号値として扱う。加算と定数倍は正確に閉じる。データ依存のbranch、動的address、二つの非定数の積などは拒否する。Wasmのblock/loop/ifのlabel depth、local.teeの評価順を追い、計算された各結果が同一の(1,a,b)なら元のaffine式へ置換できる。

full解析は入口qを全て検査する。これはhelper内の全x,yについての係数による検証であり、表やprivate stateを恣意的に無視する近似ではない。一方、方式が同期するという約束の下で候補だけを得る場合は、代表q一つで十分である。代表解析そのものは不正な入力・未知の生成族の同値証明ではないが、今回の全12sync条件でfull解析とbyte一致の回復先になった。

反証の核心は、同期によって入口の違いを消す保証が、解析者にも代表一つを選ぶ理由を与える点である。全状態の検証費用を、同等計算の候補を取り出すのに必ず必要な費用と混同できない。
