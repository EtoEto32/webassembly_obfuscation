# 値依存配置の実測集計

主実験は3種類の小さな状態更新kernel。正42条件、共通468入力列、19,656呼出し（期待trap 5,040件）で戻り値・trap有無・復号した全メモリが一致。負6条件はすべて反例を得た。
公開binaryだけから18/18条件の通常配置候補を構成し、その候補も主実験で比較した。各回復は同じ1,024 helper呼出しで同定する。有限の同定試験は任意binaryの全入力同値性証明ではない。
42本をbyte一致再生成。別WABT実行器は値168、trap 42、物理メモリprobe 840件を照合。0/2ページの追加8条件520呼出しも一致。
縮小幅1/2/3bitで135,296更新を全探索、32bit乱数で4,096更新を比較。モデル検査と実Wasmの呼出し数は加算しない。

## 方式既知の回復費用

O3各条件7回、計63回。WABT読取・計測用binary生成・Node起動・helper同定・候補のコンパイルを含むend-to-end ms。純粋な記号解析時間ではない。

| coupled | 116.17 (113.71–120.99) | 118.99 (115.26–122.85) | 119.50 (116.55–138.46) | 1.029 |
| xor | 118.75 (114.68–130.77) | 120.05 (116.70–124.00) | 120.73 (115.56–125.09) | 1.017 |

差分移送は同じ動的表現のfull版より約12～19%速かった。固定配置に対する回復時間の中央値比は約1.017～1.055で、範囲は重なる。問い合わせ数の増加はない。全体復号を省く実行改善と、追加保護効果を区別する。

全本体はlinear memory 64KiB、追加配置表・追加ページは0。Node maxRSSは36,408–37,268KiBで実行環境全体を含む。変換時間は単回測定で42.45–49.49ms。本体サイズはfacts.jsonのbinariesに保存。

既存の動的符号化との独立性、実用的な保護優位、実アプリでの適用率は未確立。今回の公開統計量は実行側と解析側の双方に安い配置の復元手順を与えるため、主発明への採用は見送る。
