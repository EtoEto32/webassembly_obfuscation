# 公開履歴に応じた累積予約の検査計画

2026-10-24、実験前。Fの拡張仮説であり、原理の異なる第四案として数えない。

目的は、既に公開済みのevent列だけから秘密経路の候補を絞り、不要になった論理opcode予約を返せるか調べること。秘密の実測費用で返金すると漏れる。未公開の将来出力で先に予約額を選んでも、公開時点を早めてしまう。予約の判断を公開履歴のみに制限する。

有限・非trap・非再入のCore Wasm、整数演算、void if、定数id/payloadのmarkerを対象とする。各構文経路を列挙し、同じ公開prefixを持つ経路の「次のmarker又はreturnまでの累積費用」の最大値を作る。入口でrootの額を予約し、markerを公開した後で次の最大値へ残高を調整する。新上界が低ければ返金する。返金後の累積予約は当該履歴で可能な過去の実費用を下回らない必要がある。

基準: 全関数予約、event深さだけを使う累積予約、公開履歴で絞る提案、独立した実行経路から作る手書き履歴予約。Naiveな秘密依存返金・未公開出力先読みを負の対照にする。境界値と固定seed入力、予算範囲、公開履歴が同じ秘密対、低予算のprefix進捗を測定する。正常時の返値とevent一致、各prefixで予約≥実費用を別に照合する。実時間や実runtime fuelの保護とは主張しない。

成功条件: 少なくとも一例で深さ予約より低い拘束額又は返金を確認し、同じ公開履歴までの会計が一致すること。大きい公開入力を事前に全部公開したことにして費用を隠さない。過大な経路近似、経路爆発、計算時間、binary/sidecar sizeも記録する。実現できても新規性・特許性を同時に成功扱いしない。

先行反証: Zhang/Askarov/Myers CCS2011のpredictive mitigationは公開情報に応じたscheduleを既に扱う。Ene/Mounier/Potet『Output-sensitive Information flow analysis』LMCS17(1:15),2021, DOI10.23638/LMCS-17(1:15)2021は最終公開値で許容する漏洩を定義する（現在abstractのみ）。重み付きautomataのobserverも近い。公開履歴、max計算、declassification自体を新しいと主張しない。静的な予約額と停止点、返金後の支払済み費用の不変条件を具体的差分として検査する。
