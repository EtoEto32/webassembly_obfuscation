# 設計見直し：公開payloadが計算移動を制約する場合

2026-10-24。preopt-v1でconstant markerの6/7例のifが通常O3で消えたことを受け、次の仮説を固定する。

公開通知が計算値の一部を返す場合、全計算をmarkerの後へ移動できない。`mark(id, releasedValue)`という明示的公開APIの値を、契約上の出力として扱う。秘密の全情報を隠すのではなく、元の公開event payload・最終返値が同じ2実行について、fuel残高・予算停止が追加情報を出さないことを目標にする。

手書きWATの2段mix pipeline、Rustの同じ計算を、通常O3**の後**で計量する。必要なら標準的なBinaryen flatten passを全対照の入力に共通適用する。normalizationの実行時間・サイズを記録し、元binaryとnormalization後を差分実行する。loopやmemory accessの対応を広げない。

変換器は引き続き定数idの列を照合する。第2引数だけを明示的に公開してよいものとして受理する。1引数版の秘密marker拒否を緩めない。第2引数の全命令費用も上界に含める。

secret flagの0/1でmixを(12,1)/(1,12)回に分け、markerには中間値の上位4bit、返値には最終値の上位8bitを出す。全体のmix回数は同じなので同じpayloadの最終返値は一致する。中間の4bitも一致するpayloadを独立oracleで列挙し、その同一公開traceの範囲で低予算の比較を行う。都合の良い入力だけを実行するのでなく、全入力の値とtraceを照合したうえで、公開traceの一致群と不一致群を分けて集計する。

これは自作小例であり第三者用途ではない。ここでも最適化に消される、あるいは強い既存対照より効果がない場合、主発明としての優先度を上げない。

## v5後の第3設計

Rustの2/sでは同じ有限分岐がblock/brとして表れるため、flattenしたWasmから非循環の重み付き制御グラフを作る解析を追加する。block/ifのラベル深度を解決し、分岐先の残りevent列を照合し、入口から各event位置までの最長費用を合成する。loop/再帰は引き続き拒否。各グラフ辺は後に作成済みの継続へ向かい、cycleがあれば拒否する。block自体の費用は0、br/br_if/returnは1と定義する。既存の式・local・call費用は変更しない。

これはpath feasibilityの解決ではない。通常のDAG最長路とtrace照合が基盤であり、この追加だけを新原理とは数えない。上界は別interpreterの実費と照合する。
