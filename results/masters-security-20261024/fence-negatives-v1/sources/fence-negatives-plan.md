# Aの信頼前提を外す負例

2026-10-24。生成器の型検査が業務認可を証明するとの誤解を避けるため、明示的に契約違反のhostを3種類作り、試験用新規ファイルにだけ接続する。成功条件内の攻撃耐性評価としては数えない。

1. WIT上は妥当な契約だが、copy先にwriteでなくreadを注釈する。write失効後にも誤った検査が通り、copy先へ書けるか。
2. 正しい依存を保存した後に、executorがmutableな送信先を読み直す。依存にない失効済み実体へのwriteが生じるか。
3. executeSyncという契約に反してawaitを含む関数を渡す。host内の論理受付後、失効を挟み、実OS呼出しが後から発生するか。これは「受付前失効を防ぐ」という定義そのものの反例とは限らず、実効果側の受付とhostログの時点を同一視できない例として区別する。

raw/optそれぞれ実Component経由で試す。修正対照は、正しいwrite契約、固定送信先、同期executorである。単純なログでなくファイル内容を独立に観測する。反例成立時の結果を正常動作の成功件数へ加算しない。
