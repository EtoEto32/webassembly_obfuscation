# 修士研究と両立するWasmセキュリティ発明候補

作成日: 2026-10-24。ユーザーの指定により、難読化以外を含むWasmセキュリティへ範囲を拡張する。既存の難読化実験を新発明として再計上しない。

## 実験前の仮説

1. **A: 呼出しの権限依存を具体化する失効フェンス。** インターフェースの実引数から、使用するリソースの実体・スロット世代・操作権限の世代を固定する。実効果の直前に、その依存だけを再検査する。入口だけの検査に比べ失効後の効果を防ぎ、全体世代の検査に比べ無関係な失効による拒否を減らす。ただし世代付き権限・コミット時認可・依存追跡は既知であり、型からの生成部分に独立した差があるか未確認。
2. **B: 再入時の書込み範囲の証拠から退避範囲を生成する境界アダプタ。** ホストが再入前の値を必要とする読取り集合Rと、検証したWasm callbackの書込み上界Wから、R∩Wだけを保存する。戻った後は保存部分と未変更部分を組み合わせる。コード同一性・完全な効果要約・非共有メモリが前提。部分コピー自体は既知である。未知の効果はR全体のコピーに退避し、黙って安全扱いしない。
3. **C: タスク解決と資源消滅を分ける予約保存則。** キャンセル要求、Component Model上のタスク解決、ホスト側資源の実際の解放を異なる事象として管理する。資源ごとの予約は実解放まで所有者を保持し、返却は一度だけ行う。一般のセマフォ・参照カウント・クォータ管理との近さが大きい。型付き非同期境界からの解放条件生成が差分候補。

## 最小実験の範囲

- 実Wasmの小さいguestと、信頼するNodeホストの境界で再現する。
- Component Model/WIT/WASI 0.3の完全な実装や既存ランタイムの脆弱性実証とは呼ばない。
- ファイル・ネットワーク等への実副作用は用いず、ホスト内の模擬sink/有限資源で検査する。
- raw/O3のWasmをWABTで検証する。値・状態・拒否理由を独立した期待値と比較する。
- A: 入口検査、全体epoch、リソースepoch、操作別依存epochを比較する。
- B: 全Rコピー、Wasmからの範囲生成、コピーなし、手書きの正確な範囲を比較する。強い手書き対照より速いとは予断しない。
- C: キャンセル時返却、タスク解決時返却、実資源解放時返却を比較する。正しい実資源セマフォを強い対照とし、同じ挙動なら独立した安全性の新規性を主張しない。

## 採用・棄却の基準

有限試験で不正な効果／スナップショットの不一致／資源上限超過が1件でもあれば、前提漏れを修正するまで安全とは扱わない。模擬ホストの故意に弱い対照に勝つだけでは新規性の根拠にしない。WIT自動生成、実ランタイム適用、意味保存の証明、強い対照との実用効果は次段階の別達成条件として記録する。

3案とも、特許取得を確認した発明ではなく、構成と反証条件を持つ発明候補として提出する。特許の請求項、説明、論文の読了範囲を別々に記録する。
