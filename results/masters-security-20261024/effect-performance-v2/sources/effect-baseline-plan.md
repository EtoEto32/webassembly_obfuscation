# A第2設計：同一計画の手書き対照

2026-10-24、実行前の計画。前回の3方式は「権限抽出と実行計画を分けた手書き」と比較した。同じ計画から権限を導くこと自体は既知のcapability interpreterでもできるため、その正しい手書きbuilderを4番目の対照に追加する。

- 4方式×5独立process、seed 2026102403で順序を混ぜる。処理・warmup・反復は前回と同じ。
- 手書き単一計画も同じcreateEngine、同じfile executor、同じComponentを使う。相違はWIT/recipe生成builderと手書きbuilderだけ。
- 実Componentがliftした正しい型の値に限定する。手書きbuilderに生成版の重複shape検査は追加しないため、malformed JS入力の同等性は主張しない。操作数上限は共通engineで検査する。
- 性能に加え、同じ36失効条件・最終ファイル内容を比較する。以前の測定との差を速度改善とは扱わない。
- 生成版と手書き単一計画の安全性が同じなら、「単一計画にしたので新しい安全原理」という主張を退ける。生成による保守性は別途未評価。
