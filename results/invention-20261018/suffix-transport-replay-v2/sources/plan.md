# 残り入力の受理条件をSIMDで運ぶ候補：実験前の固定

2026-10-18。採用済み発明ではなく、具体的構成と費用を検査する候補。有限オートマトンの逆転、線形表現、基底変換自体は既知である。前回の単独座標の射影に関する反例とは別に、実行する状態空間を変更する案を検査する。

## 入力と構成

入力は2文字アルファベット・最大16状態の、読み取り専用DFA走査を含む実 `.wasm`。prototypeが出力する厳密なテンプレートに一致するものだけを受理する。公開APIは `run(pointer,length)->i32` と1ページの固定線形memory。各byteの最下位bitが文字。ホストによるmemory変更は呼出し間に限る。import、共有memory、外部副作用、別のexportは対象外。

通常は初期状態q0から入力を前向きに読み、q←δ(q,a)を実行する。候補では最後から読み、v[q]を「状態qから、既に処理したsuffixを受理するか」とする。空suffixは受理集合Fの指示ベクトル。文字aを前置するとv'[q]=v[δ(q,a)]。0/255 byteの16laneを `i8x16.swizzle` で更新し、最後にv[q0]を返す。

混合版ではGF(2)上の可逆行列Lを生成し、z=L vとする。更新はz←L A_a L^-1 z、初期値L F、出力e_q0^T L^-1 z。生成時に行列を合成し、実行時に元vへ戻す境界を出力しない。各行列列の0/255 maskとlane複製のswizzle・AND・XORで更新する。これは各元値を独立に符号化する規則ではないが、共同復元が安い可能性を排除しない。

```
extract and validate the exact source scanner template
enumerate its pure transition function for both letters and all 16 states
build pullback matrices A[a][q,delta(q,a)] = 1
choose invertible L (identity for the unmixed control)
B[a] = L * A[a] * inverse(L) over GF(2)
emit z = L*F
for i = length-1 down to 0: z = B[memory[pointer+i]&1] * z
return dot(e0*inverse(L),z)
```

## 仮説・意味保存・解除方法

動機は、逆向きのsuffixベクトルが多数の異なる値を取り得ることを利用し、元の小さな状態機械への復元費用を増やせないか、というもの。単なる状態数・命令数の増加を保護効果にはしない。

意味保存はsuffix長の帰納法とLの可逆性で説明する。読むアドレス集合は同じ。副作用がなくmemoryが呼出し中不変なら、読み取り順序を反転しても正常結果・bounds trapの有無・memory内容は同じ。資源枯渇、fuel、タイミング、同時書込みまでの同値性は主張しない。

**強い反証を先に固定する**：解析者はバイナリだけからB_a、初期z、出力row ℓを抽出し、rowの軌道 `ℓ←ℓ B_a` を探索できる。B_a=L A_a L^-1ならこの軌道は `e_q^T L^-1` の集合に含まれ、元の到達状態数以下で閉じる。したがって逆向き状態の爆発を必ず解析者に強制できる、という強い仮説は既に支持できない。実装後にはこの解析の費用を測り、共同復元と実行負荷のトレードオフとして判断する。

## 比較と合否

- 元、無混合のsuffix実行、混合したsuffix実行。raw/O2/O3。
- 4/8/16状態の巡回型と、到達性・最小性を検査した固定seedの一般型を用いる。最小DFAの状態数を元にも計測する。
- 境界値、短い全入力語、ランダムbyte列、空入力、不正pointer/末端越えを比較。WABTによる別実行も追加する。
- 実行時間・bytes・線形memory・process RSS・変換時間。fresh processの反復とばらつき。解析のtool起動/parseと行列抽出/軌道探索を分離する。
- 元、無混合、混合から回復したDFAの言語同値性を積状態の全探索で検査する。これはDFAモデル間の同値性であり、Wasmエンジン全体の証明とは異なる。
- 未対応、クラッシュ、時間上限、誤答を区別する。非線形の更新を線形抽出器が黙って受理しない対照も置く。

主方式に進むには、既知線形オートマトンからの具体的な独立差分と、適応的解析を含む有用な費用対効果が必要。回復成功だけでは不採用にしない。一方、Wasm移植と状態数増加だけを発明としない。最大のReject理由は、古典的な双対表現がそのまま安い解除手順になることである。
