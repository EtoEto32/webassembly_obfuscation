# 2回の更新を合成して中間状態を消す案の棄却記録

2026-10-18。探索段階で棄却した小さい構成であり、新規で有効な難読化方式ではない。先行する多項式の合成・分解に関する保護研究から独立した新規性も確認できていない。[文献照合](../nonlocal-literature-audit.md)を参照。

## 仮説と対象

元の更新を2回まとめて展開し、実行途中に元の1回分の状態が現れないようにすると、元のトレースの部分列を探す解析から外れる可能性がある。ただし、中間値が直接現れないことから復元困難性は導けない。この必要条件を、最小の構成で先に検査した。

対象は `F(x) = a*x*x + b*x + c (mod 2^32)`、`a` は奇数。入力も出力もi32で、メモリ・呼出し・トラップ・浮動小数点・共有状態を持たない。`F(F(x))` を展開した四次式 `Q(x)` へ変更する。整数剰余の意味にはWasmとの対応があるが、この構成はWasm固有ではない。一般のループや任意の入力Wasmを変換するCLIは作っていない。実Wasmを生成して解除可能性を検査する早期実験である。

解析者は方式と対象範囲を知る。一方の攻撃には配布されたWasmを与え、もう一方には公開関数への入出力問い合わせだけを与える。生成元の係数は解除関数に渡さず、事後の採点にのみ使う。保護対象は元の更新則の一意な同定と、短い同等実装の再構成を区別する。

## 係数から最大4候補で戻せる理由

`M=2^w, H=2^(w-1), w>=3` とする。昇順係数を `q0,...,q4` と書くと、形式多項式として

```text
q4 = a^3
q3 = 2*a^2*b
q2 = a*b^2 + 2*a^2*c + a*b
q1 = 2*a*b*c + b^2
q0 = a*c^2 + b*c + c                         (すべて mod M)
```

奇数の単元群の指数は `2^(w-2)` を割り、3はこの値と互いに素なので、三乗は奇数上の全単射である。従って `a = q4^(3^-1 mod 2^(w-2)) mod M` が一意に決まる。さらに `a^2` は `mod H` で可逆である。

```text
inv := inverse(a*a, H)
b0  := (q3/2)*inv mod H
for b in {b0, b0+H}:
    r := q2 - a*b*b - a*b mod M
    if r is odd: continue
    c0 := (r/2)*inv mod H
    for c in {c0, c0+H}:
        p := (c,b,a)
        if compose(p,p) equals all five coefficients of Q:
            retain p
```

`q3` が奇数なら該当する形式多項式根はない。偶数の最高次係数や四次以外は未対応として返す。候補は最大4個で、最後に全係数を再計算する。これは奇数最高次係数を持つ二次式の**形式多項式根**の列挙である。有限環上で同じ関数を表す別の係数列もあり得るため、すべての関数的平方根を列挙したとは主張しない。

複数の根があれば生成元を一意には決められない。しかし、どの根も同じ2回分の計算をする。生成元と異なる根を返したことを、同等実装の復元に対する保護成功とはしない。

実Wasmからの抽出は単一関数の `i32.const/local.get/local.set/local.tee/add/sub/mul` と定数シフトの多項式正規化に限る。`-O2/-O3` はBinaryen 133。抽出元は合成版のバイナリであり、元の式を抽出器へ渡していない。復元版そのものには追加の最適化をかけていない。

## 公開I/Oだけでも5問い合わせで複製できる

この対象はさらに弱い。**整数係数の次数4以下の多項式であるという既知の前提**があれば、入力 `0,1,2,3,4` に対する5出力で、同じ関数を表す式を構成できる。係数列そのものを一意に回復する必要はない。

整数のNewton展開 `f(x)=sum_k Delta^k f(0) * binom(x,k)` を使う。`k! = 2^v * u`、uは奇数と分け、観測した差分 `d_k mod M` から `(d_k/2^v) * inverse(u,M)` を求め、下降階乗 `(x)_k` に掛ける。整数係数多項式では差分はk!で割り切れる。mod Mからの持ち上げに伴う曖昧さはM/2^vの倍数で、`(x)_k` が2^vで割り切れるため、積では消える。この議論は既知の次数上限の下での関数同値性についてのものである。

[問い合わせ](../../results/invention-20261018/checkpoint-wasm-v1/blackbox/queries.json)と[検査結果](../../results/invention-20261018/checkpoint-wasm-v1/blackbox/checks.json)を保存した。18条件すべてで各5回、計90回の公開問い合わせから新しいWasmを生成し、各264入力・計4,752実行でBigInt参照と一致した。学習器へ渡すのは5出力だけであり、バイナリの読み取りは実行ホスト側で行う。検証用入力・参照係数は学習に使っていない。

5点の一致から未知のプログラムの次数を証明することはできない。意図的に前提外の `x^5` を与えた対照では、学習式のx=5での値は3,005、元は3,125となった。この[対照](../../results/invention-20261018/checkpoint-wasm-v1/blackbox/control.json)を保存し、一般の未知プログラムを5回で学習できるという主張を排除した。

## 判断と限界

中間状態を消す変換だけでは、係数の関係も、公開I/Oからの複製可能性も隠れない。この構成は採用しない。有限テストだけで全実装の正当性を形式証明したとは言わない。係数についての導出は局所規則の根拠であり、パーサ・コンパイラ・ランタイムを含む証明ではない。

この早期棄却後にプログラム全体の実行時間・RSS・変換時間の本測定は行っていない。Wasmサイズはmanifestに保存した。Chisel、XSmir、NotDecとの実行比較もしていない。一般の関数合成、偶数係数、多変数、ループ、全Wasm難読化の不可能性を示す結果ではない。一般問題の難しさを、この簡単に解ける生成部分集合に転用してはならない。

## 再現

Python 3.9以上、PATH上のNode（実測24.15.0/V8 13.6.233.17-node.48）、`.tools/wabt-1.0.42/bin`、`.tools/binaryen-version_133/bin`を使用する。実測環境はWindows x64、Core i9-11900K。Pythonの外部パッケージは不要。ツールの別配置は `WASM_TOOLS_ROOT` で指定できる。既存の出力先は上書きせず停止する。

```powershell
python research/checkpoint-composition/probe.py results/checkpoint-coefficients-new
python research/checkpoint-composition/wasm_gate.py results/checkpoint-wasm-new
python research/checkpoint-composition/blackbox.py results/checkpoint-wasm-new
```

`wasm_gate.py` は `research/observation-synthesis/transform.py` のWATパーサ・ツール呼出しを再利用する。同ファイルのimport先 `core.py` も必要。保存された `source/check.cjs` はスクリプトが `node -e` で起動するためのソースであり、直接 `node check.cjs ...` と起動する形式ではない。元の結果は再現実行と別フォルダに保存する。
