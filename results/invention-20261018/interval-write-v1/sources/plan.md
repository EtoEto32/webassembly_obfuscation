# 可変長上書きによる比較：早期実証ゲート

2026-10-18。前回のsuffix方式は小さい双対状態へ回復された。今回は線形状態を使わず、入力依存のメモリ更新と後続loadの関係で比較を実行する仮説を検査する。採用方式ではない。

`a,b` をbyte値とする。256byteの私有領域を0で埋め、先頭b byteを1で上書きした後、位置aを読むと `[a<b]` になる。各比較で領域を再利用する方式と、共通のbごとに一度だけ構築して複数loadで使う方式を比較する。元の公開memoryを変えないため追加の非export memoryを用いる。解析者には私有領域も公開とみなす。

入力は純粋なbyte比較とBoolean結合を持つ実Wasm。まず元、既知の二次元lookup対照、個別fill、共有fillをraw/O2/O3で比較する。保護課題は同じ比較・Boolean式と等価Wasmの回復。長い命令列やツール未対応を効果としない。

先行照合でDomasのREcon2015資料pp.17–19、45–49のscratchへの書込みによる等値判定を実際に確認した。M/o/VfuscatorのREADMEも算術lookupを記載する。したがって「メモリの別名関係で比較する」一般発想は新規ではない。今回の差候補はbulk fillによる順序判定と複数比較の構築共有だが、それだけで独立した新規性とはしない。

先に試す適応解析はload位置への最後の書込みを追うもの。区間内なら上書き値、外なら前のmemoryという式へ変換すると、`a<b` が安く回復する可能性がある。raw/O2/O3のバイナリだけから復元し、同じ解析タスクで費用を測る。生成モデルやseedを解析へ渡さない。

意味保存の条件はa,bの0..255制限、256byteの確保、毎回の初期化、追加memoryへのホスト・他関数からのアクセスがないこと。外部call・並行実行・再入・sourceの副作用は対象外。追加memoryの資源確保成功を前提とする。Wasmの未定義動作や意図的trapを使わない。

全byte対、32bit入力の上位bit、連続呼出し、公開memory不変、最適化後、別エンジンを検査する。誤った上書き長・初期化省略を負の対照とする。早期ゲートで具体的差と費用が弱ければ、実アプリケーションへの拡張や人手評価を行ったことにせず不採用を記録する。これを研究全体の完成条件の縮小にしない。
