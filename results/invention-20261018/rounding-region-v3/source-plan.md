# 丸め誤差の上界で領域を分割する整数計算変換

2026-10-18。実装前の仮説。前回の接続グラフとは別原理で、整数計算を「近似した大きい値」と「正確な短い剰余」の二経路へ移す。新規性も有効性も未確認。単語を二つのfloatへ符号化する過去のrounding-residual案とは異なり、複数演算を領域として計算してから補正する具体的な変換を検査する。

## 変換規則

入力は純粋なi32のadd/mul式。unsigned入力を整数として解釈した式をE、Wasmの結果をE mod 2^32とする。f64で同じ領域を計算した整数値Hについて、静的に |E-H|≤B を求める。2^(k-1)>B を満たすk≤30を選び、別にL=E mod 2^kを整数演算で計算する。

```
R := H - nearest(H / 2^32) * 2^32
r := wrap_i64(trunc_f64_s_to_i64(R))
d := sign_extend_k(L-r)
result := r+d (mod 2^32)
```

Rは[-2^31,2^31]内の正確な整数で、i64経由なので正の端点でもtrapしない。E-Hが符号付きk bitへ収まるため、d=E-Hとなる。結果はE mod 2^32。非負整数のadd/mulのみを高経路へ入れ、NaN、無限大、浮動小数点入力、除算、メモリ、副作用、trapを含む式は対象外。

各ノードに最大整数値Mと誤差上界Bを付ける。加算の既存誤差はBa+Bb、乗算はMa*Bb+Mb*Ba+Ba*Bb。加えて、その最大絶対値に対応する保守的な1 ulpを加える。整数の正確な結果が2^53以下なら新しい丸め誤差は0。この規則でkが上限を超えると、値の大きい側の演算部分を先に領域として閉じ、i32の境界値として扱い直す。領域内の低経路は係数をmod 2^kへ落とした多項式へ展開する。展開量には上限を設ける。

## 先行性と反証すべき点

floatと整数下位剰余を併用した正確な計算は既知。Victor Shoup, *Arithmetic Software Libraries*, January 2020 author chapter draft, https://www.shoup.net/papers/akl-chapter.pdf のp.1書誌、§2、Figure 1を読んだ。LIP/NTLが浮動小数点積と整数の下位桁を併用するaddmulpを説明している。査読論文扱いにはせず、書籍正式版の確認は未実施。この算術原理自体を発明と呼ばない。

FLOB (arXiv:2607.17603v1)は逆方向に浮動小数点計算を整数表現へ移す既知研究で、既存のliterature-reviewに記録がある。今回の具体的な差分候補は、Wasmの固定剰余意味を利用した領域分割・誤差に基づく剰余幅選択・領域単位の補正であり、独立した新規性の確認は残る。単なる言語移植だけでは採用しない。

特に危険な解除方法は、高経路のf64演算を「正確な整数演算」として読み直すこと。元の整数式と同じ演算グラフが残るなら、補正の複雑さを解析する必要がなくなる。この方式既知の解析を必ず実装し、低経路の整合性と誤差上界を照合する。回復成功だけで無効とは判定せず、処理時間と実行負荷も測る。

## 固定する実験

- 元のWasm、演算ごとに補正する対照、領域を融合する候補、低剰余をさらに狭める誤った対照。
- 原始的な積・内積と、複数段の多項式を使い、raw/O2/O3で検査。toyであり実務のIP保護評価ではない。
- WABT validation、独立BigInt oracle、境界・random・反復呼出し。有限検査を数学的な全系証明としない。
- 同じ方式既知の解析器で未変換と変換後を比較する。未対応、誤答、時間超過を区別する。
- 実行時間、サイズ、変換時間、追加memory、プロセスRSSを記録。コード単位のf64残存だけを保護効果としない。
- 高経路を線形時間で読み替えれば通常の整数式へ戻る場合、費用増加を記録した上で、実用上の差と新規性を評価する。難解に見えることを根拠にしない。
