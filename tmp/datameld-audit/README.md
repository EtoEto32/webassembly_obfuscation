# DataMeldの具体的な規則と次候補の判断条件

2026-10-12。独立研究用の作業記録。CSEC原稿・実験は変更しない。

## 確認資料と範囲

Ghosh, Hiser, DavidsonによるUS11042631B2（公開2021-06-22）、*System, method and computer readable medium for software protection via composable process-level virtual machines*。https://patents.google.com/patent/US11042631B2/en 。Description内の§3.4 DataMeld、§3.5–3.5.1、§3.6–3.7の一部を本文確認。これは技術開示の照合であり、権利範囲や実施可否に関する法律判断ではない。

DataMeldはアプリケーションと実行環境のデータ依存を混ぜる。例ではアプリケーション値をVM側の値で変更し、制御を戻す前に逆操作で復元する。VM側の変数選択には命令由来の依存を数えるICVを用い、StrataとPinを使う実装手順、変数同定で人手を用いる箇所が記載される。著者実装・SPEC実験は未取得・未再実行。開示の効果を本研究で再現したとは扱わない。

## 新候補Mを操作単位で分ける

M1：アプリケーション値xをVM状態kでx+kへ変え、同じkで減算して戻す。これは確認したDataMeldの具体例と重複する。異なる演算や変数を選ぶだけでは採用しない。

M2：xを元の表現に戻す地点をなくし、符号化領域で通常計算を進める。DataMeldの上記例とは差があるが、既存のデータ符号化・領域間変換の枠組みでも可能。この説明だけでは固有の変換規則がないので未採用。ただし、一般枠組みとの共通性だけを理由に、今後の具体的なM2アルゴリズムすべてを既存と断言しない。

M3：VM状態と計算値を同じ機械語のビットへ配置する。JBCOの著者公式例 https://www.sable.mcgill.ca/JBCO/examples.html のPacking Local Variables into Bitfieldsを確認した。2007年の論文に対応する例として説明される。変数のビットフィールドへの統合と読書き時の取り出し・格納は既存である。制御変数を同じ容器へ入れただけなら採用しない。同資料は今回のWasmや動的な範囲依存割当てまで実装済みという証拠ではない。

## 意味上の依存と、解析器が追跡した依存

純粋なwビット加減算で同じkを使うなら、(x+k)-k=xが全入力で成り立つ。この例で依存グラフがkを含むことと、結果がkの値に意味上依存することは異なる。これを区別できない解析器だけを相手にして強度を主張しない。

途中にkの変更、副作用、trap、別名参照が入る場合は、この単純な式だけで削除の正当性は決まらない。ここではDataMeld全体が容易に解除できると証明したわけではない。著者実装を評価せずに全体を棄却しない。

## 今後の候補選択を修正する

過去の探索では、一般的な枠組みが見つかった後、具体的な差分を詰めずに広い方向を見送る傾向があった。一般のdata refinementは多数の表現変更を記述できるが、その事実だけでは特定の変換規則、適用条件、構成アルゴリズム、コストの新規性を否定できない。

今後は次の3段階を分ける。

1. 具体的な操作が一致する候補：棄却（例M1）。
2. 一般枠組みは共通だが具体的な規則が未定義の候補：設計未完了（例M2）。研究が存在しないこととは言わない。
3. 具体的な規則・意味が保存される条件・解析上の仮説を提示できる候補：新規性未確定のままでも反証可能な試作へ進める。試作前に「新規性が証明済み」であることまでは求めない。

次にM2を再検討するなら、E_s F E_r^{-1}という記法や「非線形にする」という説明で止めず、少なくとも二つの非自明な元演算とデータ依存分岐を、どの具体命令へ写すかを定める。最も近い既存方式からの差と、その差を消した対照条件を同時に定義する。単なるパラメータ変更を別候補と数えない。

## 状況

新規実験は行っていない。DataMeldの検索抜粋しかなかった状態から、具体的な規則と実装手順の一部を本文確認した。M1/M3の単純案は採用しない。M2は設計未完了。全体の目標は未達で、採用アルゴリズムはまだない。

利用枠は使用10%、残量90%。残り10%の区切り条件には達していない。
