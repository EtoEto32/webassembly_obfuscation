# 候補探索の現在地と選択最適化の照合

確認日2026-10-12。独立研究用の作業記録。CSEC研究とは別。新方式の採用やゴール完了の報告ではない。

## 今回追加した先行研究の確認

[Generating Adversarial Computer Programs using Optimized Obfuscations, ICLR 2021](https://arxiv.org/pdf/2103.11882)の問題設定、式(2)-(8)、§5冒頭を確認した。位置と変換を選択する最適化を定式化し、MLモデルの損失を目的としている。評価はPython/Javaのコード要約で、今回の式・制御の意味再構成を直接評価した資料ではない。
したがって「最適化で変換場所を選ぶ」という一般的な発想は既存だが、これだけを根拠に、どの意味再構成コストに基づく選択法も同一の既存アルゴリズムだと断定しない。逆に対象の言語や目的関数が違うだけで、新規性を認めることもしない。
著者実装は本文脚注の https://github.com/ALFA-group/adversarial-code-generation に案内があるが、今回コードは未取得・未実行。著者の効果をこちらの難読化耐性と読み替えない。

## 前回の案から実装へ進むか

「中間値の定義を使用箇所へ展開し、どの定義を展開するかを制約付きで選ぶ」という案を検討した。しかし定義展開そのものは確認済みLOKIのreplace_expr_var等と重複する。
局所的なランダム選択を予算付きの全体選択に変えることは実装差になり得るが、それだけで今回要求する新規性・解析への効果を満たす証拠にはならない。
特に全命令を観測できる解析者に対して、展開しただけで中間演算が消えるとは限らない。領域出口だけを観測する比較で有利な結果を作らない。
現段階では独自の変換規則と有効性仮説を確立できていないため、候補として採用せず、性能測定を増やす段階へ進めない。
