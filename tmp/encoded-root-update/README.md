# 符号化状態の平方根補正による更新：棄却した具体的な規則

2026-10-12。Python 3.12.14で実装・実行。新規Wasm難読化アルゴリズムとして採用しない。既存Wasmを入力する変換器でも、実用ハッシュの実験でもない。

## 規則

幅w>=3で、E(x)=x+2x² mod 2^wを状態表現とする。入力uに対し、v=u²+u（xが奇数）またはu²+3u（偶数）、x'=x+vを計算する。元コードではxを使うが、候補更新はz=E(x)とuだけを使う。

`(1+4x)² = 1+8E(x)` を利用し、zからr=1+4x mod 2^wをビットごとに求め、`z'=z+v*r+2v² mod 2^w`とする。xとzの偶奇は等しいので分岐にはzを使用できる。更新内に完全なxを計算する式は置かない。

r=1から始め、k=2,...,w-1で、1+8z-r²のbit k+1が1ならrのbit kを立てる。rは奇数なので、2^kの追加は平方のbit k+1を反転し、それより低いbitを保存する。k>=2では平方の追加項2^(2k)はこの判断に影響しない。これによりr≡1 mod4の根の必要なwビットが定まる。実装では中間計算にPython整数を使った。Wasmへ移すなら追加精度が必要であり、i32演算だけの同じコードとして検証済みとはしない。

## 保護の狙いが成立しない理由

rには元の状態の下位w-2ビットがそのまま残る。a=(r-1)/4とすると、x=a+t*2^(w-2)でtは0..3。w>=3では `E(x)-E(a)=t*2^(w-2) mod 2^w` なので、残りの2ビットもzから直ちに求まる。復元式は

`x = a + (z - E(a)) mod 2^w`。

observer.pyはこの式を独立に記述し、width、z、rだけを受け取る。検証器だけが元のxを保持して照合する。同じプロセス内の関数であり、OSによる隔離ではない。既知の符号化方式と観測箇所を使う復元であって、未知Wasmからrを自動発見する解析器ではない。

## 実測

| 対象 | 比較した更新 | 出力不一致 | 元の状態の復元成功 |
|---|---:|---:|---:|
| 幅3..8の全x,u | 87,360 | 0 | 87,360 |
| 32bit、1,124入力列×8更新 | 8,992 | 0 | 8,992 |

32bit入力は境界値10×10組と乱数1,024組。seed=1380929364。奇数分岐4,392回、偶数分岐4,600回。各幅のrootの直接照合も不一致0。ビット幅が小さい場合の全数検査と32bitの有限標本を混同しない。上の代数的説明は全入力の関係を説明するが、形式証明器での検証ではない。

入力、生観測、結果、ソースのSHA-256はresults.jsonに保存。observations.jsonのrecovered欄は観測後に計算した解析結果であり、解析器への入力ではない。参照実装は直接xを更新してEへ写し、候補の平方根補正を使わない。

## 新規性と既存候補との差

Ronald L. Rivest, *Permutation Polynomials Modulo 2^w*, Finite Fields and Their Applications 7 (2001), pp.287–292。著者公開本文 https://people.csail.mit.edu/rivest/pubs/Riv01c.pdf の§1–2を確認。x(2x+1)そのものが既知の置換多項式として挙げられている。Eや置換性を独自の発見としない。

2016年SPROの *Binary Permutation Polynomial Inversion and Application to Obfuscation Techniques* も直接の調査対象。会議公式目次 https://sigsac.org/ccs/CCS2016/wp-content/uploads/2016/10/Open-TOC-SPRO.html で掲載を確認。今回その本文や著者実装は未確認。Quarkslabの資料一覧 https://github.com/quarkslab/conf-presentations に2016年・2018年の関連資料への入口がある。本文未読のまま今回の規則と完全同一とは断定しない。

過去のimplicit-equation-gateは出力残差へ可逆なQをかけていた。今回は符号化状態を継続して保持する直接更新で、完全な復号ローカルを作らないという狙いを具体的に検査した。しかし部分的な復号に相当するrとzを合わせれば、元の状態は簡単に得られた。変更点だけでは新規性を支持できず、狙った効果もこの観測条件ではなかった。

この結果を、未知バイナリへの全自動復元成功や、符号化難読化全般の不可能性へ拡大しない。逆に、復元器がバイナリ認識をまだ持たないことを候補の強さとして数えない。この具体的な規則のWasm化・性能測定は進めない。

## 再現と残件

experiment.py、observer.py、protocol.mdを空ディレクトリへコピーし、Pythonでexperiment.pyを実行する。標準ライブラリのみ。既存results.jsonがあれば停止する。元の結果を上書きしない。

次の候補は、復号変数を別の中間値に置換するだけではない規則が必要。入力・出力・全中間値を含む実際の観測範囲で評価し、簡単な組合せで復号できる補助量を残す設計を除外する。新規性と有効性を支持できる候補は未確定で、ゴールは未達。CSEC原稿や既存実験は変更していない。
