# 丸め残差による整数分割の早期検査

2026-10-12。別構造の候補として整数をbinary64の丸めた値と残差に分ける案を具体化した。**新しい難読化方式としては棄却。** 単純な復元式が成立するため、更新演算や大規模変換器の開発へ進めない。

## 具体的な規則

u32のxをbinary64へ正確に変換し、公開定数B=2^kを選ぶ。

    h = fl(B+x)
    l = fl(x-fl(h-B))

状態を(h,l)で持つという案。検査したkは52,53,60,70,83,84,85で、7個の別方式ではなく1方式の設定差である。対応は有限u32入力の符号化・復元だけ。任意のWasmを変換する実装、符号化状態のままの加算・乗算、NaN等を含む一般浮動小数点プログラムの変換ではない。

## 既存手法との関係

Ogita, Rump, Oishi, *Accurate Sum and Dot Product*, SIAM J. Sci. Comput. 26(6), 1955–1988, 2005, DOI 10.1137/030601818。著者PDF https://ogilab.w.waseda.jp/ogita/math/doc/2005_OgRuOi.pdf の§1.1、Algorithm 1.1と続く誤差なし変換の説明を確認した。大きさの条件の下で丸めた和と正確な補正項を持つFastTwoSumは既存であり、この整数分割もその考え方の特殊化である。論文全体や著者実装を検証したわけではない。新しい数値表現原理だとは主張できない。

FLOB, arXiv:2607.17603v1, https://arxiv.org/html/2607.17603v1 も再確認したが、こちらは浮動小数点計算を別表現へ持ち上げてMBA化する研究として既にrecent-obfuscation-audit等に記録済み。この残差案と同一の難読化器だとは断定しない。今回はFLOBを再実装していない。

検索語: obfuscation floating point encoding; obfuscation rounding error; mixed boolean floating obfuscation; Ogita Rump Oishi accurate sum dot product TwoSum error free transformation。

## 全u32範囲で成り立つ復元

    x = (h-B)+l

この特定のBとu32領域ではhとBの差は正確に表せる整数で、その絶対値は2^32以下。xとの差もbinary64で正確に表せる整数なので、lの計算は正確。最後の和は元のu32整数を正確に表し、`i32.trunc_f64_u`はtrapを起こさず元のビット列へ戻せる。hとBは十分近く、その減算にも余分な丸め誤差は生じない。この説明は指定した範囲についての代数・浮動小数点表現上の理由であり、SMT証明や全2^32入力の実行ではない。

従って(h,l)とコード中の公開定数Bが分かれば、**f64.sub、f64.add、i32.trunc_f64_uの3命令**で復元できる。命令位置や状態の対応を未知として自動で発見する攻撃は実装していない。とはいえ、単なる表現分割を強い保護とみなす根拠はない。符号化開始時の入力や内部変換値まで観測するなら、さらに情報が多い。

k=85ではBの直上の間隔が2^33で、すべてのu32のxに対してh=B、l=xとなり、残差が元の値そのものになる。k=52では和自体が正確で残差0。大きいオフセットほど強いという性質はない。

## Wasm検査

experiment.cjsが専用の多値結果WATを生成し、WABT 1.0.42で組み立て、Binaryen 133で-O2最適化する。fast-mathは指定していない。Node v24.15.0 / V8 13.6.233.17-node.48で実行。

入力は0、最大u32、2の冪の近傍、固定seed 0x52455349による4,096乱数を重複除去した4,307値。各7設定×raw/O2の14条件で、符号化対と復元出力を確認し、不一致0。**60,298回の符号化・復元の組**であり、呼出し総数はその2倍。14条件を14アルゴリズムとは数えない。

符号化対はBigIntで定義した最近接・偶数丸めの整数基準と比較した。基準は浮動小数点の同じ式の再実行ではない。各Wasmはraw110 bytes、O2 108 bytes。すべての入力と、h/lのbinary64の正確な16進ビット表現、復元出力を保存した。SHA-256とツール版はartifacts/results.jsonにある。

強い保護を示せなかったため、微小な性能差を測って採用根拠にしない。通常版・既存方式・候補・要素除去版の性能比較は行っていない。

## 再現と判断

artifactsが存在しないコピー先で `node experiment.cjs`。WASM_TOOLS_ROOTでWABT/Binaryenの配置を変更できる。実験はローカルのみ。

本案の棄却理由は、既存の補正算術の特殊化であることと、公開定数による極めて短い復元式があること。浮動小数点を使うすべての将来方式を否定する結果ではない。新規性・有効性を示せる新方式は未完成で、研究全体の目標は継続する。CSEC原稿、以前の実験、セキュリティ設定は変更していない。
