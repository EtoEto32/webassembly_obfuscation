# 遅延補正候補の先行例と判断

確認日: 2026-10-12。CSECとは独立した作業記録。新方式の成果、論文、著者実装の再現ではない。

## 検討した案

各i32演算直後の補正を、範囲を保証した加算・乗算の領域の末尾まで遅らせる。RNSの成分上で計算を継続し、途中の平文の出現と補正コストを減らす、という案である。

前回のhoacs-source-auditは既存実装に補正があることを確認した。今回の問いは「補正を遅らせること自体に新しい変換規則があるか」であり、不正な補正なし実装に勝つかではない。

## 確認した先行例

1. Michael Scott, Slothful reduction, IACR ePrint 2017/437。本文§1–4を確認。有限体演算で冗長な表現と最悪時の範囲を利用し、完全な剰余削減を遅らせる。Wasm i32意味保存や難読化の有効性を示した資料ではない。著者コードは実行していない。
   https://eprint.iacr.org/2017/437
   https://eprint.iacr.org/2017/437.pdf

2. US11755288B2, Secure transformation from a residue number system to a radix representation（2023年登録文献）。Justia上の公報本文のDetailed Descriptionを確認。pseudo-residue、範囲制約、postponed reduction、white-boxでの利用が記載される。入力等に依存するobfuscating numberを変換へ加える実施形態もある。これは技術的先行例の確認であり、権利範囲や利用可否の法的判断ではない。コード・効果は未検証。
   https://patents.justia.com/patent/11755288

## 混同しない三つの操作

|操作|必要な根拠|今回の位置付け|
|---|---|---|
|成分のmod m_i削減を遅らせる|成分の実装整数がオーバーフローしない上界|通常のlazy reductionと直接重なる|
|RNSで整数多項式を評価し、最後にmod 2^32を取る|CRTで復元する値の範囲と、途中で観測される意味|成分の削減延期とは別問題|
|符号化状態で比較・ビット操作・副作用を実行する|各演算と観測の意味保存|本案では新しい規則をまだ定義できていない|

N=2^32とする。純粋な整数多項式Pについて、途中をmod Nで評価しても最後のP mod Nは同じである。一方、RNSの積Mで得られるのはP mod Mであり、その後mod Nを取るだけでは一般に一致しない。非負の整数評価がM未満と保証されればこの違いを避けられる。ただし、この条件は十分条件であり必要条件とは主張しない。例えばNがMを割る場合も別途考えられる。負数は符号付き復元範囲が別途必要になる。

比較や右シフトなどは整数多項式の合同式だけでは扱えない。例として8bitでx=255のとき、(x+1) mod256と0の比較は真だが、256と0の比較は偽になる。したがって途中の比較を単に最後へ移すのは誤りである。これは代数的な説明と一例であり、新規の実測結果ではない。

## 判断

「範囲解析を追加して補正をまとめる」だけの案は、新しい難読化アルゴリズムとして採用しない。削減の延期そのものは既知で、現在の案には解析者の復元を難しくする追加の仕組みが定義されていない。性能改善が仮に得られても、この不足は埋まらない。

上の資料が、任意Wasmに対する意味保存変換を既に実装していると結論したわけではない。正しい実装の工夫が必要なことと、新しい難読化の技術的差分があることを区別する。

この案の比較用Wasm実装・大規模性能測定は開始しない。今回、既存実験の結果を増やして見せることもしない。既存のresidue-wrap-gateの結果はそのまま保存する。
