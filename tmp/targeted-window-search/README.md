# 実在する中間計算を指定した窓内探索

2026-10-12。前回のランク差だけによる評価を避け、事前に指定した中間計算の復元を判定した。**採用する新しい難読化方式は得られていない。** 探索範囲を増やしたこと自体に新規性はない。

## 事前に固定した対象

入力はa,b、各3bit。以下のtを合成した算術カーネルの実際の途中値として指定し、外側の乗算を含む出力を保存する候補を探した。

|対象|t|最終出力|
|---|---|---|
|xor_product_sum|`(a*b) XOR (a+b)`|`t*b`|
|difference_of_squares|`(a-b)*(a+b)`|`t*a`|
|xor_two_products|`(a*b) XOR (a*a)`|`t*b`|

全演算はmod8。これらは合成した通常計算であり、実用暗号の不可欠な秘密と実証したものではない。結果を見て復元困難な任意関数を選んではいない。

## 探索と観測

葉a,b,0,1、add/sub/xor/mul、最大4演算の純粋な式の構文木を探索。全64入力の出力関数とすべての途中値の関数集合が同じ候補だけをまとめ、低コスト代表を保持する。これは全構文木の列挙ではなく、指定した観測モデルで重複するプロファイルの除去である。命令順序・コード形状・対応付け探索時間を評価するモデルではない。

生成試行: cost1=64、cost2=672、cost3=12,100、cost4=227,544。保持プロファイルは葉4、各コスト21、323、5,415、103,603。出力が各指定プログラムと同じ候補だけを後段へ渡した。

入力と定数、すべての途中値のビットから二次以下のBoolean多項式を構成できる観測者を使う。全64入力の真理値表を線形代数で照合するため、学習入力だけの一致ではない。対象の全ビットが復元できる場合は保護候補として除外する。

さらに対象が二次式で復元できなかった候補に対しては、観測されたワードと全3bit定数からadd/sub/mul/xor/and/orを最大2演算で使う復元を試すコードを用意した。ただし今回は二次式の段階で候補がすべて除外されたため、**この二次判定後のワード復元コードは実験では実行されていない**。ワード解析を突破したという結果はない。

## 結果

|対象|同一出力候補|対象が直接観測される候補|対象の全ビットを二次式で復元できる候補|
|---|---:|---:|---:|
|xor_product_sum|3|1|3|
|difference_of_squares|4|2|4|
|xor_two_products|1|1|1|

8候補中4候補はtそのものを途中値として出さないが、それでも復元できた。生の途中値の一致が消えることだけでは、この観測者に対する保護になっていない。

別のスカラー式評価器で8候補の全64入力を検査し、出力一致512件、不一致0。ビット幅が小さい場合の有限モデルでの意味保存であり、i32の証明ではない。候補をi32/Wasmへ移しておらず、実行性能も未測定。

## 判断

この文法・コスト上限・事前指定した3対象では、有効な変換は得られなかった。大きな文法や新しい符号化方式全体に対する不可能性を示す結果ではない。単純な式の並べ替えを新方式として採用しない。次に必要なのは同じ狭い文法の機械的な拡大ではなく、既存方式と異なる具体的な変換構造と、その意味が保存される条件の設計である。
