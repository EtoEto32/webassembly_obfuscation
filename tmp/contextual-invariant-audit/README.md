## 調べた候補と判断

前回は全反復で同じ二次復元式が成立した。次に「ある地点の到達状態でだけ成立する関係を使い、式を局所的に同値な別の式へ置換する」方向を検討した。

候補K1：到達状態でI(s)=0が成り立つ地点のi32式e(s)を、e(s)+q(s)*I(s)へ置換する。i32環上ではその地点で同値になる。追加式は純粋でtrapしないものに限定し、順序や副作用を変えない必要がある。

候補K2：複数の変数にまたがる関係から述語を構成し、通常計算に見かけのデータ・制御依存を作る。成立する地点にだけ適用する。

候補K3：実行中に更新する補助状態の不変条件を使い、仮想命令やデータを復号する。

**K2を一般的な新方式としては採用しない。K3にも直接的な既存機能がある。K1は具体的な新規変換と確認できておらず、採用保留。** K1とK2の式や制御が同一だと断言するのではなく、「文脈依存だから新しい」という根拠が使えないことを区別する。K1を単にWasmで実装して、先行研究との差を検証したことにしない。

## K1の意味保存と解析条件を混同しない

I(s)=0を仮定すればe+qI=eとなるのは意味保存の説明にすぎず、解析が困難になる証拠ではない。解析者が同じ不変条件を得れば消去できる。

独立に値を変えて式を問い合わせる解析は、到達不能な状態を含む可能性がある。そこで得た不一致を「元プログラムの意味を復元できない」と直結させない。評価には実際の入力から到達する状態の追跡と、経路条件を含めた解析が必要。

棄却条件：既存の文脈付き書き換えと同一、通常最適化で消える、実到達状態では簡単に復元できる、または解析失敗の原因が未対応命令・不適切な問い合わせだけである場合。まだ実験をしていないため、これらの結果が出たとは報告しない。

## 次の設計作業

固定復元式を難しくするために係数・次数を増やすだけの案は進めない。次は「値を即座に計算せず、未評価の演算グラフとして保持し、使用時に計算する」方向を、既存の仮想化・演算融合・遅延評価と比較する。現時点では独自規則未定義であり、検索で直接同名の方式が見つからないことを採用理由にしない。

この方向を実装するなら、どの演算を遅延できるか、分岐やloop-carried stateをどう扱うか、trap・副作用の順序をどう保つか、グラフの観測から元演算がそのまま読めないかを先に定義する。単なるASTインタプリタであれば、新方式として採用しない。元の計算を別の計算に置き換えて適用済みとはしない。
