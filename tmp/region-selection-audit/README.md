# 統合範囲の選択と解析者の観測範囲

2026-10-12。前段 `../control-fusion-source-audit/README.md` から継続。今回は範囲選択だけを変更する案Iを、実装前に検討した。

## 案Iと採否

案: SSA依存グラフを領域へ分割し、各領域の出力から復元できる小さい式が少なくなるように境界を選ぶ。LOKIのランダムな依存展開に対する範囲選択の改善を想定した。
判定: **このままでは採用しない**。領域出口だけを観測する解析器を用意すれば有利に見えるが、ユーザーの想定するバイナリ解析者は生成コード内部を再分割できる。範囲のラベルを変更するだけでは、保護する観測情報は消えない。
また、スライスを用いて難読化を設計し、出力ごとの依存を変える方向自体は既存研究にある。単にその指標を最適化するだけで新しい原理とは主張できない。

### 境界だけを隠す案が不足する理由

この限定条件を置く:
- 変換前後でプリミティブ命令、その順序、各命令直後の値は同じ。
- 変化は命令群のラベル付け・関数/handlerの境界だけ。
- 解析者は両方のプリミティブ命令直後を観測できる。

この場合、境界ラベルを取り除いた観測列は同じである。同じ観測列から同じ依存関係を抽出する解析手順に対して、ラベルの変更だけを耐性向上の根拠にはできない。
これは今回の設計上の論証であり、すべての仮想化・命令融合が無効という定理ではない。実際の命令やデータ依存を変える変換、観測の計算量が変わる変換は前提の外にある。前提を超える具体的な変換がない現在の案Iは試作しない。

## 確認した一次資料

### Slicing Obfuscations, 2007

[著者公開本文](https://www.cs.auckland.ac.nz/~cthombor/Pubs/drm0127-majumdar.pdf)。今回は§4の変数依存とTable 1周辺、§5.3を確認。以前のアフィン符号化監査に加え、出力ごとのスライスを考慮した設計との重複を確認した。実装再現はしていない。
出力間の依存を増やすことや局所領域へ変換を適用することを、今回新たに発見した着想とは扱わない。

### Chisel, OOPSLA 2024

[著者公開extended版](https://www.cs.utexas.edu/~isil/chisel.pdf)、DOI 10.1145/3689789。§3の問題定義、§4冒頭、§6のbinary評価末尾、§7を確認。traceに基づく制御構造の再構成を比較対象に含める必要があると分かった。
一方、著者が対象とするcontrol-flow extensionsには制限があり、仮想化・例外ベース変換・MBAはそのままの対象ではない。等価性の確認にもテストを用いている。Wasmへの直接対応や任意の候補を解除できることは確認していない。
[著者artifact](https://zenodo.org/records/13863694) v1.0を確認。chisel_0816.7z、掲載MD5 4d5c2b3962829b247aaac44bb7020aaf、約9.8MB。今回は掲載情報のみで、ダウンロード・コード監査・実行は未実施。
この比較対象を導入する場合、未対応変換で停止したことを保護の成功とは数えない。
