# 途中値の意味集合を保持する候補枝刈り

2026-10-12。研究候補の探索部品を実装した記録。新規性を確定した難読化アルゴリズム、汎用Wasm変換器、強度評価の完成ではない。前回の作業は行列式候補の一次資料と採用・不採用の判断を保存した進捗あり。

## 具体的な規則

同じ入力領域上の純粋で全域的な式P,Qを考える。V(P)は出力関数、O(P)は各途中値が表す関数の集合、c(P)は式の構文木の演算数とする。全候補に共通な入力・定数はOに追加してもしなくても比較は同じ。

次の場合にPを残しQを捨てる：

`V(P)=V(Q), O(P) subseteq O(Q), c(P)<=c(Q)`。

同じ出力に対して、この関係で互いに優劣が付かない候補を複数保持する。途中値の単なる個数ではなく、**入力に対する関数としての集合包含**を使う。現在の実装では有限全入力に対する評価列がその関数を表す。

これは候補を生成する規則ではなく、候補を失わずに減らすための規則。既存の多目的・半順序枝刈りとの同一性はまだ調査中で、新発明と断定しない。

## 保証する範囲と理由

観測された値から、固定した演算文法・演算数上限で式を構成する復元者を考える。Pの各観測関数がQでも観測できれば、Pの値を葉にした復元式をQの同じ意味の葉へ置き換えられる。よってPから復元できる対象は、同じ演算数でQからも復元できる。この比較では値の対応を既知としており、対応を発見する探索時間の大小は証明していない。

さらに、同じ純粋な式文脈CへP,Qを入れると、穴の外で計算する値はV(P)=V(Q)によって同じになる。したがってO(C[P]) subseteq O(C[Q])が保存され、加法的な式の構文木コストの順序も保存される。この条件の下でQをPで置き換えても、より少ない観測値で成立する候補を失わない。

これはセットからの式復元モデルについての説明である。命令位置・実行順序・命令の種類やソース構造を使う全解析器の実行時間を順序付けるものではない。共有DAG、分岐、loop、メモリ、副作用、trap、JIT後のコードへ無条件で拡張しない。抽象化・不変条件で到達領域が変わる場合にも追加証明が必要。

## 復元の成否だけを記録すると文脈で変わる反例

3bit、a,b,c全512入力。P=(a+b)+c、Q=a+(b+c)は同じ出力。入力値とすべての途中値を観測し、add/sub/xor/mulを最大1回使える復元者の対象をT=(a+b)*c*cとする。

P,Qとも、その時点ではTを復元できない。しかし同じ文脈 `C[e]=e+(c*c)` に入れると、Pでは途中値a+bとc*cを掛けて復元でき、Qではこの文法内で復元できない。両方とも文脈の最終出力まで観測に含めて検査した。

したがって、現在の「この対象を復元できる／できない」という1bitのプロファイルだけでは、後続合成に対する同値類として不十分。この反例は実用的な保護効果の主張ではなく、不適切な枝刈りの例である。Tが元プログラムの意味理解に必須であるとも主張しない。

最初の実行は共通途中値c*cの追加だけを検査した。results-initial.jsonに保存した。その後、上記の完全な式文脈へ修正し、再実行したresults.jsonを最終記録とした。どちらも反例は成立したが、本文の根拠は後者。
