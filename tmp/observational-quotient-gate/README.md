# 観測同値による状態削減：候補採用前の検証

2026-10-12。判定：この具体案は新しい難読化アルゴリズムとして棄却。研究全体の目標は未完了。

## 確認したかった点

前候補は元の書き込み情報を補助関数引数に残していたため復元された。そこで「必要な出力を保ち、元の内部状態を一意には復元できないように統合する」案を検討した。しかし不要情報を消すだけでは、意味を理解しにくくする新規則にはならない。通常の状態最小化と区別するための実行可能な棄却用サンプルを作成した。

## 変換・意味保存

状態sは0..255、入力uは0/1、各時点の観測出力はs & 15。初期状態は全256通り。出力の等しい状態を分け、遷移先のクラスが一致するまで分割を反復する。クラスを新状態とし、遷移と出力をlookup tableで実装した。

射影qについて q(T(s,u)) = T'(q(s),u)、O(s) = O'(q(s)) を全状態・全入力で検証する。これは有限機械の閉じた遷移関係なので、帰納法により任意の有限入力列の観測出力一致を説明できる。任意Wasmへの意味保存証明ではない。初期値を商状態に写すqは検証器側で使用し、公開バイナリに初期化器として組み込んでいない。完全なアプリ変換としての隠蔽を主張しない。

実装は4つの専用算術関数からの生成器。既存Wasmの変換器ではない。メモリ副作用、trap、外部呼出し、実時間の保存は対象外。除算の除数は定数3でゼロ除算しない。

## 結果

| 遷移（mod 256） | 元の状態数 | 商状態数 | 商の全動作を列挙する呼出し数 | raw / O2の商Wasm bytes |
|---|---:|---:|---:|---:|
| s²+3s+u | 256 | 16 | 48 | 136 / 135 |
| rotl8(s,1) XOR u | 256 | 256 | 768 | 859 / 858 |
| s+(上位bitが1なら3、他は5)+u | 256 | 256 | 768 | 859 / 859 |
| floor(s/3)+u | 256 | 256 | 768 | 859 / 858 |

通常版・商状態版×raw/O2×4関数で16本。各512遷移と256初期出力、合計8,192遷移・4,096出力照合で不一致0。生成側のNumber演算と別に書いたBigInt演算で照合。さらに別アルゴリズムの状態対識別固定点で各65,536順序対、計262,144対の同値判定が一致した。

多項式では1クラス16状態となり元の状態の上位4bitは一意に復元できない。しかし商機械の入出力動作は48呼出しで列挙できた。回転・上位bit分岐・除算は後で上位bitが観測に影響するため、256状態のままだった。下位bitだけを保持する規則ではこれらの処理を保存できない。

## 観測者と結論の限界

観測者関数はバイナリ、step/readoutのABI、有効状態数だけを受け取り、各状態の出力と2つの遷移を列挙する。元の式・q・代表元表を関数内で参照しない。ただし検証器と同一Nodeプロセスであり、情報隔離した盲検ではない。任意の状態を引数に与えられる強いモデルで、固定初期状態だけを利用する解析とは異なる。

列挙できたのは変換後の有限機械全体であり、元ソース式や消された上位bitの復元ではない。状態を削れたことと、動作理解を困難にしたことは異なる。本例は広い状態空間に対する列挙効率も、他の非単射変換の無効性も示さない。

既存状態最小化そのもの以外の変換規則がなく、この観測者に対する保護も得られないため棄却。通常版とのバイト数差は表現コストであり、難読化の強度ではない。判定が付いたので性能ベンチマークや追加の難読化を重ねて延命しない。著者実装との性能比較、一般的な難読化解除の成功率は測っていない。

## 次の候補の選定条件

今回の結果を「内部状態を消す難読化は全部不可能」と一般化しない。ただし元の不要状態の完全復元を阻止しただけでは採用しない。次候補では、現実的な解析者が求めるプログラムの性質と、その解析に必要な計算を増やす具体的な規則を先に定める。小さい状態空間の総当たりを破ることや、表を大きくするだけを目的にしない。既存のopaque predicateやモデル変形との差を説明できるかを確認する。
