# 必要桁の段階計算：採用前の意味保存確認

## 判定

この着想は新規算法として採用しない。必要な下位ビットの計算、要求に応じた遅延評価、不要な値の除去だけでは既存技術との実質的な差がない。段階的な精度向上そのものを難読化の新規性として扱わない。

今回実装したのは、その候補の前提となる「要求されない値を計算しなくてよいか」の小さいWasm反例と修正版である。段階的精度の変換器を完成させたものではない。アルゴリズム開発という全体目標は未達成。

## 一次資料の確認

- MIT Bitwise project: https://groups.csail.mit.edu/cag/bitwise/ 。プロジェクト概要で整数・ポインタのビット幅推定を確認。元の論文全体の精読とは扱わない。
- LLVM InstCombineSimplifyDemanded.cpp: https://github.com/llvm/llvm-project/blob/main/llvm/lib/Transforms/InstCombine/InstCombineSimplifyDemanded.cpp 。2026-10-12にWeb表示の Mul、UDiv、DemandedMask関連部分を確認。低位ビット要求に基づく演算変形が存在する。コミット固定やLLVM実行比較は未実施で、閲覧したmainの範囲に限定する。

これらが今回と同じ難読化器を実装しているとは言わない。基本操作が既知であり、それを越える具体的な保護機構をまだ設計できていないという判断である。キーワード検索で完全一致がないことも新規性の根拠にしない。

## サンプルの意味

通常版はstageを0にし、x/y（符号なしi32）を評価して商を捨てる。その後stageを1にし、x*xの下位(k mod 32)ビットをresultへ保存する。Wasmのシフト規則によりk=32では要求幅0となる。この入力仕様を明示してBigInt参照実装にも反映した。

- strict: 元の除算を実行。
- naive: 商が不要として除算も消去。
- checked: y=0なら同じ位置でtrapし、それ以外では不要な除算を省く。

比較対象は正常終了/trap、公開global stageとresult。trap時にresultが前回の値のままであることも照合する。trapのメッセージやスタック表示の同一性は対象外。有限入力比較とは別に、本例のunsigned除算の唯一のtrap条件はy=0なので、checkedの意味保存はこの条件と更新順序から説明できる。メモリ、外部呼出し、符号付き除算、一般Wasmへの拡張を証明していない。

## 実測

WABT 1.0.42、Binaryen 133、Node v24.15.0。3方式×raw/O2の6本、各512入力。

| 方式 | raw/O2それぞれの不一致 | raw/O2それぞれのtrap数 | raw/O2 bytes |
|---|---:|---:|---:|
| strict | 0/512 | 64 | 96/96 |
| naive | 64/512 | 0 | 90/90 |
| checked | 0/512 | 64 | 97/97 |

naiveはy=0の全64入力で元のtrapを消す。checkedは照合項目を保存するが、単なる停止条件保存と不要値除去であり、解析を困難にする追加規則ではない。速度や解析耐性を測ったとは報告しない。対照はすべて自作の専用サンプルで、著者実装との比較ではない。

最初の試行ではtrap後のresultを照合していなかったため、最終版で比較を強化して再実行した。本ディレクトリには最終版の結果だけを収録し、最初の試行との合算はしない。初回出力は作業用tmpに残している。

## 再現

空のディレクトリへexperiment.cjsをコピーする。PowerShellでWASM_TOOLS_ROOTをWABT/Binaryenを置いた.toolsの絶対パスへ設定し、Nodeで実行する。artifactsが既存なら停止する。乱数なし。入力、全反例、環境版、各バイナリのSHA256はartifacts/results.json。WAT/Wasmも同所に保存。

## 設計に戻す条件

元の未使用値を消せたことや、値の全ビットが同時に現れないことを成功基準にしない。次候補には、通常の要求解析・状態最小化・既存符号化を越える具体的な変換規則と、それが妨げる意味復元手順が必要。今回の反例修正自体を新しい難読化アルゴリズムとは呼ばない。
