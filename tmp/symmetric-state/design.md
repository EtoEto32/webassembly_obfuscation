# Symmetric-state recurrence transformation: candidate design

2026-10-12. Research candidate, not established novelty. Previous conversational turn was no progress (goal clarification only); this work resumes implementation.

Transform a region of n parallel state variables, n=2 or3 initially, updated uniformly by a polynomial f(t)=t²+c*t+u. c is chosen each iteration from a permutation-invariant condition, namely parity of their sum. Exits expose only symmetric polynomials. Replace individual lane state with elementary symmetric coefficients e1..en; derive each next coefficient by exact integer polynomial reduction. No root extraction or decode-to-individual-state occurs within transformed iterations.

The reducer removes the lexicographically leading monomial using products of elementary symmetric polynomials. All coefficients are integers, no division by2 or3 or field assumption. The resulting integer identities survive i32 wraparound. This is a classical symmetric-polynomial algorithm, NOT an invented mathematical result. The candidate research question is whether a region transformation with explicit applicability certificates and non-injective state replacement has a useful software-protection property beyond existing quotient/data-refinement techniques. That difference remains to be established.

Original variables are public inputs; nothing claims input secrecy. Labels lost by the symmetric representation are not by themselves a valuable protected secret. Analyst receives complete Wasm and inputs, may instrument all instructions, solve polynomial constraints, or infer a simpler equivalent recurrence. Must evaluate recovery of unordered states/equivalent computation as well as labeled states. Earlier finite-machine quotient audit showed that mere information loss can hide irrelevant distinctions without protecting computation; this candidate must address that failure, not repeat its claim.

Implementation stage: polynomial-region generator, NOT arbitrary binary transformer. n=2,3, pure total i32 arithmetic, invariant branch, counted loop, symmetric outputs. No memory/import/trap/float support. Exit and branch dependence on a particular lane make a region ineligible. Preserve n=0 behavior. Normal, quotient, raw and O2 variants; ordinary source is the no-transformation control. No author-baseline performance claim until a closest implementation is identified.

Before performance or security conclusions: verify expanded-back identities over integers, independently compare compiled Wasm against BigInt reference with boundary/random inputs, record binaries and hashes; then test inverse fibers and full-trace/equivalent-function recovery. A passing semantic test does not establish obfuscation or novelty. Do not silently substitute this limited region for a practical hash function.

No search-hit absence is novelty evidence. Relevant existing mathematical reduction work and software data-refinement must be compared in full before adoption.
