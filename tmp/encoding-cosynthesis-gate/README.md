# 同時合成案の有限探索ゲート

2026-10-12。判定：この具体的探索範囲を新しい難読化アルゴリズムとして採用しない。全体目標は未達。

## 実装したものと未実装のもの

256種類の既存の多項式分割表現 D(a,b)=a+f(b) を列挙し、元演算と可換になる更新多項式を展開する探索器。fの次数は最大3、係数は各0..3。更新は x'=x²+c*x+u、c=3（uが奇数）、5（偶数）。b'=b+1とし、a'は展開した式で計算する。

これは符号化と更新を同じパラメータから生成する限定試作であり、任意のE/D/Uを独立に合成する前段設計の完成ではない。更新式の合成にSMTを使っていない。多項式の代数展開と反例なしの全数照合だけで、新しいアルゴリズムとは扱わない。

## 実験結果

- 4bitモデル：256候補×16³状態入力＝1,048,576遷移。独立BigInt/Horner実装で意味保存照合、不一致0。
- 探索用復元器：D=a+g(b)、次数<=2、係数0..15を全列挙。4,096構文、2,048異なる16点関数。
- 64候補はこの復元器で復元され、192候補が残った。
- 事前に定めた別の復元器：次数<=3、係数0..15、65,536構文、16,384関数。残った192候補をすべて復元。
- 最初の残存候補はf(b)=b³。復元式もa+b³で、候補選択は弱い文法の次数制限を利用しただけだった。
- 完全な16点関数が同じ候補をまとめて除く仕組みも実装したが、今回の候補集合では1回で除けた候補数は最大1。制約の一般化による探索効率改善も示せなかった。

復元器の照合は全16点であり、秘匿されたバイナリからの状態自動発見ではない。今回の文法内の存在判定であって、汎用解析耐性を測る実験ではない。正しい復号関係の全体的な形a+g(b)は既知とする強い解析モデル。

## i32 Wasmの動作確認

f=b³について通常版、decode→元演算→encode版、展開更新版を生成。raw/O2で6本。境界432入力とseed0xc012bc39の1,024入力、各1,456入力、合計8,736実行で正しい次状態と初期化を確認、不一致0。元の整数計算は独立したBigIntで照合する。これは有限個の入力によるテスト。代数的にmod2^wで成り立つ展開と、実装のテストは区別する。

| 版 | raw bytes | O2 bytes |
|---|---:|---:|
| 通常 | 96 | 88 |
| decode→演算→encode | 263 | 141 |
| 展開更新 | 377 | 255 |

これらはinit/decode検証用exportを含むバイナリサイズであり、実運用の保護バイナリのサイズではない。性能は測定していない。規則自体に採用根拠が得られなかったため、大規模ベンチマークに進まない。

## 採否と次に必要なもの

この試作は、前段で提案した探索方針の最も単純な具体化を試したもの。有限文法を相手にするフィードバックや多項式の次数増加に独自性は立証できず、候補も容易に復元されるため棄却する。次数4へ上げるだけの継続はしない。

元設計の未解決点は残る：復元導出を利用して候補群をまとめて除く新しい制約、符号化と更新を独立に探索する方法、途中の命令値への対応。新候補を提案するならこれらのどこを解決するか具体化する。全内部命令の計測、未知のプログラムへの適用、著者ツール比較、実行コスト評価は未実施であり、達成済みとしない。更新式展開と同時合成を混同しない。
