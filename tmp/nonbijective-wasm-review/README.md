# 1. 提案アルゴリズム（新規性未確定・現時点では不採用）

2026-10-12。ユーザー承認の独立レビューを受けた既存案の再評価。
仮称「非可逆残差の6段収束」。新規発明を確定した記録ではない。

追加の[新規性検討](novelty-reduction.md)で、Qが残差依存の可逆行列の
左乗算に書けることを確認した。非単射性だけを独立性の根拠にはしない。
さらに[初回更新後の領域の証明](even-basin-reduction.md)で、偶数残差を
正規化すると零固定置換になることを導出した。以下の全領域での非単射性は、
初回後の反復領域で既知の置換合成と異なることを示す根拠にはならない。

R=Z/(2^32)、固定入力に対する出力をf,gとする。
a=z-f、b=t-gとして、P(z,t)=(a+a(a+1)b, b+b(b+1)a)。
Pを入力とz,tの多項式へ展開し、任意の初期z,tから
(z,t) := (z,t)-P(z,t)を**同時に**6回実行する。
元の二つの式を、二つの仮の出力が相互に依存する反復計算に変える。
今回の対象はf=x+y、g=xy。全演算はi32の剰余演算。

# 2. 新規性の根拠と未確定事項

独立レビューは、旧記録の「係数抽出で復元できたため失敗」という判定を
現在の要件には使えないと判断した。復元は簡単であり、形式多項式P1の
z^2 t^0係数は-g、P2のz^0 t^2係数は-fである。

最も近い一次資料はRaneaら、CRYPTO 2022、
[Implicit White-Box Implementations](https://crypto.iacr.org/2022/papers/530630_1_En_2_Chapter_OnlinePDF.pdf)。
今回は§2のLemma 3と§3のDefinitions 3–4、および線形求解の説明を確認。
零点集合を保存して計算を暗黙化する点は共通する。
同論文のLemma 3の左合成は零固定の置換である。
本Qは非単射で、例えばmod 4でQ(1,1)=Q(3,3)=(3,3)。
したがってその特定の置換規則への直接代入ではない。
一方、零の逆像だけを保存する一般化が明白な特殊化・一般化を超えるかは
未解決であり、これをLevel 1/2の確定根拠とはしない。

求解については[Conrad, A Multivariable Hensel's Lemma](https://kconrad.math.uconn.edu/blurbs/gradnumthy/multivarhensel.pdf)
との比較が必要。過去の調査範囲は../residual-root-lifting/README.mdに保存。
今回の6段則は残差次数から直接導いたが、既知の持上げや反復解法から
独立していることを示してはいない。世界初や先行研究が存在しないことは主張しない。

# 3. 実装

build_check.pyは小さな形式多項式演算でPを展開し、example.watと
example.wasmを生成する。変換対象は固定の二出力関数で汎用変換器ではない。
Wasmのafter内ではf,gを先に計算して渡すのではなく、展開済みPを評価する。
両方の新しい値を一時localへ保存してから更新する。

Before: before(x,y) -> (x+y,xy)。
After: after(x,y) -> 初期値(0,0)から6回の多項式更新 -> 同じ二出力。
変換前後の公開関数型は(i32,i32)->(i32,i32)で一致する。
検証用after_seed(x,y,z0,t0)では任意の初期値を指定できる。
すべての初期値について結果が同じである。
副作用、メモリ、除算、トラップは対象に含めない。

リポジトリルートから実行する（生成物は同ディレクトリ内のみ上書きする）。

```powershell
.tools/runtime-analysis-py312/Scripts/python.exe tmp/nonbijective-wasm-review/build_check.py
.tools/runtime-analysis-py312/Scripts/python.exe tmp/nonbijective-wasm-review/prove.py
```

既存WABT 1.0.42、Node v24.15.0、Z3 4.13.3を使用した。
この環境ではZ3ライブラリ読み取りにサンドボックス外実行が必要だった。

# 4. 最小検証結果

更新後の残差は(-a(a+1)b,-b(b+1)a)。初回で各成分が偶数になる。
a,bがともに2^kの倍数なら次はともに2^(2k)の倍数。
従って残差の確定精度は0→1→2→4→8→16→32となり、6回で厳密解。
任意初期値に適用でき、零点からは動かない。よって零点の一意性も従う。

prove.pyはこの6つの32ビット補題の反例をZ3で探索し、すべてunsat。
これは残差更新の証明であり、WAT生成器全体の形式検証ではない。
verify.cjsは実Wasmのbefore/after/after_seedを独立なBigInt計算と照合した。
境界値7種類の(x,y,z0,t0)全組合せ2,401例と、固定seedの乱数2,048例、
計4,449例で不一致0。検証用関数も含むバイナリ601 bytes。
数値とSHA-256はresults.json、SMT結果はproof.jsonに保存。
初回のSMT起動はライブラリ権限で失敗し、権限を変えて再実行した結果が上記。
意味保存の反例は出ていない。O2、性能、SHA全体、攻撃耐性は未実施。

# 5. 結論

この具体的な関数について、任意初期値から6段で意味を保存する根拠と
動作するWasm例が得られた。旧来の解読成功だけを棄却根拠にはしない。
ただし独立した新しい変換原理は未確定で、研究目標の達成とは扱わない。
限定調査後の採否は[新規性検討](novelty-reduction.md)に記録した。
独立した差異を示せていないため現時点では不採用とし、この案の実装・試験の
追加は区切る。同一先行方式の存在を断定した棄却とは区別する。
