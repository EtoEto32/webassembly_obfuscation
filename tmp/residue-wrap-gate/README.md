# RNCをi32へ適用する前の意味保存ゲート

2026-10-12。独立研究の実装前検証。新規難読化アルゴリズムの成果ではなく、符号化領域内で演算をまとめる候補の適用条件を具体化するもの。

## 先行資料と確認範囲

HOACS, Hossainほか、arXiv:2402.09701v1、2024。https://arxiv.org/pdf/2402.09701 。§II.CのRNC定義、§IIIとTable IIの関連記述を確認。加減乗算と他の操作を区別し、Table IIにはoverflow/underflowの検査も記載される。https://github.com/ASTHA-Lab/HOACS のREADMEも確認したが、現在のソースを精読・実行していない。READMEは2026年版の研究に言及しているので、2024年論文と完全に同一の実装だと仮定しない。

本実験は著者コードの再現でもバグ報告でもない。以下の自作した「補正なしの単純RNC」をWasm i32へそのまま適用する案を検証する。

## 実装と観測対象

moduliは65537と65539、積M=4295229443（2^32より大きい）。互いに素で、すべてのu32入力は一意に符号化できる。加算と乗算について、各成分で演算して各modulusで剰余を取り、CRTで[0,M)へ戻して最後にi32へ縮める。

専用の6関数を持つWasmをWATから生成した。任意Wasmの変換器ではない。

- plain_add/mul：Wasm i32の通常演算。
- residue_add/mul：補正なしの成分ごとの演算とCRT。
- normalized_add/mul：まず通常i32演算を行い、その結果を符号化・CRT復号する診断用対照。符号化状態のまま計算する方式ではない。

各成分の積と今回のCRTの中間値にはi64を使用し、i64範囲内に収まる。メモリ、import、外部通信なし。BigIntの独立計算で通常のmod 2^32結果と、mod M後にmod 2^32へ縮めた結果をそれぞれ求める。

## 結果

各演算1,124組（境界値100組、seed 0x17ac2481の乱数1,024組）。通常版と診断用対照は期待値とすべて一致。補正なしRNCは加算513組、乗算1,068組で通常i32と不一致。一方、補正なしRNCが計算すべきmod Mの期待値とは全例一致した。

例：2 * 4294967294 のi32結果は4294967292だが、補正なしRNCは4294705145になる。CRTを正しく実装しても、演算している剰余環が異なるためである。

8bit版の符号化E(x)=(x mod17,x mod19)では全65,536組を調べ、E((x+y) mod256)と成分ごとの加算が32,640組で一致しなかった。これは8bit領域での全数確認であり、32bit全入力実行ではない。

## 適用限界の説明

標準の写像x→x mod mがZ/(2^w)の加算をそのまま保存するにはmが2^wを割り切る必要がある。1を2^w回加えることを考えると、元の環では0だが、成分側では2^w mod mになるためである。したがって、互いに素な二つ以上の非自明なmodulusを選び、標準の成分演算だけで全i32演算を保存する構成は成立しない。

これは通常の剰余算術の性質で、新しい不可能性定理ではない。補正、別の表現、演算範囲の制限、部分復号等を含む方式を否定しない。「入力を一意に表せるほどMが大きい」と「全演算列のi32意味を保存する」を混同しない。

純粋な非負整数の多項式領域では、整数として評価した中間結果がM未満であることを保証できれば、この特定のMによる折り返しを避けられる。ただし途中のi32値を使う比較・ビット演算・副作用の観測は別途扱う必要がある。分岐を勝手に除いて対応済みとしない。

## 候補への反映

補正なしRNCをそのまま全i32へ使う案は棄却する。符号化したまま演算する候補全体を棄却するのではない。次の設計では、補正の具体的な規則と平文が現れる地点、または安全にまとめられる領域の判定を明記する必要がある。

現時点では、それを新規アルゴリズムと認めるだけの差分はまだない。今回の正しさ試験を公平な4条件の有効性・性能比較の代用にしない。性能測定、解析耐性、一般バイナリ変換は未実施。研究全体の目標は未完了。
