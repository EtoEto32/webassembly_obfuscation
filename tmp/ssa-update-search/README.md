# 命令構造を選ぶ更新式探索器の試作

2026-10-12。合成器の対照試験であり、新しい難読化アルゴリズムの採用ではない。前回の作業は設計仕様と文献比較のみ。今回は実行可能な探索器と、別の式評価系による全入力検査を実装・実行した。

## 何を実装したか

以前のindependent-update-synthesisは既定の多項式基底の係数を合成していた。今回は演算子・引数・式の木構造を選ぶ。葉はa,b,u,0,1、二項演算はadd/sub/xor/and/or/mul、各出力式は最大3演算。共有部分式を持つ一般SSAグラフではなく、式の構文木の対を生成する試作である。ファイル名・フォルダ名のSSAは今後の展開用で、SSA変換器完成を意味しない。

同じ評価列を持つ式をまとめる。ただし途中に元の値xを恒等的に計算する式がある／ないの二種類は分ける。二出力について、右出力の評価列から必要な左出力の評価列を計算して辞書で照合する。全候補対を逐一評価する方式ではない。これは既存の列挙・観測同値削減・照合に基づく探索で、新しい原理とは主張しない。

合成対象は固定した対照表現x=a XOR b、元の更新はx'=x+u。初期化は公開多様化値rを使いa=x XOR r,b=rとできるため、全(a,b)状態が到達可能である。rは秘密ではない。この対照を新しい符号化と扱わない。

正しさ条件は `a' XOR b' = (a XOR b)+u`。正しさのみの選択と、途中でxそのものを恒等的に計算する式を避ける選択を比較する。後者も、単に「内部値を直接計算しない」という弱い条件で、復元耐性ではない。観測できる入口a,bのXORで全候補の元の値を復元できる。

## 実行結果

2bitの全64状態で29,666式の生成を試み、意味と露出フラグでまとめた10,798項目を得た。出力対は408組が一致（左右交換などの重複を含む）。これは新手法の数ではない。

|選択|生成された更新|結果|
|---|---|---|
|正しさのみ|a'=0, b'=u+(a XOR b)|2bit/3bit/i32で同値。元の値をそのまま計算する|
|元の値を直接計算しない|a'=a, b'=b+(a XOR (a+u))|2bitで同値、3bit/i32で不正|

後者はa=b=u=1で、3bit以上では期待1に対して出力5となる。さらにZ3による独立のビットベクトル翻訳でも、2bitはunsat、3bit/i32はsatとなった。有限入力試験のみで一般化していない。

最初からi32の演算で、小値64組＋固定seedの乱数12組を使った探索も実施した。41,735生成試行、21,714項目（葉を含む）、20出力対が一致。正しさのみの候補は同じ式で、Z3がi32全入力の同値性を確認した。「元の値を直接計算しない」条件の候補はこのサンプル上の辞書にはなかった。

この「候補なし」は、文法全体のunsat証明ではない。サンプルによる同値類の代表化が異なる式をまとめている可能性がある。小幅やサンプル上で一致する式を捨てる探索と、全i32意味で同値な式だけを捨てる探索は異なる。

探索はSMT反例が出ればサンプルに追加して再構築する上限4回のループを持つ。ただし今回i32で選ばれた候補は最初から正しく、反例による再探索は実際には発生していない。反例誘導の速度改善を実証したとは言わない。

## 検査の独立性と限界

search.pyの具体値評価とi32_search.pyのZ3翻訳を分けた。著者・開発者として独立した検証ではない。生成語彙は純粋な整数演算のみ。メモリ、trap、分岐、一般ループ本体、Wasmバイナリへの変換は未対応。実行時間やサイズの比較はしていない。JSON内の時間は探索・検証時間であり、生成プログラムのオーバーヘッドではない。

出力式にxが現れるかの判定は、全入力（2bit）または現在のサンプル（i32）について恒等的に一致する部分式があるかを見る。特定入力で偶然数値が一致することや、NOT等で簡単に復元できることまで排除しない。入口の一演算復元が成功するため、この対照から保護効果を主張できない。

## 既存手法との位置付け

Gulwani, Jha, Tiwari, Venkatesan, *Synthesis of Loop-Free Programs*, PLDI 2011。著者機関の出版ページ・要旨を確認：
https://www.microsoft.com/en-us/research/publication/synthesis-loop-free-programs/
部品からの命令列合成と反例誘導・SMT利用は既存。今回その著者ツールを実行しておらず、論文全体・実装を精読した比較でもない。

観測同値削減についてMetric Program Synthesis（arXiv:2206.06164）の著者要旨を確認：https://arxiv.org/abs/2206.06164 。既知の観測同値を緩める研究として記載される。本文は未読。今回の辞書実装を、その方式の再現や新規な改善とはしない。

## 再現と次の課題

Python 3.12.14、Z3 4.13.3、i32サンプルseed=5460801。新しい空のコピー先で `python search.py`、続いて `python i32_search.py`。Z3の親ディレクトリをWASM_SYNTH_DEPENDENCIESで指定できる。結果ファイルが既にあれば上書きを拒否する。

results.jsonに小幅探索と検査、i32-results.jsonにSMT結果・i32サンプル・探索結果を保存。生成WasmはないのでWasmハッシュは該当なし。inventory.jsonは保存ソース・記録のハッシュ。

更新の命令構造を探索する部分は動いた。一方、符号化そのものの同時合成、復元の導出を一般化する独自規則、公平な既存方式比較は未実装。固定XOR表現を複雑化しただけで新方式にしない。次はこの欠落を埋める具体的規則の設計が必要で、単に探索を長時間回すことはしない。研究全体の目標は未達成。CSEC原稿・以前の実験は変更していない。
