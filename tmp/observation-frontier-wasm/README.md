# 観測集合の反例をi32 Wasmで確認

2026-10-12。observation-frontierの小幅モデルを実際のWasmへ移した検証。新しい難読化方式の提案・採用ではない。前回の作業は観測集合の包含による枝刈りを実装・全数比較した進捗あり。

## 検証対象

P=(a+b)+c、Q=a+(b+c)、同じ文脈C[e]=e+c*c。いずれもi32のmod2^32算術。対象の復元値T=(a+b)*c*cは例示用で、プログラム理解に不可欠な秘密だとは主張しない。単純な結合順序の変更自体も新規な変換ではない。

P、Q、C[P]、C[Q]の4種類をWATから生成し、rawとBinaryen 133の-O2を比較した。これは専用サンプル生成器で、任意Wasmの変換器ではない。

## 最適化と計測の順序

先に非計測Wasmを最適化し、WABTで逆アセンブルした。その後、各算術命令の結果を記録して同じ値を返すimport呼出しを挿入した。したがって計測importがBinaryenの最適化を妨げた結果ではない。

ただし計測版と非計測版はV8が別々にJITする。これは**最適化後のWasm命令の値**の観測であって、非計測版のネイティブJITコードに現れる値を取得したものではない。JIT最適化に対する耐性を確認したとは言わない。

観測対象は公開引数a,b,c、定数0,1、全算術命令の結果。値の固定した位置から、射影・NOTまたはadd/sub/mul/xor/and/orを1回適用する全候補を列挙した。任意の式・任意の解析器を網羅する評価ではない。

## 結果

|式|raw/O2の非計測サイズ|1演算でTを復元|2演算の明示的復元|
|---|---:|---|---|
|P|46 byte|候補なし|今回対象外|
|Q|46 byte|候補なし|今回対象外|
|C[P]|52 byte|成功|成功|
|C[Q]|52 byte|候補なし|成功|

全4種類で、rawと-O2のバイナリはそれぞれ同じSHA-256だった。8条件を8個の異なる方式とは数えない。非計測バイナリは4種類、計測版も4種類が重複なく存在する。

1演算の探索にはa,b,c各0..7の全512入力を用いた。C[P]ではa+bとc*cを掛ける式が見つかった（左右の交換で2件）。境界値・固定seed乱数の未学習997入力でも一致。C[Q]でも、引数a,bから和を計算し、観測済みc*cを掛ければ**2演算で容易に復元できる**。この2演算の式は明示的に構成したもので、自動2演算合成器の結果ではない。

全8条件で、計測・非計測の双方を1,509入力ずつ実行し、独立したBigInt基準計算と比較して不一致0。計24,144回のWasm呼出しだが、4種類の小さな式の検査回数にすぎない。

加えて、逆アセンブルから構成した算術式を別のPython/Z3翻訳器で検査。全8条件の出力、C[P]の1演算復元4件、文脈付き4条件の2演算復元について、計16件すべてi32でunsat。問い合わせ前に正確な多項式正規化を使用した。Z3の解析耐性やソルバー性能を測った実験ではない。

## 判断

同じ出力でも途中値の違いにより限定された復元式の有無が変わるという反例は、i32 Wasmでも成立した。この例ではBinaryen -O2で違いが消えることもなかった。

しかし差は1演算対2演算であり、有効な難読化を示していない。既知の代数的結合順序を新方式として採用しない。前回の作業の枝刈り規則の検証には使えるが、規則の新規性・有用な変換の発見・実用的解析コストの増大は別途必要。

## 再現と成果物

Node v24.15.0 / V8 13.6.233.17-node.48、WABT 1.0.42、Binaryen 133、Python 3.12.14、Z3 4.13.3。乱数seed=0x4f425357。取得したバージョン文字列はartifacts/variants.json。既存のartifactsがない新しいコピー先で順に実行する。

1. `node experiment.cjs`：非計測Wasm、最適化版、逆アセンブルを生成。
2. `node analyze.cjs`：最適化後の計測、具体値照合、1演算復元探索。
3. `python prove.py`：i32の式・復元式を検証。

WASM_TOOLS_ROOTでツール配置、WASM_SYNTH_DEPENDENCIESでZ3の親ディレクトリを指定できる。成果物は既存なら上書きを拒否する。JSON中の絶対パスは実行時の作業場所で、独立リポジトリには同じファイルを相対配置で複製している。

- artifacts/*.wasm、*.wat：生成・最適化・計測版。ハッシュはvariants.json、results.json、inventory.json。
- artifacts/inputs.json：全入力、学習境界、seed。
- artifacts/*.observations.json：全観測値、実測出力、基準値。
- artifacts/results.json：復元候補、正しさ、サイズ、式。
- artifacts/proofs.json：全SMT結果と2演算復元式。

この検証から実用的な保護を主張できないため、実行速度の微小差を測って候補を延命しない。前回の作業の規則については先行研究との比較と、実際に有用な新規変換を生成できるかが未完了。研究全体の目標は未達成。CSEC原稿、以前の実験、保護設定は変更していない。
