## 今回の実測

Node.js v24.15.0 / V8 13.6.233.17-node.48、Binaryen 133。importやネットワークを使わない小さなモジュールのみ。

1. `probe.cjs`：GC型、例外tag、select/ifの評価順について5例を実行。期待した結果と5/5一致。
2. `direct-gc.cjs`：アセンブラの型統合を避け、型定義を別々に残した7バイナリを直接生成。型同一性の事前予測と7/7一致。
3. `recover-gc.cjs`：生成器・期待値JSONを読まず、上記7バイナリの型節と制限した命令列だけからref.testの結果を再構成。実行結果との一致7/7、推定用の実行問い合わせ0回。

最後の照合では予測をすべて確定してからエンジンで実行する。解析対象は定数を返す7例だけであり、一般のGCプログラム、参照を含む再帰型、動的型フロー、元ソースの復元には対応しない。生成器とは別のコードだが、同じ研究作業で記述した検証器であり、第三者による独立再現ではない。

| 直接生成した型配置 | ref.testの結果 |
|---|---:|
| 同形structを別々の暗黙単一型グループに定義 | 1 |
| i32フィールドとi64フィールド | 0 |
| 同形structを別々の明示単一型グループに定義 | 1 |
| 一つの2型グループ中の同形struct同士 | 0 |
| 同じ2型グループを複製し、同じ位置の型を比較 | 1 |
| 同じ2型グループを複製し、異なる位置の型を比較 | 0 |
| 単一型グループと2型グループの同形struct | 0 |

型名やtype indexが異なるだけでは別の状態を表現できない場合がある。一方、グループ内の位置などによって同じフィールド形状でも型を区別できる。しかし今回の単純な配置の判定結果は静的に復元できた。これだけを解析耐性や新アルゴリズムの根拠にはしない。

## 候補台帳

解析者はWasmバイナリ全体と公開関数へのアクセスを持つとする。変換器の内部メタデータは与えない。秘密鍵・暗号学的安全性は主張しない。

| 候補 | 保護対象・変換 | 近い手法と差分 | 現在の判断・棄却条件 |
|---|---|---|---|
| A: 例外tagでの制御転送 | 分岐先をtagとhandlerで選び、生存値をpayloadで渡す。制御の対応関係を隠す狙い | Drape 2009 §2.4.1に例外によるループ脱出やswitchの変換がある。Wasm tagの型付きpayloadは実装差 | 単純なbranch→throw置換を新しい原理として採用しない。payloadの受け渡しだけでも不十分。例外CFGの復元を阻害する固有の差分が必要 |
| B: GC型による状態表現 | 状態をstructの型・グループ位置で表し、ref.test/castで処理を選ぶ。状態の対応の復元を難しくする狙い | 型による分派・データ表現変更が近い。CHFはクラス階層を変換する周辺先行研究で、同一アルゴリズムとは断定しない | 型名のみの区別案は不成立。静的グループ識別だけの案も今回7例で復元可能。動的な状態の対応を含む案は未設計・新規性未確認 |
| C: SIMDによる値混合 | 値を複数laneへ配置し、演算をvector化。値の依存関係を隠す狙い | AVX-512を使った既存VM難読化の作者説明あり。アフィン混合は前回の棄却理由も適用 | SIMDを使っただけでは採用しない。具体的変換は未設計。スカラー化・式簡約後に差がなくなるなら効果を棄却 |
| D: 分岐をselectへ移す | 両候補値を計算し選択する | 通常の条件付き選択。独自性の根拠なし | trap・副作用がある枝を無条件評価すると意味を保存しない。一般変換として採用しない |

候補A/Cの現時点の差分では本実装を拡大する根拠が弱い。Bは言語機能の前提確認までであり、採用を決定していない。これらを棄却・保留したことだけで研究目標の達成とはしない。

## ツール失敗の記録

初回はBinaryenの`--all-features`により、Nodeの標準設定では受理されないexact heap typeを含む出力が生じた。元スクリプトを`probe-initial-all-features.cjs`、結果を`results/initial-all-features-probe.json`、失敗バイナリを`results/gc-same-shape-all-features.wasm`に保存した。必要な機能だけを明示する現行runnerでは5例とも実行できた。これは互換性問題であり、難読化の効果ではない。

Binaryenを通す`gc-same-shape.wat`では同形型が統合されるため、それだけでエンジンの型同一性を結論付けなかった。直接バイナリ生成の7例はこの交絡を避けるため追加した。

## 再現

このディレクトリで実行。先に結果を保存したい場合はディレクトリ全体を複製する。これらのコマンドは対応するresultsを更新する。

```powershell
node probe.cjs C:/path/to/binaryen-version_133/bin
node direct-gc.cjs
node recover-gc.cjs
```

`results/probe.json`は最初の作業用ディレクトリでの実行パスを保持する。direct-gc/recover-gcはNodeの標準ライブラリだけを使用。乱数なし。ソースとバイナリのSHA-256、バージョンは各JSONに記録。全体の保存時ハッシュは`inventory.json`。
