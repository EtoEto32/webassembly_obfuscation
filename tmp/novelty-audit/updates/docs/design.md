# 設計：構造化境界での状態再符号化

> 2026-10-11監査：この案を新アルゴリズムとして採用しない。多変数符号化・領域別切替・境界合成に直接の先行例がある。
> [新規性監査](novelty-audit.md) に出典と追加実験を記録した。以下は試作の設計記録として残す。

## 研究候補

各Wasm領域の生存値の組を、その領域専用の表現に変える。分岐合流やループの戻り先で
型の合う値の組を渡しながら、表現を明示的に合わせる。
「変数のアフィン符号化」は既知であり、本研究候補の検討点はWasmの多値境界への配置と評価である。
新アルゴリズムとしての新規性は支持できない。通常のコード保護・解析研究用である。

## 算法

状態を列ベクトル v=(x,y)、領域を r とし、すべてを Z/(2^32) 上で計算する。

```
E_r(v) = A_r v + b_r
D_r(z) = A_r^(-1) (z - b_r)
```

A_rは行列式が奇数の2×2行列とする。2^32と互いに素なので逆行列が存在する。
コードでは逆行列を生成時に計算し、実行時の除算は使わない。
定数を署名付きi32で出力しても、同じ32ビット列を表す。

元の領域の計算Fと移動先sに対し、次を出力する。

```
T_(r,s) = E_s ○ F ○ D_r
```

Fがアフィン変換なら、生成時に行列・定数を合成できる。実行時に各領域で平文へ戻す必要はない。
外部の引数を入口で符号化し、公開戻り値だけを出口で復号する。
符号化パラメータはバイナリから読める。暗号鍵の秘匿や暗号学的な安全性はない。

### 小さな例

元の処理は `(x,y) -> (x+y,y+1)`。
入口で `u=x+3y+5, v=y+7`、出口で `p=x'+11, q=2x'+y'+13` と表すと、境界の処理は

```
p = u - 2v + 20
q = 2u - 3v + 25
```

になる。`examples/boundary-demo.wat` がそのまま動くサンプルである。

## Wasmでの境界処理

- ifの両側は各々の表現で計算し、同じ合流先の表現に直して `result i32 i32` を返す。
- loopへ戻るbrはループの**入力**型に従う。本試作は2値をループ先頭の表現に直して渡す。
- 外側blockへ脱出するbrはblockの**結果**型に従う。ここでも期待する表現を合わせる。
- br_ifが成立しない場合、ラベルへの引数はスタックに残る。本試作では明示的にdropしてから更新する。
- 2値を同時に計算してからlocalsへ保存し、1値の更新で他方の旧値を壊さない。

型だけでは表現の取り違えは検出できない。i32 i32が同じでも別領域の符号化なら出力が壊れる。
そのため各移動の元・先・元の処理・合成後の式をmapping.jsonへ保存する。

## 意味保存の考え方

正しい入力表現 z=E_r(v) が来れば、

```
D_s(T_(r,s)(z)) = F(v)
```

となる。両分岐と各ループ反復にこの不変条件を適用できる。
分岐条件は元と同じflagの下位ビット、反復回数はn & 15のままである。
終了・分岐選択も一致する。i32のadd/sub/mulは剰余演算で、対象にはtrapする演算がない。
これは制限した抽象変換の代数的説明であり、Python実装全体の機械検証ではない。
有限のWasm実行照合は生成器やスタック処理の誤りを見つけるために併用する。

## 比較条件

1. baseline: 全領域を恒等表現にする。多値ブロック構造は共通。
2. global: 全領域で同じアフィン符号化を使う。領域別切替を除いた対照。
3. per_region: 7領域で独立した表現を使う。

各符号化条件は3シード、3プログラムで実行する。さらに各バイナリへ同じBinaryen -O2を適用する。
globalは自作の単純な対照で、Tigressそのものの再現ではない。

## 限界と反証可能性

アフィン式は線形代数、定数伝播、記号実行で簡約できる。分岐・ループの骨格と条件は隠れない。
固定flag/nごとなら、関数全体もアフィン写像である。この低い耐性を隠して「強い難読化」としない。
O2後にサイズ差が残っても、解析耐性の証拠にはならない。
既存の単一命令パターン正規化が使えないことも、新規性や耐性の証明にはならない。

追加の入出力推定では、baseline/global/per_regionの全42本・1,344制御条件で、各3回の問い合わせによってアフィン式を推定できた。
別入力1,438,080出力ペアの照合で不一致は0だった。内部式や元ソースの復元を示したものではない。

今後は、同一条件のglobal版との差、既存簡約器による復元率・時間、型付き合流の復元誤り、
複数ランタイムのコストを測る必要がある。改善がなければ、この案は有効性の低い候補として棄却する。
多値だけ版、局所encode/decode版、既存Tigress等との比較も未実施である。

浮動小数点、整数除算、シフトを含む一般式、メモリ、呼出し、例外、参照型、SIMD、
任意のbr_tableや任意Wasmの変換は未対応。対応したように見せる代替処理は行わない。
