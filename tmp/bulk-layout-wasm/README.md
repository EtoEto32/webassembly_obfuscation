# Gの実際のWasm検証と棄却判断

実験日2026-10-12。前段 `../bulk-layout-gate/README.md` の設計ゲートを実際のWasmで確認した。

## 結論

**今回の固定配置変換とbulk fast pathの候補は、新しい難読化アルゴリズムとして採用しない。**
意味保存のテストには合格し、連続範囲の高速化は観測した。しかしXOR定数を用いる既知の配置変換から抜け出しておらず、配置パラメータは全4本から静的に抽出できた。最適化後も同じだった。
前段の「bulk制約を踏まえた配置選択」自体を一般の変換器として実装したわけではない。その実装に進む前に、この具体案の保護効果の根拠が不足するため見送る。あらゆる配置変換を無効とする判断ではない。
パラメータを別の定数にしたり、MBAを足しただけで次の新方式としない。非線形カーネルを増やしてこの否定結果を隠さない。

## 実装条件

1ページ固定65536バイト、論理位置iの物理位置は `i XOR 23040`。256バイト内の順序を保ってブロックを置き換える。
`copy(d,s,n)`を公開し、データ移動そのものを変換した。バイト単位のコピーなのでデータの値には依存しない。
通常版はmemory.copy、mapped-loopは論理方向を守る1byteループ、mapped-bulkは両範囲がそれぞれ256byteブロック内に収まればmemory.copy、それ以外は同じループ。
mapped-loopは最も近い自作対照とbulk部分のablationを兼ねる。同じ実装を別名の第四条件に水増ししていない。先行研究の著者実装は実行していない。
各3方式をraw/O2で生成し、計6本。専用Wasmの生成器であり、任意Wasmの変換器ではない。

mapped版はi64へゼロ拡張してsource+lengthとdestination+lengthを検査してからメモリを変更する。ゼロ長でも先に境界検査を行う。論理アドレスの大小で重複コピーの方向を選ぶ。
実験用に物理メモリをexportして入出力を検査した。ホストに同じ論理メモリ表現を公開する一般的ABIは未実装であり、任意の既存ホストプログラムに置き換えられるとは主張しない。
imports、共有メモリ、grow、atomic、実用ハッシュは対象外。

## 正しさ

568組の入力。ゼロ長、ブロック境界、65536境界、範囲外、重複、0xffffffff、ランダム範囲を含む。
BigIntで独立に範囲を判定し、元のメモリsnapshotから期待値を作る。各呼出し前にメモリをリセットする。
6本×568=3408比較で、trap有無と全65536byteの復号後メモリが一致。不一致0。各バイナリ203ケースはtrapで、メモリが変更されないことも検査した。
これは有限の入力と固定配置についての結果で、一般の意味保存証明ではない。trapのメッセージ文字列やスタックトレースの同一性は検査していない。
入力、生の各判定、メモリSHA、初期メモリ、バイナリSHAはartifactsに保存した。

## 解析者側の確認

recover.cjsの入力はファイル名とWasmだけ。元WAT、manifest、元の配置値は読まない。
既知の「アドレスをXOR定数で変える」方式を想定し、wasm2watで逆アセンブルして定数直後のxorを抽出する。4本とも候補が1個となった。
元配置との照合は別のreport.cjsで行い、4本×65536位置で一致を確認した。
実行問い合わせ0。抽出と逆アセンブルを含む観測時間は約9–11ms/本、単回の測定。一般解析器、ブラインド解析、CFG復元、元ソース復元とは呼ばない。全xorがアドレス演算であることを自動証明する処理もない。
新たな解析耐性の根拠がないことを示す限定的な否定結果である。

## 探索的な時間測定

各条件12×4096コピーのウォームアップ後、7ラウンド。各ラウンド内はseedに基づき条件順をシャッフル。1測定16384コピーをWasm内ループで実行。メモリリセットは時間外。
同一入力を反復するマイクロベンチマークであり、実アプリケーション速度やデータ依存経路の性能ではない。

O2、通常版に対する同一ラウンド時間比の中央値:

|入力|mapped-loop|mapped-bulk|
|---|---:|---:|
|ブロック内128byte|12.19|1.56|
|ブロックを跨ぐ512byte|30.45|30.56|
|重複128byte|10.31|1.40|

倍率が大きいほど遅い。最小・最大・中央値と全126件の生時間はsummary.json/timings.jsonに保存。通常版の一部測定は0.1ms前後と短く、単一プロセスであるため精密な性能比較には弱い。肯定的な性能主張をするなら長いバッチと複数プロセスで再測定が必要だが、今回の候補棄却はこの速度差に依存しない。

O2のサイズ: 通常108、loop228、bulk279byte。正確な命令数は未集計。ファイルサイズを命令数・解析耐性と扱わない。
