## 4. 検討した規則と判断

### C1: データ依存VPCの符号化

Before: 論理ラウンドiと状態sを持ち、s'=T_i(s), i'=i+1。
想定After: 状態成分aとp=i XOR aを持つ。更新はi=p XOR aを求め、s'=T_i(s), p'=(i+1) XOR a'とする。演算は同じ幅のビットベクトル上。

不変条件p XOR a=iから意味保存は帰納的に説明できる。しかし1回のXORで論理位置を復元し、更新の途中でその値を使用する。固定VPCスロットをなくした事実だけでは復元に要するコストの増加を支持しない。既存DataMeld・データ符号化との差も未確立なので不採用。乱数や非線形関数を足すだけの派生探索は開始しない。

### C2: 合流時の相関消失を利用

Before: 論理位置iを保持する。
想定After: 入力由来rとz=i+r mod 2^32を保持し、制御先をz-rから選ぶ。異なる経路のr,zを独立にTOPへ抽象化すれば、抽象解析がiを失う可能性はある。一方、具体状態ではz-r=iであり、同一経路内の式簡約でも戻る。

解析器が相関を保持しないことを狙う設計は既存の抽象解釈に対する難読化と重なる。この式は通常の加算符号化である。「合流後の候補アドレス数が増えた」という値だけを解析耐性の成果としない。今回の具体案は不採用で、既知恒等式の数値試験を追加しない。

### C3: 制御とデータに固定した分解を持たせない共同更新

単に物理語を共同使用する案なら、ビットフィールド統合やC1へ戻る。そうでない案には、少なくとも二つの元演算と入力依存分岐を、具体的な共同更新命令へ写す規則が必要である。今回はその規則を構成できなかったため、設計未完了。新しい候補を発明・採用したとは数えない。一般的なdata refinementで記述できるという理由だけで、将来のすべての具体案を既存と断定することもしない。
