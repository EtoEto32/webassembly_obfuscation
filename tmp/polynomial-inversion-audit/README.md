# 置換多項式の逆変換：著者本文の照合と比較器の実装

2026-10-12。これは新しい難読化方式ではない。encoded-root-updateの後に、既知の一変数多項式表現へ戻る案を判定するため、より一般的な復元器を実装した。元の研究目標は未達。

## 結果

係数を受け取らない復元関数に、ビット幅と符号化関数の呼出し口だけを渡した。162個の整数係数の置換多項式について、64,648件の元の入力をすべて復元した。入力生成の次数上限は1,2,3,7,17,65。最高係数が0になる可能性があるため、正確な次数ではなく上限と呼ぶ。

| 幅 | 多項式数 | 関数ごとの復元用問い合わせ数 | 照合範囲 |
|---|---:|---:|---|
| 3,4,5,6,7,8 | 各18 | 4,6,8,8,8,10 | それぞれ全入力 |
| 16 | 18 | 18 | 境界値と乱数、重複除去 |
| 32 | 18 | 34 | 境界値と乱数、重複除去 |
| 64 | 18 | 66 | 境界値と乱数、重複除去 |

結果の問い合わせ数は復元段階のみ。検証器による正解照合のためのP評価は含まない。32bitと64bitの全入力を実測したわけではない。速度の反復測定やWasm性能比較は行っていない。

## 実装と前提

recover.pyの引数はwidthとoracleだけ。入力係数はcheck.pyの検証側に保持し、入力JSONとして保存している。隠した係数を復元器へ渡した実験ではないが、同じPythonプロセスでありOSによる隔離ではない。oracleは内部表現を個別に問い合わせられるという強い条件を置く。未知Wasm内からその関数を抽出する処理は未実装。

v2(i!)<wとなる最大iをdとし、P(0)..P(d)を問い合わせ、Q(P(i))=iを満たすNewton積基底の係数を三角形順に求める。係数の合同式は、分母の2の因子を取り除いてから奇数部分の逆元で解く。Pが整数係数の置換多項式であることは前提であり、任意のブラックボックス関数へ適用できるとは主張しない。

これは著者コードの実行ではなく、論文の入力・出力関係を参考にした自作比較器である。著者のreduced monomial形式とは出力形式が異なる。実装の正しさは独立した直接冪乗によるP評価で照合したが、第三者による再現ではない。予算切れや失敗を別手段で置き換えず、全検証例をresults.jsonに残した。

## 研究候補への判断

前回の平方根補正ではrの構造を利用したが、この比較器はrも元の係数も受け取らない。一変数の多項式符号化を単独で評価できる限り、次数の増加だけを解析耐性の根拠にする案は見送る。式を巨大化して各問い合わせを高価にすれば費用は増えるが、正規の実行コストとの比較が必要であり、それだけを新しい保護原理としない。

これは多変数の符号化、非多項式演算、内部関数を個別評価できない場合、全プログラムの意味再構成の結果ではない。仮に次候補がその範囲を扱っても、「比較器が未対応だから強い」とは判断しない。独自の更新規則と適切な解析対照を別に必要とする。
