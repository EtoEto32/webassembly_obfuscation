# 探索候補の有用性検査：ランク差と実在する途中値を区別

2026-10-12。前回 observation-span-frontier の候補を実際の保護効果へ結び付けられるか調べた。新しい難読化方式は採用しない。探索部品の正しさと、得られた変換の有用性を分離した実験。

## 条件

前回と同じ生成器をoriginal_frontier.pyとして固定。二つの2bit入力全16通り、定数0/1、add/sub/xor/mul、式の構文木最大3演算。入力の全ビット、定数、すべての途中値を観測できる。次数d以下のBoolean多項式で任意個のXOR項を使う復元者を対象とする。ソース形状や命令情報による解析コストは対象外。

同一出力で最初に見つかる最小演算数の代表を基準に、各候補の復元可能関数空間を比較した。この代表は通常コンパイラの出力でも既存難読化器でもない。従って実用方式に対する優位性を測る公平な比較を完了したとは言わない。

## 得られた結果

|対象|次数|同じ空間|真に狭い|真に広い|包含で比較不可|
|---|---:|---:|---:|---:|---:|
|基準の全3,654プロファイル|2|3,010|114|529|1|
|線形包で保持した392プロファイル|1|344|45|0|3|
|同上|2|346|45|1|0|
|同上|3|375|17|0|0|
|同上|4|392|0|0|0|

392候補中45件では、同じ演算数の基準より二次の復元可能関数空間が狭い。ただし、各基準プログラムに**実際に現れた途中値のビット**（共通の最終出力を除外）を対象にすると、45件すべてで復元できないビットは0件だった。これは最終出力や入力だけを対象にして得た結果ではない。比較が等しい/広い他の候補も、基準の復元可能なビットを失わせない。

二次特徴の生成は、縮約した線形基底同士を掛ける方式に加え、元のすべての観測ビット同士を直接掛ける方式でも3,654件照合し一致した。全16入力の関数表を使用し、学習データだけでの判断ではない。

## 数値だけだと誤解する例

基準 `a+(a+b)` を候補 `b+(a+a)` に替えると、二次特徴空間の次元が13から11になる。演算数はいずれも2。しかし基準の途中値a+bの各ビットは、候補でも公開入力から二次式で復元できる。失われた関数には、観測値をさらに組み合わせた関数が含まれる。保存した target_truth_table=450 も、元処理の重要な秘密だと設定したものではない。

この例の結合順序変更は既知の算術変形であり、新規アルゴリズムではない。さらに4個の公開入力ビットしかないため、次数4まで許せば元の入力だけですべてのブール関数を表せる。次数4で全空間が一致することも、この小領域の制約と整合する。

## 採否と次の探索条件

今回の小領域・小文法から得られた候補群を、有効な新しい難読化方式として採用しない。線形包による枝刈りの健全性は否定されないが、この実験で生成できた変換の保護効果は示せなかった。探索器の保持数やランク差を主成果に置き換えない。

今後の候補選択では次を必須にする:

1. 保護対象を元処理の非公開の実在する中間計算として事前に定め、その重要性を説明する。復元しにくい関数を結果から選ばない。
2. その対象について復元の成功・失敗と費用を直接測る。特徴空間の次元は補助指標に限定する。
3. ビット多項式の次数だけでなく、Wasmの加算・乗算など少数の機械演算で復元できないかも確認する。
4. 小幅モデルの式をi32へ無条件に移さない。意味保存と復元に要するコストを実幅で検証する。
5. より大きな探索を行う場合も既存変換との差を明示する。単に探索量を増やしたことを新規性としない。

これらは新しい難読化アルゴリズムの提案ではなく、不適切な成功判定を防ぐ検証条件である。大きな文法や別の変換方向全体を否定した結果ではない。
