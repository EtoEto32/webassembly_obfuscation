# F候補の公平な初期化対照

確認日: 2026-10-12。前段: `../typed-dispatch-audit/README.md`。

## 判断

**非nullの型付きループ引数を使うだけで、同じflattening範囲のままnullable化を避けるという案を、新しい難読化方式として採用しない。**
前段のtyped-loop-payloadは実データの生成をループ外へ移していたため、初期化処理まで含む対照と同じ変換範囲ではなかった。
今回は実データ生成をstate 0、読み出しをstate 1に置く構造を維持した。
型付きループへ最初に入る時点でも非null値が必要になり、nullを渡す条件は検証で拒否された。
ダミー値を渡せば受理されるが、通常localを同じダミー値で事前初期化する条件も受理される。
この小実験で一般の型付き領域計画を不可能と証明したわけではない。しかし現状の案には、既知の値受け渡し・初期化を超える変換規則や解析への効果がない。

## 実験

`probe.cjs`はNode標準ライブラリだけで5本のWasmを直接生成する。アセンブラの自動修正を挟まない。
全条件で関数run(i32)->i32、immutable i32 fieldを持つstructを使用する。外部importなし。
state 0で入力を持つstructを作り、state 1でその値を読む。非線形処理のベンチマークではなく、候補を実装する前の適用条件の検証である。

|条件|受理|バイト数|出力確認|
|---|---|---:|---|
|通常local・非null・事前初期化なし|拒否|78|実行不可|
|通常local・nullable|受理|78|4,101件一致|
|通常local・非null・global sentinelで事前初期化|受理|94|4,101件一致|
|型付きループ・global sentinelを初期値にする|受理|96|4,101件一致|
|型付きループ・nullを初期値にする|拒否|84|実行不可|

global sentinelはモジュール初期化時に作る追加のstructで、実データと別物。実際の入力のstruct.newはどちらの方式でもstate 0内にある。
この対照では追加の割当が発生する。メモリ資源枯渇まで含む等価性や、全参照型でsentinelを生成できることは主張しない。
正常終了時の値だけを確認した。実行時間・解析耐性の優位性は測定も主張もしていない。

境界5入力とxorshift32 seed 0x753be291の4,096入力。参照結果は入力自体という独立した仕様。3方式合計12,303比較、不一致0。
Node v24.15.0 / V8 13.6.233.17-node.48。入力、生の検証エラー、各バイナリSHA-256とスクリプトSHA-256はartifactsに保存。

## 先行実装の照合

検索日2026-10-12。検索語:
- site:github.com/WebAssembly/binaryen "non-nullable locals" "fix"
- site:github.com/WebAssembly/binaryen "handleNonDefaultableLocals"

[Binaryen公式README](https://github.com/WebAssembly/binaryen/blob/main/README.md)のReference Types節を確認。非null localの構造的な初期化条件と、pass後にnullableへ変更するなどの修正を行う仕組みを記述している。main版の文書確認であり、version_133の修正コード本体を監査したという意味ではない。
前段で観測したBinaryen経由の修正を未知の難読化機構とは扱わない。
