# 正規化前処理時間の反復比較

2026-10-10。この前処理時間の比較では採掘Wasmを起動していない。

## 方法

6入力・4処理について、1回ウォームアップしてから各6回測定した。入力と処理の順序は測定ごとにずらした。168記録のうち144記録が測定対象である。

計時範囲には、入力の読み出し、作業用コピーの保存、逆アセンブル／規則適用／組み立てまたは最適化、出力の保存、WABTによる最終検証を含めた。SHA計算とログ保存は含めない。Pythonのプロセスは再利用し、外部ツールの起動時間は含めた。測定したのはアルゴリズム単体ではなく、実装した処理全体の時間である。

単位はms。表は中央値（最小値–最大値）を示す。この範囲は信頼区間ではない。

## 判断と限界

専用処理の中央値は120.1–781.1ms、局所最適化は36.6–171.7msで、今回の6入力では専用処理の方が時間を要した。単純な定数分割は既存最適化でも整理でき、専用処理の速度上の利点は確認できなかった。一部の生成標本が基準版と同じバイト列に戻ったことと、最適化によって他の命令が変わったことは別に評価する。バイト列が一致しただけでは、意味の保存や検知上の優位性は示せない。

測定条件は単一ホスト、6反復、ファイルキャッシュが温まった状態で、CPU affinityは設定していない。逆アセンブル、テキスト処理、組み立ての構成やプロセスを起動する箇所が処理ごとに異なるため、結果をアルゴリズム自体の優劣に一般化しない。旧記録にある規則適用だけの時間とも区別する。式解析時間は今回の比較に含めていない。正規化後のハッシュ出力・速度は別の実験であり、進捗と結果はdocs/countermeasure-runtime-plan.mdおよびdocs/countermeasure-experiment-report.mdを参照する。
