# 公開WebAssemblyクリプトジャッキング関連データセットの比較・分析

予備実験報告

調査基準日：2026-10-06。本稿の数値は固定した公開配布物と取得マニフェストに基づく。解析対象を実行せず、静的に処理した。

## 研究目的

複数の公開WebAssemblyデータセットを対象に、クリプトジャッキング関連ファイルの構造的な特徴を調べる。データセットの重複、ファイルの生成方法、解析失敗、比較対象の選び方によって、結果がどの程度変わるかを確認する。公開データセットを単純に連結してファイル数を求めず、取得したファイルの件数、異なるSHA-256の数、元プログラムの数を分けて報告する。

研究質問は次の4点である。

1. 公開配布物を固定・再取得したとき、配布フォルダ内のファイル数、重複を除いたバイナリの種類数、解析に成功した数はどの程度異なるか。
2. クリプトジャッキング関連のWasmMalでは、静的な難読化候補指標が参照群の選び方でどの程度変動するか。
3. 生成履歴を追えるCryptic Bytesでは、変換後のファイルをそのまま数える場合と元プログラムを均等に扱う場合で結論が変わるか。
4. 公開メタデータだけで経年トレンドを再構成できるか。

## データと方法

候補25件を一覧に記録し、公開バイナリを取得・検証できた18データセットを統合集計した。取得マニフェストは配布パス、配布物ハッシュ、各バイナリのSHA-256を保持する。完全一致はSHA-256で除き、同じバイナリが複数のデータセットに現れる場合は各データセット内の保存場所も残した。

WABT 1.0.42による検証と逆アセンブルに加え、セクション、関数本体、命令ヒストグラム、コード・データのエントロピー、ループ内br_table、名前情報・カスタムセクションなどを抽出した。検証失敗とセクション解析失敗を欠測として捨てず、それぞれ別の解析状態として集計した。

WasmMalの悪性ラベルを中心に、同じ関数本体が何個あるかも含めてJaccard類似度を求め、最も似た参照ファイルとの構造差を測定した。閾値5通り、同点の扱い、参照ファイルの追加によって結果がどの程度変わるかを調べた。Cryptic Bytesは元プログラム22本と各変換版のファイルを、版を固定したソースのファイル構成に対応付け、変換ごとの比較を元プログラム内で先に平均した。MineSweeperは54.9 GBの公開TARを展開せずストリーム走査した。

## 全体結果

全18データセットには109,846件のファイルがあり、109,844件でSHA-256を計算できた。全体の重複を除くと70,564種類である。解析成功は67,729、逆アセンブル失敗10、WABT検証失敗2,748、セクション解析失敗75、読み取り失敗2だった。したがって、取得したファイル数を、そのまま独立した事例の数や解析可能なファイル数として扱うことはできない。

データセット間の完全一致も多い。WasmBenchとWasmMalだけで7,531 SHAが共通し、WasmizerとWasmBenchは112 SHA、WasmizerとWasmMalは94 SHAが共通した。データセット単位の交差検証で同じバイナリが学習用と評価用の両方に入る可能性がある。

## WasmMalの結果

WasmMalで悪性とされたファイルの難読化候補の割合は、参照ファイルの選び方、類似度のしきい値、類似度が同点の場合の扱いによって15.74%から51.37%まで変動した。一つの固定しきい値から得た割合を「実世界の難読化率」と呼べない。

手作業で確認したカウンタ関連124種類のうち、121種類は想定したgetter/resetの構造に一致し、3種類は厳密な条件を満たさなかった。カウンタ挿入を受けた関数の静的命令増加は34.35%から34.47%の範囲だった。これは命令列の増加であり、実行時間や検知回避効果の測定ではない。

## Cryptic Bytesの結果

固定したリリースには、45,016件のファイル、異なるSHAが34,808種類、元プログラムが22本含まれた。内訳は採掘実装10、ゲーム6、ユーティリティ6である。wasm-mutateで生成したファイルが各版22,134件を占める。そのため、ファイルごとに単純平均すると、一つの生成方法の影響が極端に大きくなる。元プログラムごとに平均を求めてから、各プログラムを同じ重みで平均した結果も別に作成した。変換名は著者のディレクトリ名であり、名前だけから変換が実際に加えられたことや、処理内容が保たれたことを断定していない。

採掘実装10本を等しく重み付けした命令数の中央値比は、未最適化版でLLVM 1.089、Tigress 1.474、wasm-mutate 1.395、最適化版でそれぞれ1.060、1.401、1.350だった。未最適化版wasm-mutateのnop増分はカテゴリごとに元プログラムの値を平均すると47.7～49.2命令だったが、最適化版ではほぼ0だった。同じ変換名でも最適化段階により観測特徴が変わる。

## MineSweeperの全配布物監査

公開TARは54,914,109,440 bytesで、SHA-256はabbcf24643676556fda635c80813953d17175387f95bc80d1348c087efcabc6eである。アーカイブ内の572,485ファイルを順に調べ、349サイトのディレクトリから、Wasmの識別用バイト列を持つファイルを4,429件確認した。ただし、異なるSHA-256は36種類だけであった。最も多い1 SHAは、1,127箇所に現れた。

36種類すべてで本解析器のセクション解析が失敗し、WABTでも検証に失敗した。MineSweeper論文が報告するWasm利用サイト数と、本調査でTAR内に直接保存されたWasm本体の識別用バイト列を持つファイル数は同じ測定単位ではない。349を論文の1,735サイトの再現値として扱わない。

## 解析失敗の偏り

Wasmizer 8,915 SHAは全件試行済みで、6,221成功、2,694失敗だった。出典パスにtest、fixture、specを含む群の失敗率は40.76%、含まない群は0.30%だった。依存物を示すパスを含む群は53.21%、含まない群は1.39%だった。成功したファイルだけを集計すると、対象データセットの構成自体が変わる。

## 経年トレンドに関する結論

公開配布物はリリース日やデータセット全体の収集期間を持つ場合があるが、個々のSHAに対応する、実環境での観測日はほとんど得られない。MineSweeperには2018年3月のデータセットの収集期間がある一方、WasmizerとWasmBenchには同じようなファイルごとの観測日がない。このため、現時点の公開資料だけでクリプトジャッキング難読化の経年トレンドを推定することはできない。難読化の増減がなかったという結果ではない。時期による変化を再現可能な形で調べるためのメタデータが不足しているという結果である。

## 新規性と主張できる範囲

本予備実験の中心的な貢献は、複数の公開データセットの配布版を固定し、ファイル数、バイト列の完全一致、元プログラム、解析失敗を分けて扱った点にある。特に、MineSweeper全配布物の4,429件に対して異なるファイルが36種類だったこと、Wasmizerの解析失敗の偏り、条件によるWasmMalの判定の変化、Cryptic Bytesで特定の生成方法のファイルが多いことを同じ測定枠組みで示した。

本研究では、実環境の難読化率を確定したとはいえない。公開データセットから割合を推定するとき、結論を左右する要因を実測し、再現可能な数え方を示した。CSEC論文では、クリプトジャッキング関連の公開データセットについて、測定方法と結果の妥当性を確認する研究として位置付ける。

## 限界

悪性ラベルは各配布元の定義に依存する。採掘機能があるだけでは悪性と判断できない。静的な候補指標だけでは、処理内容が同じであること、実行時の動作、検知を回避する効果は証明できない。公開データだけを対象とし、現在活動中の非公開キャンペーンの代表性は保証できない。個別レビュー35件は研究者による監査であり、別の評価者による再判定は今後必要である。

## CSEC発表に向けた次の実験

投稿前には、35件の判断を独立評価者が再判定し、判断一致率と不一致理由を報告する。Wasm単体では判定できない配布・利用の意図については、取得可能な範囲で対応するJavaScriptとサイトでの利用状況を静的に照合する。また、元プログラムとの対応が確定しているCryptic Bytesを用い、今回観測した指標変化と既存検出器の判定変化を別の評価軸として比較する。これらを追加しても、公開日を観測日へ読み替えた経年トレンドは作らない。
