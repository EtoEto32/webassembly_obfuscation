# 埋め込みWasmの取得範囲

2026-10-06時点の取得・抽出結果を記録する。以下の件数は、すべてのWasmが検証に成功したことや、実行時に使われたことを確認した件数ではない。

## Wobfuscator

コミットを固定した6つのProjects配布物を対象に、リンクを除くすべての`.js/.mjs/.cjs`ファイルをAcorn 8.15.0で構文解析した。整数を直接並べた配列とbase64文字列から、Wasmの識別用バイト列を持つデータを抽出した。SHA-256と、元のJSファイルのハッシュ・行番号・UTF-16で数えた位置を保存している。取得したJSは、実行・import・evalしていない。

|配布物|JSファイル|構文解析失敗|埋め込み箇所数|異なるSHA-256の数|node_modules外の箇所数|
|---|---:|---:|---:|---:|---:|
|async|16,644|9|229|21|229|
|chalk|7,890|9|78|11|74|
|commander.js|8,162|13|38|6|36|
|debug|10,291|8|149|12|149|
|lodash|4,360|0|601|76|154|
|node-fetch|8,092|11|23|14|19|
|計|55,439|50|1,118|121（配布物間の重複を除く）|661|

数値配列から588箇所、base64文字列から530箇所を抽出した。単独のWasmファイルは53件・19種類で、埋め込みデータにも含まれていたものは18種類であった。両者を合わせて重複を除くと122種類になる。単独ファイルだけの調査では、103種類を取得できていなかった。

lodashは単独Wasmがないが、`.internal/Hash.js`等にbase64のWasmがある。拡張子検索や`WebAssembly`だけの文字列検索では不十分だった。

node_modules内の457箇所には、テスト用や機能の有無を確認するモジュールが含まれる可能性があるため、アプリケーション本体のコードと区別する。node_modulesの外にあることだけでは、変換済みであること、悪性であること、実行がその箇所に到達することは判断できない。

失敗した50ファイルも`data/catalog/*-js/js-coverage.jsonl`に残した。意図的な構文エラーテストや標準JS以外の構文等を含む。計算による復号、データの連結、動的生成、HTMLのscript要素などは、今回のようにソースへ直接記述された値を抽出する方法の対象外である。

`node scripts/extract_js_wasm.cjs`で再現できる。依存ライブラリは`.tools/js-parser`のAcorn 8.15.0である。テストには`node scripts/test_extract_js_wasm.cjs`を使う。

## AndroWasm

提供されたMD5と照合した配布ZIPを使い、その中のZIP/APK/JARを深さ5まで再帰的に読み取った。通常のファイルはすべて、先頭の識別用バイト列と拡張子を調べた。40,673ファイルを確認し、Wasmを24件・3種類取得した。取り込み失敗は0件であった。

最上位の検査ではWasmが見つからず、入れ子を調べる必要があった。APKをインストール・実行していない。ZIP内部の`Spyware:AndroidOS.GetFiles`は仮想パスとして記録し、その名前でWindowsへ展開しない。

ネイティブライブラリ内や独自形式の埋め込みデータを、すべて抽出したわけではない。著者が作成したAndroidのPoC（概念実証用プログラム）は、ブラウザから実際に収集したマルウェアの割合を求める際に合算しない。
