# 固定した条件合成器の生成例検査

2026-10-24。12説明例と実測由来11条件に合わせた不具合を見逃さないため、別の生成器で96 moduleを作る。seedは48879に固定する。前半はdrop/init/copy/fillを独立に選ぶ列、後半は共通trapで終了するAPIと、別のcopy/fill APIを含む。これは人工的なprofile内分布で、実アプリからのランダム標本ではない。

各moduleは1page memory、非空passive data 3個、1–3個の引数なしAPIを持つ。offsetは0–15、lengthは0–3。左右のsegment 0のみが異なり、segment 2は両方drop済みとする。各6memory（乱数、条件を満たすよう構成、測定基準）を用い、全API列を深さ4まで実行する。条件に違反したmemoryで反例が深さ4以内に見つからない場合は、失敗と断定せず到達上限として残し、生成器の固定点反復数と照合して追加計画を立てる。条件を満たすmemoryで差が出た場合は合成器の誤りとして扱う。

生成した条件はZ3の別arrayモデルでも検査する。元の解析器のhashを出力に保存し、結果に合わせたルール変更は別versionにする。反例件数は製品のbug件数ではない。
