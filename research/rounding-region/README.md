[実行前の設計・文献照合](plan.md)、[変換器](prototype.py)、[方式既知の復元器](recover.py)、[結果](../../results/invention-20261018/rounding-region-v3/summary.md)、[補正の検証費用と抽出費用の分離](../../results/invention-20261018/rounding-region-v3/adaptive-cost.json)。

## 差分を検査したアルゴリズム

対象は、1～128個のi32引数、1個のi32返り値とexportを持つ、純粋なadd/mul式のWasm。実際の入力バイナリをWABTで検証・逆アセンブルし、式を変換してWasmへ戻す。元プログラムの演算はmod 2^32で定義される。

各演算部分に、unsigned整数としての最大値Mと、同じ式をf64で評価した場合の絶対誤差上界Bを付ける。k≤30かつ2^(k−1)>Bを満たす間は演算を同じ領域に入れる。境界を超える場合は、大きい側の子の演算領域を閉じ、結果をi32へ戻してから続ける。これは最適分割を解く算法ではなく、具体的なgreedy規則である。

各領域は、f64近似Hと、正確なL=E mod 2^kの二経路で計算する。Lの式は元の構文をそのまま複製せず、係数をmod 2^kへ落とした多項式として生成する。最後にHを2^32で中心剰余Rへ落とし、`sign_extend_k(L-R)`で丸め誤差を補って返す。領域の詳細と疑似コードは[plan.md](plan.md)に記録した。

比較は未変換、各演算を別領域にする対照、領域融合の3方式。どれも公開関数は同じで、元/変換後にmemory・import・globalはない。融合率や補正幅を別発明として数えない。

## 先行研究と新規性の限界

浮動小数点と整数下位剰余を併用する正確な計算は既知である。Shoupの[Arithmetic Software Libraries](https://www.shoup.net/papers/akl-chapter.pdf)（2020年著者章草稿、§2/Fig.1を確認）にはLIPのaddmulpがある。FLOBはfloat計算を整数へ移す方向の既知難読化研究。本試作の差分候補は、Wasmの剰余意味を使った領域分割・補正幅選択・領域単位のコード生成であり、算術原理の発明ではない。

以前の[丸め残差による変数分割](../../tmp/rounding-residual-gate/README.md)は単一値の符号化と復元までだった。今回は複数演算を保持したまま計算し、整数の中間結果を領域末尾まで作らない。ただし、この拡張が既存の混合精度・modular arithmeticコンパイラ研究に対して独立した貢献になるかは未確定である。新しい呼称やWasmへの移植だけを差分にしない。

## 意味保存の説明

非負整数のadd/mulに限定する。二つの子の上界をMa,BaとMb,Bbとすると、丸め前の既存誤差は加算でBa+Bb、乗算でMa*Bb+Mb*Ba+Ba*Bb以下。さらに最大絶対値に対応する保守的な1 ulpを加える。整数演算結果が2^53以下なら追加誤差は0。各regionのM+Bは2^80未満に制限し、NaN・無限大を生じさせない。

Hは整数値のfloatであり、`H-nearest(H/2^32)*2^32`は[-2^31,2^31]内の正確な整数Rとなる。i64を経由してi32へ戻すため、正の端点2^31でもtrapしない。L-RはE-Hとmod 2^kで一致し、|E-H|≤B<2^(k−1)だから符号拡張で差を一意に回復できる。結果はE mod 2^32。領域境界の値をunsignedのi32と解釈し直しても、add/mulの剰余意味は合成して保存される。

これは対象範囲についての数学的説明で、パーサ・コード生成・最適化器・エンジンを含む機械検証済み証明ではない。浮動小数点入力、sub/div、bitwise、メモリ、ループ、呼出し、副作用、元からtrapし得る操作は入力として未対応。多項式展開は4,096項まで。任意Wasm変換器とは呼ばない。資源不足・時間・スタックtrace文字列の一致も意味保証に含めない。

## 正当性と誤り対照

5個の人工的な式（積、8項内積、定数係数を含む式、6段の多項式更新、12入力の二次式）×3方式×raw/O2/O3の45本を生成した。

- 45本と復元後45本の90条件、**404,388呼出しで不一致0**。独立のJS BigInt演算をoracleとし、境界値、bit位置、固定seedの4,096乱数列、同一instanceの反復呼出しを使った。
- WABT interpreterによる別エンジン検査は45本×4例、180呼出しで不一致0。
- 剰余幅を1へ壊した有効Wasmは、4,599入力で不一致。復元器の検証モードも誤差幅不足として拒否した。
- 幅を正しく保ち低経路だけに1を加えた有効Wasmを、剰余不整合として拒否した。これは復元器側の対照で、追加の実行入力数には加算しない。
- memory、float入力、division、loopの範囲外4対照を明示的に拒否した。

入力とログは[結果ディレクトリ](../../results/invention-20261018/rounding-region-v3/)に保存。全入力の同値性をテスト件数だけから主張しない。小式を現実的なIP保護のベンチマークとも扱わない。

## 適応的解析と実測

復元器は配布バイナリだけを読み、SSA状のlocal依存を展開する。補正パターンを認識し、そのHを計算するf64 add/mulをi32 add/mulへ読み替える。既定では誤差上界と低経路の多項式合同も検査する。元式・対応表・transform reportを渡さない。

## 判断と保存した失敗

領域融合のコスト低下と、方式既知の抽出費用増加は観測した。しかし抽出はこの例で0.017～0.148 ms程度、演算グラフを直接取り出せる。実用的な保護課題・既存方式との同負荷比較・独立した新規性は未確立であり、主方式には採用しない。この判断を、全ての浮動小数点難読化や全ての回復可能な方式の否定へ広げない。

最初のv1は出力WATの括弧が一つ多く、組立に失敗した。v2は全変換の実行が一致したが、元のchain6の最適化後に現れたi32.subを復元器が未対応として拒否した。i32.subのmod 2^32表現を追加してv3で45/45を処理した。失敗snapshotはv1/v2に保持し、この未対応を保護効果に数えない。v2の検査器が表示した90行のうち2行はmissingであり、成功90条件と報告しない。v3が本報告の主結果である。

## 再現

Python 3.9、Node、`.tools/wabt-1.0.42/bin`、`.tools/binaryen-version_133/bin`を使う。ツール配置は`WASM_TOOLS_ROOT`で変更可能。追加パッケージは不要。構文・外部ツールの共通処理は既存の`research/connectivity-elimination/prototype.py`を読み込む。

```powershell
.\research\rounding-region\reproduce.ps1 -OutputDirectory results/invention-20261018/rounding-region-fresh
python research/rounding-region/prototype.py input.wasm output.wasm --mode fused
python research/rounding-region/recover.py output.wasm recovered.wasm
```

一括再現には新しい出力先を指定する。既存ディレクトリは拒否する。公開・push・課金操作は行っていない。

一括再現を[別出力先](../../results/invention-20261018/rounding-region-replay-v1/)で実行し、45本と復元後45本、入力列のbyte一致を[audit.py](audit.py)で検査した。[監査結果](../../results/invention-20261018/rounding-region-audit.json)には各runの461ファイルのinventoryも保存した。計時値は同一性の対象にしない。再実行を新しい独立入力数に加算しない。
