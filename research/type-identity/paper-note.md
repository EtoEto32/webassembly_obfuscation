# Wasmの型同値性へ移した制御状態の回復

2026-10-19。研究草稿への否定結果の追補。主難読化方式の完成ではない。

## Abstract

WebAssemblyのrecursive type groupを利用し、有限状態機械の状態識別を整数から型identityへ移す仮説を検査した。空structの参照を状態として保持し、別の同値groupにある型へのref.testで遷移を選ぶ。group複製数と実行時に使わない兄弟型数を変えて、実Wasmの変換・正当性・適応的解除・費用を比較した。主42targetのGC系30条件はすべて整数状態機械へ回復できた。通常GC対照に対する追加の保護優位性は確認できず、主方式には不採用とした。

## Introduction / Related Work / Motivation

以前のメモリ表現案では、未変更の任意copyと両立する全域表現が位置共通のbyte写像へ制限された。そこで別の意味領域としてWasmの型同値性を検討した。ただし、rec group内位置によるidentityとgroupの正規化は既知の仕様である。クラス階層を変換する難読化も先行している。今回の差分仮説は、型を単に隠すのでなく、別group間の同値性に制御状態の選択を依存させる点だった。[文献表と確認範囲](prior-art.md)を参照。

## Threat Model / Proposed Method / Implementation

解析者は配布binaryと方式を知り、逆アセンブル、最適化、実行、コードの再構成ができる。元遷移表・seedを回復器に渡さない。目標は同じ公開APIを持つ通常の整数状態機械の回復費用を増やすこと。暗号学的秘匿性や全解析手段への耐性は求めない。

対象は1–16状態の2記号DFA。状態qをφ(q)というGC tokenへ変え、同じgroup定義・同じ位置の型の同値性により、step(φ(q),b)=φ(δ(q,b))を満たすようにする。globalの初期allocation以外に追加のallocationはない。実バイナリを入力する限定変換器と、型宣言を直接生成するbinary writerを実装した。詳細な疑似コードと意味保存条件は[algorithm.md](algorithm.md)に示す。

## Evaluation

3kernel×7方式×raw/O3の42targetと各回復版を、境界・全短語・乱数1,615入力で比較した。元プログラムも含め203,490関数呼出しで不一致0。追加12targetでは58,140呼出しが一致した。Binaryen interpreterによる公開API648照合と、全状態・記号/受理519照合、Nodeの同じ519照合も通った。42targetと42回復の再生成byte一致を確認した。

適応的解除は既存の型正規化を利用し、型identityを整数ラベルへ変換する。主GC系30/30をGC型・命令のないMVPへ戻せた。group系24条件の22は通常GC版を解除したbinaryと同一だった。残り2条件はallocationされない型のラベルが異なるが、実行比較に不一致はなかった。

126 fresh processの測定で、group数8・兄弟型32の通常GC比は実行約0.96–1.04、reader込み解析約0.90–1.05、後処理約1.09–1.25、サイズ約1.13–3.41だった。後処理の費用増は記録するが、metadataの増加を超える解析耐性としては支持が弱い。nullable localの初期値を誤る解除器の不備は別fixtureで検出・修正し、最終結果には修正版を使用した。

## Discussion / Limitations / Conclusion

型グループによる非局所的な宣言依存があっても、標準の型正規化がその依存を有限のラベルへ縮約できる。未使用の兄弟型を変更すると実行を壊せるという事実は、難読化解除への抵抗とは区別すべきである。

本実装はsyntheticな有限状態scannerに限られ、任意Wasmや実製品での評価ではない。GC資源枯渇は同値性の対象外で、一般のbinary同値性を機械証明したわけでもない。先行研究との差、新しい解析課題の増分、特許候補としての独自性は確立できなかった。この枝は不採用とし、標準readerが計算する同値類の大きさを保護強度と混同しないという知見を残す。
