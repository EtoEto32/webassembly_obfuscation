# トラップで不要計算を残す仮説の反証実験

2026-10-18。**新規難読化方式として不採用**。主研究の完了ではなく、設計前の一つの反証ゲートである。既知のopaque predicateの移植を「独立した3案」の一つに数えない。

## 仮説と意味

入力の最初のi32引数xに対し、関数先頭へ次を挿入する。

```wat
(drop (i32.load8_u
  (i32.add (i32.const 65535)
    (i32.and
      (i32.mul (local.get 0) (i32.add (local.get 0) (i32.const 1)))
      (i32.const 1)))))
```

R=Z/(2^32)上でx(x+1)は偶数なので、アドレスは65535である。少なくとも1ページの非共有memory32を持つ場合、このloadはtrapせず、値は破棄され、メモリを書き換えない。したがって後続の元計算の返り値・trap・メモリ副作用を保存する。時間、リソース不足、デバッガの命令位置、マイクロアーキテクチャの観測は保存対象ではない。バイナリ全体の機械検証済み証明ではない。

着想はWasmのtrapが最適化の除去条件に影響する点を使うものだが、恒等式自体は既知である。暗黙の範囲条件へ移すだけで解析課題が難化するかを反証した。保護対象の実計算と無関係なcarrierを残せても、元アルゴリズムを隠せたことにはならない。

## 実装と再現

`probe.cjs transform input.wasm output.wasm trap|pure|recover` は実際のバイナリをWABTで逆アセンブルし、構文木を変更して再アセンブル・検証する。対応はimportなし、非共有memory32が1個、最小1ページ以上。最初の引数がi32の関数へ挿入する。他の関数は保持する。WABTの生成WATのみを読む簡易パーサであり、任意の拡張仕様への対応は未検証。custom/debug sectionの保存も保証しない。

Node標準ライブラリのみ。WABT1.0.42、Binaryen133をリポジトリの`.tools`から利用する。別配置は`WASM_TOOLS_ROOT`で指定。既存出力を上書きしない。

```powershell
node research/trap-carrier/probe.cjs experiment results/invention-20261018/trap-carrier-reproduction
node research/trap-carrier/probe.cjs transform input.wasm output.wasm trap
```

## 条件・結果

ARX、符号付き除算、store後の可変位置loadの3プログラム。未変換、純粋な不要式、trap carrier、適応的解除の4条件×raw/O2/O3。36バイナリそれぞれ境界11入力とseed固定乱数4096入力、計147,852照合で不一致0。返り値、同一エンジンのtrapメッセージ、初期化した64KiB全メモリのSHA-256を比較した。メモリは直接byte比較ではなくハッシュ比較である。乱数でtrapになる入力も除外しない。

|プログラム|基準bytes raw/O2/O3|carrier bytes raw/O2/O3|最適化後のcarrier load|解除後bytes raw/O2/O3|
|---|---:|---:|---|---:|
|ARX|65/65/65|85/85/85|O2/O3とも1個|65/65/65|
|除算|59/59/59|79/79/79|O2/O3とも1個|59/59/59|
|メモリ|62/62/62|82/82/82|O2/O3とも1個|62/62/62|

純粋な不要式はrawで12bytes増え、O2/O3で消えた。trap carrierは20bytes増えて残った。しかし構文木で可換演算の左右を正規化し、偶奇恒等式を認識する解除器は9/9条件で1箇所ずつ除去した。解除器は元ソースや変換対応表を読まず、候補バイナリのみを読む。ただし方式既知の限定パターン認識であり汎用解除ではない。

負の対照として、アドレス65535+(x&1)のloadは除去数0、x=1でのtrapも保持された。任意のloadを消して成功数を増やしたわけではない。

性能はwarmup2000、9反復×20000呼出しのns/call生値を保存した。計測はJS境界を含む逐次順序で、CPU隔離・順序均衡・コンパイル監査がないため速度の優劣を結論しない。変換・解除時間も外部ツール起動を含む単発値。線形メモリは全条件65536bytes、プロセスpeak RSSは未測定。これらは本格的な性能評価の完了を意味しない。

実行環境：Node24.15.0、V8 13.6.233.17-node.48、Windows、Intel i9-11900K。別エンジンは未実行。
