# 2進刻みの差分評価と、有限環での回復

2026-10-22。これは検査して棄却した難読化候補であり、新しい一般的な差分法・補間法ではない。近接先行技術は[prior-art.md](prior-art.md)に記録する。

## 構成

R=Z/(2^32)で整数係数多項式Fを計算するWasmを対象とする。生成時に各i=0..31について`D_i(y)=F(y+2^i)-F(y)`を展開し、32個のhelperとしてprivate tableへ入れる。実行時はF自体を呼ばず、下位から入力のbitを加え、それに伴う出力差分だけを加算する。

```text
y = 0
acc = F(0)
for i = 0..31:
    h = 1 << i
    if x & h:
        acc = acc + D_i(y)     // modulo 2^32
        y = y + h             // modulo 2^32
return acc
```

各反復の前後で`acc=F(y)`。最後はy=xなので全i32入力でF(x)を返す。signed/unsignedの数値解釈はadd/mulの剰余結果に影響しない。i=32へ到達する前に終了するため、Wasmのshift countのmod32処理も誤用しない。table indexは常に0..31、型は統一され、追加のtrapやメモリ副作用を持たない。

修正版guardedでは`N_i(y)=rotl(y >>u i,(7i+3) mod32)*(0x9e3779b1+2i)`を加える。反復iの直前は0<=y<2^iなのでN_i(y)=0。従って正当性は保つが、helperを到達不能なyで評価すると単純な差分ではなくなる。これは同一案の修正であり、独立した新原理に加算しない。

## 適用範囲と実装

変換器は実`.wasm`を受け取り、純粋な`run(i32)->i32`が定型Horner式であることをAST全体の再生成照合で検査する。次数2..12、i32 add/mul、定数だけが対象。一般のC/C++、多変数、bitwise演算を含む元式、浮動小数点、load/store、import、任意loop、trapを持つ元計算は対象外。メモリは追加しない。debug/custom sectionの保持は保証しない。

Pythonが整数係数を生成し、WABTが組立・検証する。Binaryen O3の前後を評価する。補助的な高次数例は公開問い合わせ攻撃の適用範囲を検査するための別生成物であり、この変換器が次数100万の式を受け取れるという意味ではない。

## 初版の静的回復

解析者は方式と公開binaryを持ち、元の係数・ソース・manifestを持たない。目標は短く実行可能な等価関数を生成すること。元と同じ係数表やソース文字列を回復する必要はない。

初版はD_0(y)=F(y+1)-F(y)が公開される。d_k=Δ^(k-1)D_0(0)、k!=2^v u（uは奇数）とすると、falling factorial `(X)_k=X(X-1)...(X-k+1)` の係数候補は

```text
b_0 = F(0)
b_k = (d_k / 2^v) * inverse(u) mod 2^(32-v)
F_candidate(X) = Σ b_k (X)_k
```

となる。必要な割り切れ条件を確認してから2^vで整数除算する。元のb_kに関する上位v bitは失われるが、差分`2^(32-v)*(X)_k`はすべての整数で2^32の倍数なので、関数としての出力には影響しない。

回復器は全32 helperの差分と候補Fの差分を照合する。形式係数が一致しなくても、残差多項式のNewton前進差分が全て0なら整数上の零関数である。この検査とcanonical driverの照合を組み合わせる。有限個の無作為テストだけを全入力証明へ読み替えてはいないが、ツール実装全体が形式検証済みという意味でもない。

静的回復器は純粋な式・定型driver限定で、初期定数の抽出はF(0)が0/1/32でない場合に限定する。これらの制限を解析耐性に数えない。修正版のshr/rotlは意図的にこの解析範囲を外れる。

## 修正版への34問い合わせ回復

到達不能状態のhelperを読まなくても、公開runでF(0),...,F(33)を得れば十分である。根拠は既知の有限環多項式の構造であり、今回の新発見とはしない。

`(X)_34`はmonicで、整数xにおける値は34!で割り切れる。ν2(33!)=31、ν2(34!)=32なので、`(X)_34`はmod2^32で零関数。任意の整数係数Fをこのmonic多項式で割れば、同じ関数を表す次数33以下の余りが得られる。そのNewton表現の係数は上記と同じ方法で34値から求められる。

```text
samples = [run(0), ..., run(33)]
form forward-difference triangle modulo 2^32
for k = 0..33:
    check divisibility by 2^valuation(k!)
    divide by that power, invert only the odd part
    choose a coefficient modulo 2^(32-valuation(k!))
emit the resulting polynomial in Horner form
```

攻撃コードは元の係数、生成manifest、helperを解析しない。生成方式により一変数の整数係数多項式関数だと分かっている、というpromiseに依存する。34点が一致しただけでは、任意の未知関数がこのclassに属することは証明できない。そのため`x=0xdeadbeef`だけ値が変わる範囲外の対照で、34点に一致してもcloneが誤ることを再現した。

初版・修正版・元版の問い合わせtranscriptは例ごとに同一だった。生成器を知る解析者に対する追加問い合わせ費用はこの攻撃では生まれない。元の形式係数が一意でないことと、等価な関数の作成が難しいことは別である。

## 採否

初版の公開D_0を隠す修正は成立したが、保護対象の関数class全体に34点の等価回復がある。次数やoff-path noiseだけを増してもこの攻撃は変わらない。別原理を探す際には、この一変数多項式classに閉じる変換を独立した難化機構と数えない。多変数や非多項式関数を同じ理由で否定するものではない。
