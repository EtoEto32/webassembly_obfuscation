# 状態被覆の規則と正当性

元DFAを `(Q,{0,1},δ,q0,F)` とする。各qにk個の複製 `(q,h)` を作り、qと文字aごとに0..k−1の置換 `P[q,a]` を作る。全状態上の番号置換πで配置を混ぜる。

```text
for q in Q:
  for a in {0,1}: P[q,a] := seeded_random_permutation(k)
π := seeded_random_permutation(|Q|*k)
for q in Q, h in 0..k-1:
  z := π(q*k+h)
  T[z,a] := π(δ(q,a)*k + P[q,a](h))
  O[z] := [q in F]
initial := π(q0*k)
emit Wasm scanner with public memory 0 and private table memory 1
```

各表rowは12byteで、次状態0・次状態1・出力の3つのu32。ループは公開memoryの元と同じアドレスからbyteをloadし、下位bitで次状態を選ぶ。最後に出力欄を読む。コピー数を増やしてもループ命令列の大きさはほぼ一定だが、table/cache/メモリ使用量は増える。

生成時だけ使う射影ρを `ρ(π(q*k+h))=q` と定める。`ρ(initial)=q0`、`ρ(T[z,a])=δ(ρ(z),a)`、`O[z]=[ρ(z)∈F]` が成り立つ。語長に関する帰納法で出力一致を導ける。射影は配布バイナリへ付加しない。ただし遷移表自身は公開で、最小化や観測による商を求められる。

公開メモリのload順、i32の加算wrap、長さ0の処理は元と同じ。状態は常に表範囲内にあるため、追加loadはtrapしない。公開memoryへ書き込まない。第2memoryの確保が成功する環境、同じ公開memory内容、非共有の単一実行を前提とする。時間、コンパイル資源、instantiate時のOOM、trapの文言・命令位置は観測同値性に含めない。

## 解析者

方式・Wasmバイナリ・公開API・ツールを利用できる。隠れた鍵はなく、ソース・生成seed・ρは渡さない。目標は小さい等価DFAと実行可能なWasmの回復。任意のバイナリコピー、元の状態名の推測、私有tableそのものの抽出だけを成功判定にしない。

1. 全状態解析：到達状態を列挙し、出力と次状態のclassで分割を反復する。実装は単純な分割改良であり、Hopcroftの最適化された計算量を備えるとは主張しない。
2. 代表状態解析：短語31個とrandom継続語64個への出力列をfingerprintとし、同じ列の状態は代表1個だけ探索する。未試験の語で異なる状態を誤結合する可能性がある。元DFAを知らずに候補を作り、その後に実験管理者が同値性を検査する。
3. 公開I/O学習：L*の観測表を更新し、短語全列挙＋random語で反例を探す。バイナリの中身を解析せずinstantiateと `run` のみで問い合わせる。真の等価性oracleを持つL*の全言語保証を、この有限テスト実装へ転用しない。

## 改善を進めない理由

第2・第3の方法では、物理状態数ではなく元の観測可能な状態区別が主要な費用になる。全表を読んで同値性を証明する費用を、等価処理の候補を得るために常に必要な費用と混同してはいけない。より長い識別語を持つ元DFAなら学習が難しくなる可能性はあるが、それは元の問題の性質であり、複製規則の増分効果とは区別する。

今回の新しい実装作業は状態被覆・非export memoryのbackend・複数攻撃の比較である。状態分割という既知原理から独立した新規アルゴリズムとして認定しない。
