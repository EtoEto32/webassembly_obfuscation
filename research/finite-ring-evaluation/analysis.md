# 生成規則の提案と実装の保護効果を分ける

2026-10-21。対象・脅威モデルは[事前計画](plan.md)。元方式の有限環収束理論を新たに発明したという主張は行わない。現在の追加結果は、その具体的実装の方式既知解析である。

## なぜ回復できるか

元実装は各反復を、旧状態vからF(v)を別領域へ計算する段階と、残差を混合して次状態を求める段階に分けている。このため、語単位の循環した見た目を持つ更新全体から、元の非循環回路Fを読み分けられる。全SHAの他ラウンドにある通常T2を探す近道は不要だった。

実際のWasmから抽出する手順：

```text
検証したWasmを読み、単一helperの初期化・二段store・pointer swapを照合する
Fへの各store式を Z/(2^32) 上の多項式に正規化し、零項を除く
各式の依存が先行座標か入力bitであることを確認する
最大2変数の真理値表を全列挙してBoolean値になることを確認する
更新の係数を CV*v + CF*F として抽出する
CV + CF = I、CF mod 2 が下三角かつ対角1を確認する
抽出した依存と係数の2進付値から、必要な精度への到達上界を計算する
実際の反復上限が全scratch保存に十分なことを確認する
先行順にFのBoolean値を1回ずつ計算し、出力bitを構成する
状態保存版では、元の3領域にも全381値を書き、counterを増やす
```

入力はWasmのみ。解析器は既知の生成パターンを認識する限定実装であり、元の入力DAGやseedを読み込まない。多項式・残差係数・出力の詰め方が公開binaryに残ることを利用する。回復した出力回路は381座標のbit回路であり、69bytesの通常word式そのものを発見したわけではない。

精度q_iを下界として、F_iの精度は先行座標の最小q、入力だけの式は無限精度とする。次状態は各非零係数に対する`q_j+ν₂(CV_ij)`と`q(F_j)+ν₂(CF_ij)`の最小で下から評価する。多項式が合同を保存するため、これは十分条件となる。128回で現状態の全座標が32bitに達し、追加1回で旧状態とF領域も根に一致する。よって129回を状態保存版の十分上界とした。最小必要回数とは主張しない。

旧資料の構文深さ67と今回の正規化後の依存深さ66は異なる定義である。旧上界・新上界とも十分条件であり矛盾ではない。元バイナリの2144回は変更せず、別名のcertified版だけ129回に置き換えた。

## 対照・アブレーション

1. original：既存の2144回。通常O3だけでは反復が残る。
2. certified：読んだ式から導いた129回。反復回数の過大設定の寄与を切り分ける。
3. recovered-state：反復を除去し、返り値・counter・全memoryを再構築する。
4. recovered-io：同じ回路の返り値とcounter。scratch公開の費用を除いた対照。
5. plain：独立した通常word式。元方式や回復器の成功結果には数えない。

同じ観測契約での比較は1–3の間で行う。I/O版とplainはメモリを公開しないため、1–3と無条件に同値とは扱わない。既存方式のWASMixer等との性能優劣は今回測っていない。

## 正当性と検査器の限界

Nodeで局所256組・10版の2,560呼出し、状態あり6版の1,536状態記録（原型の参照保存を含む）、1,711,276,032byteの対象領域を検査した。6版を全SHAへ組み込み、同じ531入力で3,186回の全digest・全memory・counter・input/canary検査を実施。531個の新しい独立入力ではない。無効長4種類×6版の24trapではmemoryとcounterが不変だった。

負の対照では混合係数2→1の381箇所の変更、1回への反復削減を解析器が拒否し、実行も入力(0,0,0)で誤答を検出した。128回版は全scratch保存の証明条件が足りず拒否しただけで、実際に誤答するとは結論しない。trap前にstoreする変異体は実際にtrapしながらmemory変更を検出し、snapshotの修正を検査した。

WABTで1組×10版の出力を照合した。別engineでは全memoryや全531入力は試験していない。回復生成物6本を最終ソースから再生成し、保存版とbyte一致を確認。raw/O3から得られた回復版は互いにもbyte一致する。有限個の検査を全入力の機械証明と呼ばない。

## 費用と判定

[比較表](../../results/invention-20261021/finite-ring-report-v1/comparison.md)の原型/129回版は約16.54倍、原型/状態回復版は約3,243倍。元方式の実行コストが反復回数に支配される一方、専用解析器はその反復を実行せず元の依存計算を取り出せる。通常O3に残ることだけでは、この攻撃への耐性を意味しない。

回復本体約80–83msは同一process内11反復の中央値、reader約44–51msは1回。初見の分析者の時間、解析器を作る費用、汎用逆コンパイラとの比較は測っていない。性能は一つのhelper、単一Windowsホスト、Node/V8に限定。通常word式の約1nsは共通loopでの最適化を含み、全SHAやAPI呼出しの時間へ外挿しない。

**構成的提案としての採用は保持する。現在の実装の強い保護効果・実用優位は支持されない。** 新規性は同じ生成規則の先行公開の有無を問う別項目であり、安く回復できたことはその不存在を示さない。本評価で特許の可否や世界初を判定していない。

新しい方式として次へ進むなら、反復回数や混合係数を変えるだけでは今回の弱点は残る。公開binaryから元のFを独立した安い式として分離できる条件を変え、その変更のための実行費用と回復負担を比較する必要がある。この必要条件だけを新発明とは数えない。
