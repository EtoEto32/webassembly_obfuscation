# 分岐先を参照しない鍵更新：構造上の成立条件

2026-10-18。**新しい有効な難読化の完成ではない。** 状態遷移に基づく次候補を設計し、その制約を検査するコードを実装した。今回の制約ではWasmの通常の分岐合流にも対応できず、不採用。一般の状態付き難読化、WBLO、任意のWasm変換が不可能という結果ではない。

## 調べる具体的な規則

前の局所式・係数からの復元を避けるため、命令の解釈を実行履歴から得る鍵へ依存させる方向を考えた。ただし、この一般的な方向は既知である。検査対象を次の条件へ固定する。

- 有限グラフGの頂点uは元の制御状態。辺は実際に許す遷移である。
- 状態コードS(u)は頂点ごとに異なる。
- 状態uに到達したときの鍵は常にK(u)。履歴により複数の鍵を許す方式は含めない。
- 遷移u→vで、鍵は `K(v) = F(K(u), S(u))` によって更新する。Fは今回選んだ辺、分岐結果、追加の入力を受け取らない。
- 固定したkに対して `s → F(k,s)` は単射。XOR、rotate-XORだけでなく、状態引数に関して単射な非線形関数も含む。

仮説は「Wasmの構造化された領域を使えば、この条件のまま履歴由来の鍵を合流させ、制御状態の解釈を隠せる」だった。構造化という条件だけでは成立しない。保護効果を測る前に、意味保存が可能な構成かを検査する必要がある。

## 成立条件の導出

uの全後続vについて右辺は同じなので、同じ先行頂点を持つ頂点同士の鍵は等しい。この等値関係の推移閉包を≡とする。出次数が正のuについて、後続の≡類は一つに定まるのでT(u)と書く。

**判定条件**：異なるu,vについて `u≡v` かつ `T(u)=T(v)` となる組が存在すれば不可能。逆にそのような組がなければ、鍵の値域を少なくとも頂点数まで許し、Fを自由に選べる場合には構成できる。

必要性：K(u)=K(v)で、更新後の鍵も同じになる。状態引数に関する単射性はS(u)=S(v)を要求するが、コードの相違条件に反する。≡はどの適法な鍵割当てでも成立する等値性だけから作るので、別の鍵割当てで衝突を解消できない。

十分性：≡類へそれぞれ異なる鍵を付ける。同じ入口鍵を持つ頂点は、条件により異なる出口鍵へ移る。Fのその行にこれらの対応を設定し、未使用の状態コードと出口鍵を一対一に対応させれば、行を置換へ拡張できる。これは存在構成であり、Fが低コストで評価できる、あるいは解析しにくいことは示さない。固定したrotate-XOR等のFでは追加制約があり、この十分条件だけでは足りない。

判定は後続頂点のunion-findと `(入口類, 出口類)` の重複検査で行う。全体をSATへ渡さず、グラフサイズにほぼ線形の処理で衝突証明を得る。これは初等的な制約の整理であり、新定理や既存研究にない算法だとは主張しない。

### 分岐合流の例

```text
      B
    /   \
   A     D
    \   /
      C
```

Aからの二辺によりK(B)=K(C)。B,Cの後続はDで同じなので、単射性がS(B)=S(C)を要求する。したがって異なるB,Cを持つこの形は不可能。ループへ入れてもこの部分の衝突は残る。Wasmのif/elseと共通継続で普通に生じる形であり、非構造化CFGに特有の問題ではない。

## 実装した検証と結果

[check.py](check.py) は、グラフ判定・不可能性の衝突証明・可能な場合の全域F表を実装する。独立したoracleは鍵の全集合分割を列挙し、各辺に対して決定性と単射性を直接検査する。衝突証明もunion-findを再利用せず、別の到達探索で確認する。

[保存結果](../../results/invention-20261018/structured-key-consistency-v1/results.json)：

- 自己辺を含む1～3頂点の全有向グラフ530個。
- seedを固定した4～7頂点の512グラフ。
- 計1,042グラフでoracleとの不一致0、可能319、不可能723。
- 別枠の名前付き7例には、直線・単純環・異なる終端への分岐という可能例と、diamond・loop内diamond等の不可能例を含む。
- 単射性を外す対照と、選んだ辺を更新に渡す対照では、diamondに対する正しい鍵割当てが成立する。限定した不可能性を一般化し過ぎないための対照である。

これは有限グラフモデルの検証。Wasmバイナリの実行、性能比較、解析耐性、実在プログラムの到達可能性解析、WBLOの再現・攻撃は行っていない。1,042はプログラム実行数ではない。一般の場合の主張は上の論証に依存し、有限検査だけから推論していない。

## 設計判断

この規則をそのままWasmへ実装しない。非線形なFへの交換だけでは、状態引数に関する単射性を維持する限り上の反例を避けられない。状態複製・符号の衝突を許す拡張・辺に依存した更新は成立条件を変えるが、先行研究と比較すべき既知の修復方向である。修復しただけの方式を新候補に数えない。

次の案には、どの状態依存を新たに導入・消去するかの具体則と、修復部も含む方式既知の復元タスクが必要。全域F表の存在や、長い履歴・多数の鍵自体を解析耐性としない。この検査器の完成へ研究目標を縮小せず、新規性と有効性を持つWasm変換の設計・実装・評価は未完了として継続する。
