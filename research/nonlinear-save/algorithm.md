# 非線形メモリ表現のprefix修復と共有退避

2026-10-23。これは難読化の補助となる表現変換コンパイラの試作であり、独立した強い難読化方式の成立を示したものではない。彩色による保存情報の定式化も、以下の階層比較グラフの原理も先行研究と重なる。[先行研究](prior-art.md)を参照。

## 入力と観測範囲

実装は4個の0/1 byteだけを状態とする16状態のWasmを受け取る。`reset(s)`はsの下位4bitを設定し、`peek()`は4bit全体を返し、`run(f)`は定数のmemory.copy列を実行する。fがcopy番号ならその命令の宛先を65536とし、1pageの外へのアクセスとしてtrapする。それ以外のfでは全copyを実行する。重なりのあるcopyは元のsourceを使うmemmoveの意味を持つ。

メモリは非公開、固定1page、共有・import・growなし。入力バイナリをWABTで読み、生成し直した正規形のASTと完全比較する。任意Wasmへ適用するCLIではない。一般の4byte（32bit）状態、任意長のheap、外部からのメモリ参照、host callback、並行実行は対象外である。

観測は各APIの結果、正常終了かtrapか、trap後のpeekおよび再呼出しである。trapのプログラム位置・文面、時間、fuel、資源枯渇を一致させる仕様ではない。

## 定式化

状態集合X={0,...,15}、全単射E:X→X、j個のcopyの合成をP_jとする。入口の物理状態y=E(x)に対し、未修復の物理状態S_j(y)=P_j(y)、必要な表現T_j(y)=E(P_j(E^-1(y)))である。

入口で共通code c(y)だけを保存し、各jで現在値S_j(y)とc(y)からT_j(y)を得たい。この復元が可能である必要十分条件は、あるjでS_j(a)=S_j(b)かつT_j(a)≠T_j(b)となる全てのa,bについてc(a)≠c(b)となること。必要性は同一の復元器入力から異なる出力を選べないため、十分性は入力の組ごとの表が矛盾なく定義できるためである。

この衝突関係を辺とするグラフGの適正彩色がcとなる。最小の保存alphabetはχ(G)、固定長bit数はceil(log2 χ(G))。これは既知のfunctional index codingの特殊な入力である。実際のレジスタ、local数、コード長、実行時間の最小性ではない。

## 二つの情報損失の階層から最適彩色を生成

SとTはともに、時刻が進むと既に等しくなった状態が分離しない。末尾に全状態を一つにまとめる人工時刻K+1を加える。異なる二状態の最初の併合時刻をs(a,b),t(a,b)とすると、辺の条件はs<tである。

```
Color(V):
  if |V| = 1: return 1色とその頂点のclique
  hs = Sの下でV全体が初めて等しくなる時刻
  ht = Tの下でV全体が初めて等しくなる時刻
  if hs >= ht:
    VをS[hs-1]の値で分割し、各部分を再帰処理
    色番号を再利用する               # disjoint union
    最大の子cliqueを返す
  else:
    VをT[ht-1]の値で分割し、各部分を再帰処理
    子ごとに別の色番号を割り当てる   # complete join
    全ての子cliqueを結合して返す
```

前者では異なる部分間のs=hsかつt≤htなので辺がない。後者ではt=htかつs≤hsなので全ての交差辺がある。hsとhtの定義から分割は必ず二つ以上になり、再帰は停止する。unionで色数と最大clique数は子の最大、joinでは両方とも子の和なので、生成色数とclique下界は常に一致する。従って適正彩色の最小性を証明できる。実装はさらに全辺とcliqueを列挙して証明書を検査する。

これはcographのunion/join分解であり、LDT graphの既知性を覆す新定理とは主張しない。モデル生成は全2^n状態を列挙する。nに対する多項式時間アルゴリズムではない。

## Wasmへの変換と意味保存

入口でc(y)をlocalへ保存し、物理メモリに元と同じcopy列を実行する。j番目で失敗する場合は、その直前にR_j(S_j(y),c(y))=T_j(y)で修復してから、必ず範囲外となるcopyを実行する。失敗したcopy自身には書込みがない。全copy成功時にはR_Kで修復する。j=0では既にT_0(y)=yなので修復不要である。

resetはE、peekはE^-1を通る。正常時・trap時とも呼出し境界でE(論理状態)が成立するので、帰納的に次のAPI呼出しも同じ関係を保つ。内部の表領域と状態領域は互いに素であり、全ての表アクセスは有効範囲内にある。これが限定profileについての構成上の説明であり、テスト通過を任意のWasmの形式検証と読み替えない。

比較対象fullは入口4bit全体、linearはGF(2)^4の全67部分空間を探索した最良の線形code、colorは上記の非線形codeである。線形codeのkernelが衝突差分a XOR bを含まないことが必要十分であり、最大kernelから最小rankを得る。出力codeが実際にXOR線形であることも検査する。三方式は同じlookup emitterを使う。full専用の最適な手書き実装との比較ではない。

## 解除と失敗条件

攻撃者は方式と4bitの公開profileを知り、任意にreset/run/peekできる。全16状態と各失敗番号の遷移を観測すれば、表で実装した同等プログラムを生成できる。元のEやcopy列を攻撃に渡す必要はない。実装した回復器は2copyで150 API呼出し、3copyで200 API呼出しを要した。

これは同等動作の回復であり、元ソースの一意な回復ではない。未知の隠れ状態がある一般モジュールまで有限観測から同値と認定しない。保護の有効性は支持されず、表の縮小効果だけが残る。
