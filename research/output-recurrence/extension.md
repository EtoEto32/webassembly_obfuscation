# 次の修正案を選ぶための補題と反例

「yの更新へ二乗・三乗を足す」だけでは、今回の失敗は解消しない。

M=2^W、b=g*h、g=gcd(b,M)、hは奇数とする。b≠0ならw=b*yから

```
y_bar = (w/g) * inverse(h, M/g) mod (M/g)
```

を得る。w/gは通常の整数除算で割り切れる。y_barは元のyではなく、その合同類の代表である。係数が入力や公開状態に依存してよい任意の多項式Fについて、F(y)-F(y_bar)はy-y_barで割り切れるため、`b*F(y)=b*F(y_bar) mod M` が成り立つ。したがって、yの次数を増やしてもwの更新は代表から計算できる。b=0はw=0で閉じる。

この説明は高次多項式が常に安く評価できるという主張ではない。元と同じFを使うなら、その評価の前に低bitの代表を選ぶだけで済み、元の多数のy候補を列挙する必要がない、という限定した事実である。

一方、この性質を任意のWasm命令へ広げてはいけない。b=2^r、delta=2^(32-r)、y=0とy=deltaは同じw=0を持つが、yをrotr(32-r)すると、それぞれ0と1になり、次のwは0とbで異なる。捨てたbitが観測可能な位置へ移るためである。

`extension.py`は幅1..8の全b/yと32bitランダム多項式を検査し、さらに実Wasmのrotateでr=1..31の反例を実行する。この反例は新しい難読化方式ではなく、次の設計で必要な条件を限定するためのもの。rotateを加えれば直ちに保護できるという主張もしない。履歴から全状態が安く戻る別の攻撃を検討する必要がある。
