# 再帰frame混合の構成と成立範囲

## 入力と変換

R=Z/(2^32)、v=(x,y)とする。対象の元計算は

```text
F(0,v) = B(v)
F(n,v) = Q_n(F(n-1,P_n(v)))   (n>0)
```

である。試作のPはrotate/add/xorのFeistel型更新、Qは加算とxor、Bも加算とxor。全てtotalな剰余整数演算である。公開runはn&31をFへ渡し、2語をi64へpackする。

行列M=[[a,b],[c,d]]の条件をad-bc=1とする。逆行列は[[d,-b],[-c,a]]で、除算は不要。混合値z=Mvを保つ。動的版は各callでk=z0 xor rotl(z1,n)、l=z1+nを作り、次を計算する。

```text
a1 = a + k*c           b1 = b + k*d
c1 = c + l*a1          d1 = d + l*b1
N = [[a1,b1],[c1,d1]] = L(l) U(k) M

F_encoded(n,z,M):
    v = M^-1 z                         # 実装では各使用箇所へ式を埋め込む
    if n == 0: return M B(v)
    choose k,l from current n,z
    N = L(l) U(k) M
    w = F_encoded(n-1, N P_n(v), N)
    return M Q_n(N^-1 w)
```

親Mの各wordは関数引数としてWasm frameに残る。主結果v2のrootのMは、固定版・動的版とも[[1,3],[5,16]]。固定版は全子でN=M。rootは入力をMで混合し、返値をM^-1で戻す。初回v1は動的版だけIだったため、動的更新を外した比較として条件をそろえて再実験した。秘密鍵、外部秘密、暗号学的仮定はない。

## 意味保存の論証

UとLの行列式は1なので、全k,lについてdet N=det M=1。整数のoverflowはWasmの剰余演算に含まれ、この環上の恒等式を壊さない。n=0でF_encoded(0,Mv,M)=M B(v)。n-1の主張を仮定すると、子の返値はN F(n-1,P_n(v))。N^-1を適用しQを計算してMを掛けるので、F_encoded(n,Mv,M)=M F(n,v)となる。これはnに関する通常の帰納法で、k,lが入力に依存していても成立する。

対象にはload/store、import、除算、float、例外、共有状態がない。期待する通常trapはない。有限Wasmスタック・燃料・実行時間・資源枯渇は同値性契約に含めない。公開の最大再帰深さは31である。任意のWasmモジュールや実装全体を機械証明した結果ではない。

## 適応的回復

回復器はバイナリだけを読み、workerとwrapperの型、閉じたmodule、base条件、減少する唯一の自己callを検査する。元の係数やsource/seed/manifestは入力にしない。

1. workerの混合入力へM(x,y)という記号値を代入する。
2. i32加減乗算を剰余多項式にし、adを1+bcへ書き換える。xor/rotate等は簡約済み引数を持つtotalな不透明演算として扱う。
3. 子callの行列Nについてdet N=1を確認する。子へ渡す値をN^-1で記号的に戻し、子の返値をN F(n-1,u)という2つの記号値に置く。
4. 親返値をM^-1で戻し、base・子の論理入力・post処理からa,b,c,dが全て消えることを確かめる。
5. wrapperの深さ制限と混合/復元も検査し、混合を持たない1つの再帰関数を生成する。自己callは1回だけ出力し、2つの返値射影が同じi64 temporaryを共有する。

baseでの再帰、非減少call、子det不成立、rootの出力変更、memoryを含むmoduleは拒否する。この検査は既知の行列形式と限定命令profileに依存し、任意の難読化やWasmへの一般的な同値性判定器ではない。多項式簡約は恒等式の適用であり、全入力の列挙やstack展開を行わない。

## 失敗の原因

履歴に応じてMが変わっても、現在のMを4語で明示的に持ち運んでいる。その4語が、表現変換に必要な全履歴の要約になっていた。拡張状態(v,M)から(Mv,M)への固定した可逆変換としても記述できる。従って「異なる履歴から異なるMになる」という性質だけでは、解析者が履歴全体を追う必要性を作れない。

動的Mの種類数や再帰深さを増やすだけでは、この反証を変えない。他の再帰難読化全てが弱いという定理でもない。次の候補は、行列や呼出しの種類を増やす前に、同じパラメータ付き要約で消えるかを検査する。
