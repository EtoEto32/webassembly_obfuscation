# 更新操作に閉じた状態商の検査

2026-10-23、実験前の計画。独立した発明と確認できていない仮説である。

対象は非公開の i32 配列、差の照会、加算、相対コピー、定数 k 倍の更新を公開APIとする状態機械。暗号鍵や秘密の実行環境は使わない。前の readonly memory-quotient から、任意長の更新列に対する閉性を検査する段階へ進む。これを原理の異なる新発明の一件とはまだ数えない。

R=Z/(2^32)、n>=2。全要素への共通加算 c を忘れたい。query(i,j)=x_i-x_j は c に不変。add(i,t)、copy(i,j,t) は共通加算と可換だが、scale(i,t): x_i=k*x_i+t は、未変更要素との差を (k-1)c だけ変える。従って d=min(32,nu_2(k-1)) として c が 2^(32-d) の倍数なら閉じる。この共通加算族に限って最大 d bit を捨てられる。任意の状態圧縮の最大量とは主張しない。

二つの実装を比較する。canonical は x0 の下位32-d bitと x_i-x0 を保持し、anchor更新時に全差を更新する。representative は初期データから x0 の上位d bitに対応する共通加算を引くだけで、元の更新コードをそのまま実行する。後者が正しければ、情報消去のために実行時の難しい表現維持が必要という仮説への反証にもなる。

実験を始める前に、保護タスクは「元の絶対初期状態の一意同定」と「短い等価な状態機械の回復」を分ける。後者を安価に回復できるなら、新しい有力な難読化方式としては採用しない。k=0 の定数代入対照は d=0、k=1 は d=32、k=257 は d=8。サイズ4/32/256を用い、設定違いを実アプリ数とは数えない。

境界・乱数・連続呼出し・trap後の継続・raw/O3・WABTを検査する。過剰な消去、偽のschema、不正更新コードを拒否する。実行は共通Wasm loop、fresh Node 3process、warmup 16,384、校正20ms、7batch。実行時間・bytes・linear memory・process RSS・変換時間を記録する。実験の成功を全バイナリの形式証明や特許性の証明とはしない。
