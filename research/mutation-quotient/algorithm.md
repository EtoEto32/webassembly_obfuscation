# 更新列全体に対する情報消去条件

2026-10-23。R=Z/(2^w)、w>=2、配列長 n>=2。状態 x∈R^n に対し公開操作は、query(i,j)=x_i-x_j、add(i,t)、copy(i,j,t):x_i=x_j+t、scale(i,t):x_i=k*x_i+t。更新は更新後の query(i,j) を返す。固定した初期状態への reset もある。無効なopcode・indexは書込み前にtrapする。

## 観測同値性の正確な分類

二状態 x,y が任意の同じ操作列に対して同じ応答を返す必要十分条件は、

```
y = x + c·(1,...,1),   (k-1)c = 0 mod 2^w.
```

必要性：全ての query(i,0) が等しければ、全座標の差 y_i-x_i は共通の c である。次に scale(0,0) を実行し、未変更の座標1との差を見ると、応答差は (k-1)c となる。

十分性：queryは共通加算に不変である。addとcopyは共通加算を保ち、scaleも kc=c の条件で同じ c を保つ。従って操作列に対する帰納法が使える。resetを持つ二つの配布プログラムを比較する場合、両初期状態にもこの関係を要求する。trap判定は公開引数だけによるため、無効な操作の応答と書込みなしも保存する。

d=min(w,nu_2(k-1))、nu_2(0)=w と置くと、許容される c は 2^(w-d) の倍数で、ちょうど2^d個。各観測同値類の大きさも2^dであり、異なる挙動を持つ状態数は2^(wn-d)。これはこのAPIと全R^n状態族の情報量であって、暗号強度や攻撃費用ではない。入力の追加制限、既知データ、別の観測APIがあれば結論も変わる。

事前計画では「共通加算族に限った最大消去量」とした。queryから必ず共通加算へ絞れる上の必要性を追加したことで、このAPI全体の観測同値類も分類できた。これは実験後に整理した論証であり、新しい一般的な商理論の発明とは主張しない。

## 二つの実装

canonical は a=x0 mod2^(w-d)、q_i=x_i-x0 (i>0) を格納する。代表状態 r0=a、r_i=a+q_i から元の1更新を行い、再び a,q を取る。i!=0なら1セルを書き換える。i=0なら全 q_i を q_i+a-r0' に更新し、a'=r0' mod2^(w-d) とする。元状態への秘密の復号器はない。

representative は初期データから h=x0-a を全要素に共通して引く。その後は元と同じ更新コードを実行する。毎回のcanonical化は不要である。閉性により、どの代表でも同じ応答列を返す。raw版のrun本体はplainと同じ構文で、resetの定数とdataだけが変わる。この低費用の同等実装が存在するため、複雑なcanonical維持を保護効果とみなせない。

## 公開I/Oだけによる回復

公開schema n,k と配布Wasmだけを与え、生成seed・元初期値・manifestを攻撃器へ渡さない。

```
reset()
for i=1,...,n-1: q[i] = query(i,0)
z = scale(0,0) の戻り値（座標1との差）
b = z + q[1]                         // (k-1)*x0 mod2^w
if d=w: a=0
else:
  u=(k-1)/2^d mod2^(w-d)              // odd, hence invertible
  a=(b/2^d)*inverse(u) mod2^(w-d)
return ordinary_state_machine([a,a+q[1],...,a+q[n-1]],k)
```

reset 1回、値を返す問い合わせ n 回。攻撃の関数へ元の初期値を渡さず、戻った代表状態の採点だけに正解を使う。公開APIを操作できない環境へそのまま一般化しない。これはブラックボックスの任意Wasm解析でもない。

## Wasm契約

実装は単一の固定1ページの非公開memory32、run(i32,i32,i32,i32)->i32 とreset()、2<=n<=1024、上記の完全な生成テンプレートだけを扱う。schemaは公開形式識別子であり信頼しない。実際の全モジュールを同じschemaから再構成し、rawまたはBinaryen133 O3の構文と一致することを検査する。任意C/Rust出力の自動抽出には未対応。custom section/debug情報、実行時間、資源枯渇時の挙動は同値契約外。

公開memory、imports、追加export、任意の操作追加は拒否する。内部メモリを同じbyte列に保つ必要はないが、API応答とtrap後の状態関係は保つ。診断版だけmemoryをexportし、実行中の関係を独立JSモデルと照合した。診断exportを本番仕様の一部とは扱わない。
