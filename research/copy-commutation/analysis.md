# 実測の解釈と次の判断

2026-10-19。仮説は「全域の表現を変えつつ任意byte copyを無補正で残すと、複数byteの混合は不可能」であった。紙上証明、小モデルの全列挙、実Wasmの反例が同じ境界を示した。これは難読化耐性の上昇を測ったものではない。

## rawとO3の比較

各欄は1 targetにつき242 copy条件のうち、物理メモリが期待した符号化状態から外れた条件数。seedは初期メモリの生成seedであり、242入力は全targetで共通である。

| source | mode | seed7 raw/O3 | seed19 raw/O3 | 判断 |
|---|---|---:|---:|---|
| align1 | plain | 0 / 0 | 0 / 0 | 正の対照 |
| align1 | uniform | 0 / 0 | 0 / 0 | 共通byte置換は成立 |
| align1 | position | 90 / 90 | 90 / 90 | 位置が変わると復号条件が変わる |
| align1 | coupled | 90 / 90 | 91 / 91 | 部分pairのcopyが表現関係を壊す |
| align2 | plain | 0 / 0 | 0 / 0 | 別sourceの正の対照 |
| align2 | uniform | 0 / 0 | 0 / 0 | 成立 |
| align2 | position | 70 / 70 | 70 / 70 | 2byte境界でも位置依存回転は一致しない |
| align2 | coupled | 0 / 0 | 0 / 0 | 同一pair置換として成立 |

全targetでcopyのtrap判定不一致は0。各242条件中、align1は108、align2は90条件がcopyでtrapする。値の比較は各copy後の10アドレスを元・変換後・観測用の3instanceで実施。メモリ比較は観測用instanceの全65,536byteを、JSで計算した `E(copy(initial))` と照合する。変換のPython実装と検査のJS実装は別記述だが、同じ設計上の誤りを共有し得るため、紙上証明および負の対照も併用した。

O3の前後で誤変換の分類は変わらなかった。これは保護機構の最適化耐性の証拠ではなく、誤変換が最適化で正しい変換へ戻らないという結果にすぎない。`wasm2wat`、validator、最適化器、実行器はv2で32targetを処理した。最初のv1は機能フラグ不足による設定エラーとして別保存し、攻撃のtimeoutや耐性に数えない。NotDec等の逆コンパイラの攻撃実験は行っていない。

## 攻撃モデルと主張の限界

将来の保護目標は、方式と変換binaryを知る解析者によるデータ構造・意味的なfield accessの回復費用を増やすこと。今回のAPIは任意byteをreadできる正当性fixtureなので、保護された秘密の回復困難性は評価できない。uniformもpair交換も逆写像はコードから直接得られる。これらの復号の存在だけを「難読化の失敗」とはしないが、既存方式より高い解析費用が出たという測定もない。

サイズと変換所要時間はmanifestに記録した。ただしprofile生成・外部ツール起動を含む1回の観測で、性能比較として統計処理していない。ランタイム、プロセス使用メモリ、同等コスト比較も今回は測っていない。正当性gateで棄却する一般案について、これを有効性評価の完了にすり替えない。

## 何を更新したか

1. 「globalなメモリ混合と任意bulk copyを、そのまま同時に保つ」という無制約案を除外できるようにした。単なる線形方式の失敗に限定されない。
2. 整列blockだけなら混合できることを正例で確認し、byte copyへの過剰一般化を反例で検出した。source側の整列という前提を勝手に追加しない。
3. 一方向copyだけなら依存する2セル写像が残ることを有限全列挙で確認した。任意copyの定理を全メモリ難読化へ拡大しない。
4. 次の案はcopyの実際の操作集合・到達状態の制限、補助状態、またはcopy更新則そのものの変換のどれを利用するかを明示する必要がある。その後、公開復号からの機械的回復を試し、追加の保護効果を測る。

既存の[差分境界修復案](../difference-boundary/README.md)はcopyを補正するため本補題の外側にある。ただし、そこで累積XORによる簡単な回復が可能だった事実は残る。補題の外へ出るだけでは新規性や解析耐性を得たことにならない。

査読上の最大の弱点は、初等的な可換条件の特殊化とtoy fixtureの正当性検査に留まり、新しい保護方式・実用プログラムでの解析費用増がないこと。特許を目指す主案にも現時点では採用しない。否定結果と制限付き正例を次の設計の判断材料として保存する。
