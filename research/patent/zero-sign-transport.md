# 零符号の遅延修復：技術差分と効果の候補

2026-10-21。[具体規則](../zero-sign-transport/algorithm.md)、[先行技術](../zero-sign-transport/prior-art.md)、[実測の解釈](../zero-sign-transport/analysis.md)。法的な特許性の判断や出願書類ではなく、研究上の発明候補の記録である。

| 項目 | 本候補で確認した内容 |
|---|---|
| 近い既存技術 | 符号反転を含む式置換、零符号を無視する最適化、FP難読化。符号操作自体は新規としない |
| 具体的な課題 | 零符号を観測するAPIでは符号式置換をそのまま使えず、各nodeの補正は実行費用を増やす |
| 原因 | 相殺や零の組合せで、数値として等しくても結果bitの符号が異なる |
| 変更規則 | 元のf32丸めを残して符号表現で数値graphを実行し、零rootでのみ別の論理符号graphを評価する |
| 正しさの条件 | add/sub/mulのみ、途中の符号観測なし、既存のcanonical NaN bit API。一般Wasm全体への適用ではない |
| 測れた効果 | 自作の各node補正対照より通常値3例で約36–66%時間減。全零分布では一部悪化 |
| 保護の限界 | 数値graphを公開binaryから抽出でき、零時だけ元コードを残す部分簡約は通常値で未変換の約0.99–1.12倍の時間 |
| 残る調査 | 同じ遅延修復・符号伝播手順の先行公開、既存FP難読化のソース比較、実アプリケーションでの便益 |

「難読化が解除できるから発明ではない」と判定しない。保護そのものの優位は弱いが、既存の課題を補正費用の面から改善する具体手順は残る。一方、自作対照との改善だけで既存技術全体を超えたとは扱わない。主特許候補への採用は保留し、構成の差と費用改善を部品として保存する。
