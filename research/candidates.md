## A：非単射な関係を有限回の反復で実行する

**課題**：通常の可逆な変数符号化では、復号境界や逆写像を追うと元の計算へ戻せる。逆写像全体を持たない関係から、必要な出力だけを計算できないか。

**規則**：R=Z/(2^32)、純粋な2出力多項式f(x),g(x)。未知の出力z,tに対しa=z-f、b=t-gと置き、Q=(a+a(a+1)b,b+b(b+1)a)を構成する。Qを展開した式を実行コードへ埋め込み、(z,t)←(z,t)-Q(z,t)を同時更新で6回実行する。f,gを最初に評価して渡す実装とは区別する。

```
Q := expand(z-f + (z-f)(z-f+1)(t-g),
            t-g + (t-g)(t-g+1)(z-f)) modulo 2^32
z,t := arbitrary initial words
repeat 6 times:
    nz := z-Q.first(z,t,x)
    nt := t-Q.second(z,t,x)
    z,t := nz,nt
return z,t
```

**意味**：更新残差は(-a(a+1)b,-b(b+1)a)。初回で偶数になり、以後2進付値の下界が倍増するので6回で32bitの零残差となる。i32剰余演算を直接使えるが、他の固定幅形式にも適用でき、Wasm専用性は弱い。副作用、trap、任意の関数呼出しにはこの証明を拡張しない。

**解析タスク**：公開された反復コードから、元の2出力関係を復元する。内部値・式・任意入力の観測を許す。仮説上は逆関数がないため単純な復号境界を作らない。費用は多項式展開と6反復、コードサイズ増加。

**既存研究との差と反証**：[Implicit White-Box Implementations](https://crypto.iacr.org/2022/papers/530630_1_En_2_Chapter_OnlinePDF.pdf)は直接の比較先。全領域でQが非単射という差はあるが、保存済み解析では初回後の偶数残差を正規化した関係が零固定置換へ還元された。さらにQ1のz²t⁰係数は-g、Q2のz⁰t²係数は-fであり、係数射影で出力関係が露出する。Newton/Hensel型の既存反復とも比較が必要。

**最大のReject理由**：主張した非単射性が実際に計算する到達領域では有効な差にならず、式の係数から元関係も回復できる。

**状態**：既存の専用Wasm実装・補題・反証を再利用する設計資料。今回再実行した結果ではない。`tmp/nonbijective-wasm-review/`、`tmp/nonbijective-coefficient-recovery/`参照。新しい独立した差を示さない限り追加実装は行わない。

## B：局所真理値表を符号化テンソルへ移す

**課題**：命令単位の式認識を避け、演算の種類を局所的な係数から読めなくする。

**規則**：Boolean回路の各wireに奇数行列式の2×2行列Mを割り当て、bit bをM e_bで表す。gateの真理値tensor Tに対しU=M_out T(M_left^-1⊗M_right^-1)を生成する。実行時にはUの双線形評価だけを行い、中間のbitを復号しない。

```
lower pure word circuit to bit DAG
for each wire v: choose invertible M[v] over Z/(2^32)
for each gate c=f(a,b):
    U[c] := M[c] * truth_tensor(f) * (inverse(M[a]) tensor inverse(M[b]))
    emit bilinear evaluation U[c](encoded_a, encoded_b)
emit public input encoders and output decoders
```

**意味**：隣接するM^-1Mが打ち消され、gateごとの可換条件とDAG上の帰納法で出力が保存される。Wasmのi32乗加算へ直接落とせるがWasm固有ではない。全プログラムのmemory/trapの扱いは別問題。

**解析タスク**：基底行列や元gate名を与えず、公開係数と依存辺から同じ入出力を持つBoolean回路を再構築する。費用はbit分解と各gateの双線形演算で大きい。仮説は、密な係数と内部基底の不明性がgate識別を妨げることだった。

**既存研究との差と反証**：基底変換や白箱符号化そのものは既知。今回は具体的なtensor構成を検討したが、各wireの可能な値は高々2個なので公開入力からsupportを伝播し、4組の入力評価でgateを回復できた。奇数倍率で具体値を増やす修正もmod2射影で元の小回路へ戻る。これを別案として数えない。

**最大のReject理由**：係数の見た目が密でも意味上の小さい支持集合を隠しておらず、既存の符号化から独立した難化機構もない。

**状態**：`experiments/tensor-support-gate/`、`experiments/tensor-quotient-gate/`に実装と負の結果。現在のWasm全体からの自動抽出結果ではない。今回の採用対象外。

## C：観測文脈を保持するWasm式再合成

**課題**：通常の同値式探索は出力が同じ候補を1代表へまとめる。しかし等しい出力でも、途中で現れる関数が違えば、後続処理と合わせた復元の費用は違い得る。出力同値性だけで候補を捨てる選択を改め、実際の保護対象を隠す式を探す。

**構成の核**：同じ出力関数の候補群を、観測される中間関数の集合包含とコストで非支配集合として保持する。入力・最終出力・定数も解析者に与えたうえで、元プログラムの事前固定した内部計算の復元費用を直接採点する。探索用の包含判定と、保護効果の採点を区別する。

```
extract a pure i32 expression region from a validated wasm binary
freeze source targets before generating alternatives
generate equivalent expressions under a fixed cost/resource budget
for each P:
    V[P] := exact modular polynomial of its output
    O[P] := exact modular polynomials of its observable intermediate expressions
    retain P unless some Q has V[Q]=V[P], cost(Q)<=cost(P), O[Q] subset O[P]
rank retained candidates by recovery of the frozen targets, not by |O|
emit candidates; optimize; re-extract and re-score actual optimized wasm
accept only if correctness and stronger adaptive analyses also pass the stated gates
```

**意味**：最初はpure i32 add/sub/mulに限定し、形式多項式をmod2^32で正規化して出力一致を確認する。形式多項式が違っても有限環上で等しい場合があるので、完全な同値判定とは呼ばない。一致するものだけ使う判定は健全な十分条件。local.getと定数以外のleaf、call/load/store、除算、浮動小数点、ループ全体は初版の対象外。最適化前の途中値集合がJIT後にも保たれるとは仮定しない。

**保護タスク**：元の実在する内部値を、変換後の全入力・定数・全中間値・出力から少数の機械演算で再構築する。対象は生成後に選ばない。対象の式を解析者に渡して計算させるだけの試験と、例から復元する試験を分離する。単に復元者の文法が弱いことを強度としない。

**差分の候補**：[equivalence reduction](https://pages.cs.wisc.edu/~aws/papers/vmcai19.pdf)の出力同値による正規代表と異なり、出力が同じ候補の観測文脈を複数残す。[LOKI](https://synthesis.to/papers/usenix22-loki.pdf)のdependent superoperatorと問題意識は近いが、具体的な候補削減・選択規則は照合が必要。Pareto集合自体も既知であり、この用途・関係・実効性の差が貢献になるかは未確定。一般的な「攻撃を考慮した合成」は既存なので新規と主張しない。

**解除・費用・Reject理由**：多項式正規化、因数分解、文法拡張、観測値からの式合成で容易に戻る可能性が高い。生成コストと非支配集合のサイズが増える。実行コストも候補の制約次第で増加する。最大のReject理由は、探索規則を改良しても有用な変換を生成できず、復元費用の差が小さいこと。過去の2bit実験では実際にこれが問題だった。

[重みを伴う解釈状態の同期](synchronizing-decoder/README.md)を実Wasmへ実装し、主54条件62,208呼出しと代表回復12条件13,824呼出しの一致を確認した。非可逆遷移で全入口を同じ計算へ収束できたが、代表状態一つで全12sync条件を全状態解析とbyte一致のコードへ回復。元の約3.71–30.80倍の実行費用に対して追加保護の根拠が弱く、weighted synchronizationにも先行性があるため主案に不採用。[実測と再現](../results/invention-20261023/synchronizing-decoder-report-v1/report.md)。

同期語の重み生成を新しい実装仮説として検査したが、fixed/syncや状態数4/8を別発明に数えない。一般のweighted synchronizationへ直接対応し、安い代表要約も残ることが最大のReject理由。
