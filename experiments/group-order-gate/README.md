# Exact group encoding: rejection at the principle gate

## Scope, rule and proof

The contemplated representation maps a w-bit word into a publicly computable group G, with a single canonical encoding E and exact update

    E((x+y) mod 2^w) = E(x) * E(y).

The hypothesis was that group multiplication could replace visible word addition while discrete logarithms hide the word. No auxiliary carry correction, redundant representatives, changing encodings or secret group-operation oracle is included.

Let N=2^w. In a group, E(0)=E(0)^2 implies E(0)=1. Setting g=E(1), repeated addition gives E(x)=g^x, and wrap requires g^N=1. Injectivity additionally requires that g have exact order N. Conversely, this order suffices for both injectivity and correct addition. This argument holds even if the ambient group is noncommutative: the image itself is the cyclic subgroup generated by g. It does not require knowledge of the ambient group order or its factorization.

This exact-order condition supplies the recovery attack. Let q=g^(N/2), which has order two. After removing the recovered low j bits from h=g^x, the remaining exponent is divisible by 2^j. Raising that residual to 2^(w-1-j) yields either 1 or q according to bit j. Remove g^(2^j) if needed and continue. All w bits are recovered. This is the existing 2-power discrete-logarithm bit-lifting method, not a newly invented attack.

The implemented modular unit group checks gcd(g,p)=1, g^N=1 and g^(N/2)!=1; these conditions prove exact order without a primality assumption on p. Width8 uses p=65537, g=3^256 mod p. Width32 uses p=18446744069414584321 and g=7^4294967295 mod p. No claim depends on an unperformed primality test. Products and powers use Python exact integers followed by explicit modulus, not wrapping i64 multiplication.

No XOR, rotation, memory behavior, trapping semantics, full SHA or arbitrary Wasm transformation is implemented. There is no reason to extend a representation already failing the novelty/concealment gate into those operations.

## Fixed evaluation and results

`protocol.json` was written before code execution: one rule, fixed input populations, seed87123, twenty-minute cycle cap, twenty-second attack timeout per subprocess, no parameter search and no dedicated memory cap. Primary metric is exact recovery of the provided encoded values. Correctness is a separate diagnostic. No timing superiority metric was selected.

The observer receives only width, modulus, generator and shuffled encoded values. It has public arithmetic/equality and the recovery algorithm. It receives no challenge exponents, random seed or private table. `recover.py` executes in a separate process reading that JSON from stdin. This is logical information separation, not an OS filesystem sandbox. Recognition/extraction of these boundaries from unknown Wasm is assumed, not evaluated; a digest-only SHA oracle is not sufficient for this experiment's attack model.

## Before/After and actual wrap example

The executable implementation is the pair loop in `check.py`: it mechanically evaluates the following rule for each stored pair. These excerpts are explanatory code, not a claim to have emitted a reusable source-to-Wasm transformer:

```python
# Before, source word domain
expected = (x + y) & ((1 << w) - 1)
# After, group domain; encoded[t] = pow(g, t, p)
actual = encoded[x] * encoded[y] % p
assert actual == encoded[expected]
```
