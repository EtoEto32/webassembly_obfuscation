# Kを吸収したSHA-256スケジュールからphaseを除去できるか

## 1. 状態
Inconclusive（研究目標は継続）。2026-10-12。以下の限定仮説は反例で棄却した。新方式の採用ではない。

## 2. 達成事項
V_t=W_t+K_tを使えば圧縮ラウンドの入力はV_t一本になるが、直前16個のVだけから次のVをphaseなしで計算する案は成立しない。実際の64バイトメッセージ2個を構成して確認した。

## 3. 未達成事項
独立した新規原理、汎用変換器、提案方式のSHA-256適用と解析上の優位性は未達成。この反証を難読化成果に数えない。

## 4. 候補規則・数学的反例
すべての加減算はmod 2^32。標準の小シグマをσ0,σ1とする。

Before: `T1=h+Σ1(e)+Ch(e,f,g)+K_t+W_t`。
想定After: `V_t=W_t+K_t; T1=h+Σ1(e)+Ch(e,f,g)+V_t`。

この置換自体は正しい。しかしスケジュールまでphaseに依存しなくなるわけではない。正確な更新は

```
V_t = σ1(V_(t-2)-K_(t-2)) + V_(t-7)-K_(t-7)
    + σ0(V_(t-15)-K_(t-15)) + V_(t-16)-K_(t-16) + K_t
```

である。元のスケジュール更新は最も古いワードについて逆算できる:

```
W_(t-16) = W_t - σ1(W_(t-2)) - W_(t-7) - σ0(W_(t-15))
```

よって任意の16語ウィンドウを元の16メッセージ語まで戻せる。特にt=16およびt=17の直前のVウィンドウを16語すべて0に指定し、W=V-Kとして逆算した。

|phase t|直前16個のV|必要な次のV_t|
|---|---|---|
|16|すべて0|4081834812|
|17|すべて0|2345487157|

同一引数に二つの異なる結果が必要なので、**この16語だけ**を引数にする単一の決定的更新関数は存在しない。追加phase、外部カウンタ、メッセージ本体、作業状態、別の符号化を使う方式の不可能性ではない。暗号学的ハッシュ衝突でもない。

## 5. 先行研究比較
検索日2026-10-12。検索語: `SHA256 message schedule round constants combined W K precompute obfuscation`。公開技術文書[WO2025012631A1](https://patents.google.com/patent/WO2025012631A1/en)のFigure 2の説明にはWへKを加えた入力を圧縮器へ渡す処理が明記されている。この具体的な加算の移動は既知であり、Wasmへの移植を新規性にしない。特許の有効性・権利範囲の判断ではない。Linuxの2020年パッチも検索結果に出たが本文取得に失敗し、確認済み根拠には採用していない。

|比較項目|判断|

|表現体系|既知定数による可逆なワードごとの平行移動|
|状態変換|phaseごとにW=V-Kで復元可能|
