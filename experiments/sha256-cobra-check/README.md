## 事前選択と攻撃者モデル

`protocol.json` を実行前に保存した。各バイナリについて、local.getとi32.const、add/sub/mul/xor/and/or、定数シフトからなる式の構文木を抽出する。副作用・メモリ読み出し・呼出し・回転・変数シフトを含む木は対象外。シフト定数はWasmの規則に合わせて下位5bitへ正規化する。

演算数1..8、局所変数最大2個の範囲で、変数を最初の出現順にv0/v1へ置換し、同じ式をまとめる。演算数の降順、その後文字列順で各バイナリ4式を選ぶ。難読化の有無で選択条件を変えていない。同一正規化式はバイナリ間でも1回だけCLIへ渡し、結果を再利用する。

解析者にはバイナリが与えられ、抽出した純粋式の変数を独立に変化させられるとする。制御フロー、メモリ状態、呼出し、ラウンド構造を復元する目標は今回扱っていない。抽出器が対象外とした箇所を「解析不能な保護の成功」と数えない。

## CoBRAの結果と出力検査

11/11が式を返し、Unsupported・エラー・タイムアウトは0。各式について境界49点とseed935172の乱数256点を、別実装の剰余整数評価器で照合した。合計3,355比較、不一致0。一変数の式では二変数点の一部が重複するため、3,355個の独立入力とは呼ばない。全i32領域のSMT証明は未実施。

実際に得られた代表的出力:

```text
((v0^v1)+((v0&v1)<<1))  ->  v0 + v1
(0+(v0<<2))             ->  4 * v0
(v0+1)                 ->  -~v0
```

最後の例は演算数が1から2へ増え、採用しなかった。「返された」ことと「簡約された」ことを分けている。11式のうち演算数が減った式族は先頭2種類だけである。

## Wasmへの反映と完全SHA検査

式結果を見た後、`rewrite-plan.json` に追加検証を明記してから `rewrite.py` を実装・実行した。この段階は事前の主指標とは分けた探索的な追加実験である。

採用したCoBRA出力のASTをWATへ変換し、元のlocal参照へ戻す。出力を組み込んだ同じ式族が現れる部分木を、外側から置換した。MBAという名前や生成元の変数表を復元器へ渡していない。定数・localのみの式に限定し、値の読み出し回数が変わっても副作用を失わない範囲である。

今回採用された2規則は、`x+y=(x XOR y)+2(x AND y) mod 2^32` と `0+(x<<2)=4x mod 2^32` で数学的にも説明できる。これを任意のCoBRA出力に対する正確性保証へ一般化しない。

| バイナリ | 置換箇所 | 反映後bytes | SHA検査 |
|---|---:|---:|---:|
| MBA O2 | 1 | 3,271 | 531/531 |
| MBA O3 | 2 | 7,013 | 531/531 |
| MBA raw | 2 | 3,299 | 531/531 |
| plain O2 | 0 | 3,097 | 531/531 |
| plain O3 | 0 | 4,990 | 531/531 |
| plain raw | 1 | 3,125 | 531/531 |

再アセンブルとwasm-validateが成功。合計3,186件の完全SHA出力が既存入力データ一式の期待値に一致した。各期待値は入力からNode暗号ライブラリでも再計算した。入力bytes・末尾canaryを保存し、各バイナリで4種類の不正長がtrapしてメモリを変更しないこと、その後のabc呼出しが成功することも確認した。新しい入力集団を作った試験ではなく、保存済みの同じ531入力を再実行した結果である。

O3全体の難読化を除去したとは主張しない。構造が最適化後にも残ることと、この限られた局所解析で戻せることは両立する。plain rawの置換はアドレス式のゼロ加算除去であり、難読化の除去ではない。MBAのstatic call site159箇所を159件復元したという数え方もしない。
