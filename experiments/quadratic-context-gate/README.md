# 二次復元空間を合成時の比較キーにする案の反例

## 1. 状態：Inconclusive

2026-10-12。研究目標は未達で、状態はactive（継続中）。採用した新しい難読化アルゴリズムはない。本実験は、候補合成の際に誤った枝刈りを導入しないための設計検証であり、難読化の有効性実験ではない。

## 2. 達成事項

「出力・コスト・二次復元空間が同じなら、一方の候補を捨てられる」という合成規則案を、実装前に検証した。全32入力で二次復元空間が等しくなる候補対を作り、25種類の共通文脈を調べたところ、2種類で復元できるかどうかに違いが生じた。候補を単独で評価した結果だけでは、文脈内での比較結果は保たれないことを確認した。

## 3. 未達事項

## 4. 検討規則と反例の定義

観測された各値を公開入力に対するブール関数として表し、定数1、各観測値、任意の2観測値の積のGF(2)線形包をB2(P)とする。観測値の個数とXOR項数は無制限、積の次数だけを2以下に制限する。検討した規則は `output(P)=output(Q), cost(P)=cost(Q), B2(P)=B2(Q)` を合成時の同一性を判定するキーにするもの。

全公開入力はa,b,c,d,eの5ビットであり、最初から両候補の観測に含める。

- Pは10種類の二変数積からacを除いた9種類を計算する。
- Qは同じ集合からabを除いた9種類を計算する。
- 各積vを計算するたびに、0から始めたaccumulatorへvを2回XORする。全積と全accumulator更新を観測し、出力は0。

どちらも9 AND + 18 XOR = 27演算。PとQは同じ出力で、単独の二次復元空間は同じ31次元になる。診断対象T=abcdeは実験前に固定し、両者の空間に含まれない。

共通文脈で `h=(c AND d) AND e; result=output XOR h` を計算し、途中のcd、h、最終出力まで観測する。Pにはabがあるので `ab AND h` でTを復元できる。Qの各一次・二次特徴は、5変数すべての積のANF係数が0であり、そのXOR結合でもTを表せない。Tの当該係数は1なので、これは有限デコーダ列挙の不成功だけに依存しない証明になる。

Qでも三次式 `a*b*h` なら復元できる。したがって本結果は限定した次数モデルの差であり、一般解析者に対する強度ではない。

## 7. 実装と結果

`protocol.json` を先に保存し、`check.py` を実行した。候補と文脈のブール演算を実際に評価し、全入力に対する関数表を整数のビット列として保持した。

| 条件 | Pの二次空間次元 | Qの二次空間次元 | Tの復元 |
|---|---:|---:|---|
| 単独 | 31 | 31 | 双方不可、空間自体も等しい |
| 文脈bde | 31 | 32 | Qのみ可能 |
| 文脈cde | 32 | 31 | Pのみ可能 |

次数1～3の単項式文脈25種類をすべて実行。上の2種類で分離した。cdeのP復元式を全32入力で直接照合した。Qの740個の特徴（重複あり）はすべて、完全真理値表のパリティが偶数だった。このパリティは5変数ANFの最高次係数である。Tのパリティは奇数なので、ガウス消去法とは別の理由で非包含を確認できる。

保存したトレースには全入力、すべての内部値、全出力がある。有限ブールモデルの全数検査であり、i32やWasmの意味が保存されることの検証ではない。

## 8. 攻撃比較

一般の復元攻撃や既存難読化方式との比較は未実施。Tは診断用に置いた公開入力の関数で、保護対象の秘密ではない。Pでの一つのANDとQでの二つのANDの差を、実用的な強度改善と数えない。

## 9. 性能・サイズ・残存性

Wasmは生成しておらず、速度、サイズ、最適化後の状態は測定していない。候補には明らかなXORの相殺があり、通常の最適化で内部計算が消える可能性がある。このようなサンプルを保護用の実装として提案したものではない。生成探索で使う数学的な比較キーの健全性だけを調べた。

## 10. 改善サイクル

既存の線形包による比較を、より多くの候補をまとめられそうな二次特徴空間へ置き換える案を検討した。実験により合成時の安全性が否定されたため、この変更を既存探索器へ導入しない。線形包の包含では、各観測値を線形結合へ置換しても積の次数が増えないという以前の理由がある。本反例はその規則への反例ではない。

結果から得る条件は、複合特徴へ要約する際に「その特徴を何次で作れたか」を捨てないこと。ただし、それだけで新しい有用な合成アルゴリズムができたとはしない。予算20分、実行60秒以内、固定文脈25種類。規模拡大はしなかった。

## 11. サンプルと差分

サンプルID QUADRATIC-CONTEXT-1。実行した完全コードは `check.py` のrun_blockとrun_context。差分は次の通りで、P/Qは手書きの研究用プログラムである。

```diff
- P: all pair products except ac
+ Q: all pair products except ab
  acc = 0
  for value in computed_pairs:
      acc = acc XOR value
      acc = acc XOR value
  return acc
```

出力0の機能は保存されるが、後続処理cde/bdeで復元空間の順序が逆転する。生成器が作った難読化WATや、最適化後のコードではない。

## 13. 限界

純粋なブール演算の数学的な観測モデルだけを扱う。ソース、命令形状、実行順序、最適化、解析者の計算時間は空間の比較には含めていない。独立した変換原理の発明は未達。今回除外したのは一つの不健全な合成時の比較キーであり、正しいキーを用いれば有効な難読化を発見できると保証するものではない。
