## 2. 達成事項

固定済みのProMBAソースで、規則の一般化と検証幅の選択を追跡した。選択された8ビット幅では全入力で正しい式が、32/64ビットでは誤る具体例を構成して実行した。元の制約付き規則は、広いビット幅でも正しい。この結果から、今後の解析評価では、返された式を対象のビット幅で別途検証する必要があることを具体的に示した。

## 4. 具体的な式と確認範囲

`F(t)=t(t-1)…(t-9)`、`g=x AND 1` とする。元の規則は

```text
F(g)+g = g
```

である。gは0または1なのでF(g)=0となり、任意の固定ビット幅で成立する。共有部分式gを無制約の変数tへ置換すると、一般化候補は `F(t)+t=t`。

連続10整数の積は10!で割り切れ、10!=3,628,800は256の倍数なので、一般化候補は8ビットでは恒等式になる。一方、32/64ビットでt=10なら左辺は3,628,810、右辺は10となる。

この反例では、**元の規則の正しさ**と**一般化後の正しさ**と**検証幅**を区別する。誤った一般化候補を難読化変換として採用してはいけない。
