# 履歴の列位置を隠した場合の復元試験

## 1. 状態

Inconclusive。研究目標は未達で、状態はactive（継続中）。本試験は採用済み新方式ではなく、前候補に固定の列置換とダミー値を追加する改善案の棄却検査である。2026-10-12に実行した。

## 2. 達成事項

48列のうち24列を履歴、22列を独立乱数、2列をゼロとカウンタとした。4種類の固定置換について、空入力の連続5観測だけから24列の位置と順序を推定できた。推定に使わなかった各9,097観測、延べ36,388観測で履歴と状態8語・スケジュール16語が保存済み値に一致した。独立した元の観測数は9,097であり36,388ではない。

## 3. 未達事項

独立した新規原理、再利用可能な新規Wasm変換器、新方式のSHA全体の実行、既存方式を上回る解析困難性は未達。本試験ではSHA出力検証を再実行していない。

## 4. 検査した機構

前候補は H[k]=A_(i-1-k), 0<=k<24 を保持し、H'=[A_new]+H[:23] と更新する。観測列を固定置換πで隠しても、真の履歴列には x_t[π^-1(k)]=x_(t+1)[π^-1(k+1)] が成立する。

`recover.py` は全4遷移で値が等しい異なる列の組を有向辺にする。入次数・出次数が一意な長さ24の鎖を探し、一意でなければ拒否する。既知の履歴長24を使うが、秘密の置換、列名、正解状態を引数として受け取らない。復元後の状態・スケジュールの復号式は前実験の `observer` を再利用する。これは新しい難読化原理の発明ではない。

## 5. 先行研究と新規性

2026-10-12に一次資料 [Kargén and Shahmehri, Towards Robust Instruction-Level Trace Alignment of Binary Code, ASE 2017](https://www.ida.liu.se/~ulfka17/papers/ase17main-mainp488-p-71fccdb-34324-preprint.pdf) の要旨・導入・II節冒頭を確認した。論文は命令の具体的な入出力値を照合特徴として、動的トレースを対応付ける。著者実装は実行していない。

| 項目 | 既存研究との関係 |
| --- | --- |
| 数学的原理 | 本検査はコピー等値関係のグラフ探索。論文のDTWを再現したものではない |
| 表現体系 | 固定列置換とダミー追加に独立した新規性を認めない |
| 状態変換 | 前実験の履歴表現を変更せず観測を後処理する |
| 依存関係 | 隣接ラウンド間のコピー関係がそのまま残る |
| 困難性 | 列位置の秘匿だけでは本攻撃への障害にならなかった |
| 一般化 | 同じ長さの一意なコピー鎖に適用可能。任意のWasmには未検証 |

この論文だけですべての構造変換の新規性を否定することはできない。本試験の棄却理由は実測された復元成功である。

## 6. 再利用資産

`sha-joint-history-gate/artifacts/observations.jsonl.gz` と既知の復号関数を利用した（分類A: 今回の保存トレース検査に利用可能）。元データは36入力・222ブロックの9,102境界観測。展開後SHA-256は `bd7877747ec3b1739fe77c6c0730f075bf4f287e0210d3d3b2e8d4b6d72753cf` で、実行時に元の結果と照合した。元候補自体は分類C（復元可能な候補の参考）。Wasm実装の証拠には再利用しない。

## 7. 実装・検証結果

Python 3.12.14。`protocol.json` に条件を事前保存し、`check.py` を終了コード0で実行した。4置換すべてで位置の推定・履歴照合・復号値照合に成功。全ゼロ観測と履歴を二重化した観測は各4回、計8回拒否した。二重化は交差する等値辺も生むため、実装上は一意な鎖候補が0になる。独立した2本の鎖を列挙できたという意味ではない。

## 8. 攻撃評価

攻撃入力は既にラウンド境界に整列した匿名列。表現系列と履歴長を既知とし、既知の復号器を使う。バイナリ抽出、境界検出、表現系列の識別は評価外。正解置換は評価側のみが照合に利用するが、OSプロセスとして攻撃側を隔離した実験ではない。

主要評価は推定に使わなかった観測の復元一致数。4/4置換、36,388/36,388観測が一致した。plain/MBA/新方式の公平なWasm攻撃比較ではない。全ゼロ等の曖昧な観測を拒否できても、それ自体は難読化強度を意味しない。

## 9. コストと最適化

列順序推定だけの時間はシード順に 0.0011191, 0.0012165, 0.0012321, 0.0013190 秒。各1回で統計的な速度比較ではなく、入出力・復号・トレース取得時間を含まない。難読化後Wasmの実行性能・サイズ・最適化後の残存性は測定していない。ローカル実行は約5.2秒で終了した。

## 10. 改善サイクル

元仮説: 既知の配列順序が前候補の復元を容易にした可能性がある。
変更: 配列順序を隠し、24列の余分な観測を追加した。
結果: コピー関係から列位置を復元できた。
判断: 固定の並べ替えと独立ダミー追加だけで弱点を補う案を棄却する。同じ案の置換数だけを増やす探索は行わない。ラウンド境界が未知の場合や値そのものの異なる表現を、この結果だけで棄却しない。
