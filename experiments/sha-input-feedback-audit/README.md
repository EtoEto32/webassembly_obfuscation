## 4. 数学的規則

すべて32bit、加減算はmod2^32。既存sha-history-gateの全単射p=E(s)、復号D(p)をそのまま使用する。

```text
e_j = p_j + p_(j+4) - Q(p_(j+1),p_(j+2),p_(j+3))   j=0..3
f(p) = e_3 + Σ1(e_0) + Ch(e_0,e_1,e_2) + Q(p_0,p_1,p_2)
u = K_i + W_i
v = f(p) + u
p' = (v,p_0,p_1,p_2,p_3,p_4,p_5,p_6)
u = v - f(p)
```

Q=Σ0+Maj。固定pでu↔vは全単射なので状態・入力の変換として正しい。D(p')は通常SHAの次状態と一致する。意味保存の根拠は既存履歴座標の式への代入であり、滑らかな実数系の定理を適用したものではない。

しかしvを作るinput_encodeはf(p)を評価する。fには4個のe復元とΣ1、Ch、Qがそのまま残る。shiftだけを評価範囲にすると、この処理を計上し損ねる。実装は既存history_stepの先頭式をinput_encodeへ移したものと完全に同じ。

さらにvを状態を見ずに(i,W_i)だけから求めることはこの規則では不可能。s=0とs=(0,0,0,0,0,0,0,1)では、同じuに対してvが1だけ異なる。両状態は標準IVから境界8へ到達でき、後続W8=0の64byteメッセージを構成した。全メッセージや過去の軌道を調べてvを計算する別手順を否定する結果ではないが、その計算を無料にはできない。
