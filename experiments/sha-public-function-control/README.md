# 公開SHA-256に対する対象を参照しないの負の対照

## 1. 状態
2026-10-12。Inconclusive、研究目標の状態はactive（継続中）。新しい難読化方式は未確立。この実験は今後の攻撃成功条件の妥当性を確認するための負の対照である。

## 2. 達成事項
対象Wasm・トレースを一切読まない関数が、既存531入力の期待ダイジェストすべてと一致した。「機能一致だけ」を対象固有の解析成功として扱えないことを実行可能な対照で示した。

## 3. 未達成事項
独立した新規原理、提案方式の変換器、提案方式のSHA適用、既存方式への解析上の優位性は未達。

## 4. 数学的条件
既知の公開関数fと、それを保存する任意の変換Oを考える。成功条件が `forall x: A(O(f))(x)=f(x)` のみなら、Aは引数を無視して既知のfを返せばよい。これはOの内部構造によらない。したがって、その条件だけから各Oの復元耐性の差を得ることはできない。

この議論は公開関数が既知で、代替実装が許される場合に限定する。厳密なWasm ABI、メモリに対するすべての副作用、性能上限、未知のパラメータなど追加条件を課した課題を自動的に解くとは主張しない。

## 5. 新規性・先行研究との関係
新しい難読化原理・解析アルゴリズム・数学定理の主張はない。公開関数の定義から直接導いた評価上の区別であり、新たな文献の未発見を新規性に使わない。

## 6. 再利用
sha256-research-baseline/artifactsの入力531件、4,400,287 bytesの入力データ一式と期待値を再利用。入力データ一式の保存SHA-256一致を実行前に検査。SHA実装を再作成せずnode:cryptoを使用した。元の期待値生成にもNode/OpenSSLが関与するため、独立したSHA実装の正当性検証ではない。今回の目的は対象情報を必要としない対照の確認である。

## 7. 実装・検証結果
check.cjsのattack(message)は入力だけを受け取り、node:cryptoでSHA-256を計算する。期待値は検証側だけが比較に使用する。対象Wasm読み取り0、対象トレース読み取り0、531/531一致。Node v24.15.0。詳細と入力・コードのハッシュはresults.json。

同一プロセス内の関数分離でありOSレベルのアクセス隔離ではない。非参照という性質はコードが対象パスを開かず、対象データを引数にも取らないことから確認する。これはWasmを出力する解除器ではない。

## 8. 攻撃成功条件への反映
次候補の比較では、次を明確に区別する。

- ハッシュ出力一致は正確性検証。これだけを難読化解除成功としない。
- 公開メッセージから標準ラウンド状態を再計算して並べることも、変換後バイナリ内の状態の対応付けとは異なる。
- 内部構造の復元を主要指標にするなら、解析器が何を返すかを事前に定義する。例えば対象の命令位置・状態成分と復元式の対応、およびその対応を検証する対象内の実行区間である。
- その検証器には、対象を無視して標準実装を返す対照と、誤った対応付けを返す対照を通し、成功と数えないことを確かめる。単に標準トレースと値が一致するだけでは不十分。

具体的な対応付け検証器は未実装。新候補の表現が定まった時に、観測地点・許される再計算・式のコスト・保持する必要がある副作用まで固定する必要がある。攻撃者の知識を結果に合わせて弱めることはしない。
