# 表現を固定しない状態遷移合成の有限試作

2026-10-12。**Inconclusive。新規難読化方式としては不採用。元の研究目標は未達・継続中。**

## 目的と前回からの差

既存 `tmp/encoding-cosynthesis-gate` は復号関係を多項式に固定し、`tmp/ssa-update-search` は XOR 表現を固定していた。今回は更新プログラムの候補を先に選び、任意の全単射 E を遷移の対応から求める。復号式の係数や次数は指定しない。この欠けていた探索を有限モデルで実装したが、合成できることと、新しい保護原理があることを区別する。

`tmp/shared-transition-gate` の「異なる元演算を一つの同じ更新にする」問題とも異なる。ここでは二つのラベル付き更新 U0/U1 を許し、双方で同じ表現 E を使用する。演算ラベルを隠す仕組みはない。

今回の判定は、小さい文法を一度だけ全探索したもの。探索の幅・深さや乱数試行を増やし続けない。新規性が薄い表現表の Wasm 化や SHA 移植は実施しない。

## 数学的仕様

状態 S={(x,y):0<=x,y<2^w}、今回は w=3。二つの純粋な遷移を固定する。

    T0(x,y) = (x+y mod 2^w, y)
    T1(x,y) = (x XOR rotl_w(y,1), y+1 mod 2^w)

候補は全単射 E:S→S と、文法内の更新 U0,U1。条件は全状態について

    E(Ti(s)) = Ui(E(s))   (i=0,1)

である。これが成立すれば、任意の有限ラベル列について帰納的に状態の対応が保存される。入出力の境界には E と E^-1 が必要であり、その生成・実装費用を無料とみなした実用方式ではない。本試作はその対応表と更新関数までを扱う。

更新文法は `protocol.json` に列挙した17種類の可逆な二変数演算を最大2回合成したもの。加算・減算・XOR による片側更新、1増減、回転、変数交換、3倍などを含む。「2回」は文法部品数であり、Wasm命令数ではない。状態整数は x | (y << w)。加減乗算は明示的に幅へ切り詰める。メモリ、trap、分岐の副作用、外部呼出しは対象外。

各 Ti、Ui は有限集合の置換なので、対応する置換の巡回長の多重集合は同じでなければならない。まずこの必要条件で候補を絞る。条件を通った組について E(0,0) の64通りを試し、遷移辺に沿って E(Ti(s))=Ui(E(s)) を伝播する。既定値との矛盾や単射性の違反が出れば棄却する。

元の根 (0,0) から全状態へ到達する。T1でy=1へ進み、そこでT0を繰り返すと全xへ到達し、その後T1を繰り返して各yへ移れる。従って一つの根の像を決めれば E は高々一つであり、全64根を試す検査はこのモデルの全単射を取りこぼさない。候補プログラムの全64点での遷移表が同じ場合だけ同一視し、構文別名も保存する。ただし途中値や実行トレースは同一とは扱えないため、この削減を解析耐性の最適化へ転用していない。

この可換条件と探索は既存の遷移同型・共役の考え方である。新しい数学的変換則という主張はしない。

## 解析モデルと、その限界

解析者は元の T0/T1 の意味、対応するラベル、幅、公開された初期化処理で得た E(0,0)、各 Ui の全64状態での遷移表を知る。未知の E 表は渡さない。`conjugacy.py` を別プロセスで実行し、`attack.public.json` のみを標準入力として与えた。全32表を正確に復元した。これは情報の論理的分離であり、OSサンドボックスによる隔離ではない。

解析は合成器と同じ伝播関数を利用する。独立した攻撃実装との比較とは主張しない。一方、生成側の秘密表を必要としないことと、有限の正確性は検査した。入力として全遷移表を渡しているため、実験は未知バイナリからの命令認識、元演算の推測、状態境界の抽出、oracleの切り出しを評価しない。小状態のすべての表照会であり、i32の2変数では状態数が2^64になる。今回の全域列挙を、そのまま実幅で効率的な攻撃と呼んではいけない。

**不採用の理由**は、これが通常の共役による状態符号化を超える独立した原理をまだ持たず、小モデルの保護効果も確認できなかったことである。32/32復元の数だけから、あらゆる大状態・異なる観測条件の符号化が弱いとは結論しない。
