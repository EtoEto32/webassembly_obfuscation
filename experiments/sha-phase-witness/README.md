# 実際のSHA-256でのラウンド位置の識別不能例

## 1. 状態

2026-10-12。**Inconclusive。新規アルゴリズムの発明という研究目標は未達で、状態はactive（継続中）。** 新規難読化方式は採用していない。前回の置換平方根モデルの反例をSHA全体へ一般化する代わりに、別の限定案を実際の32bit SHA-256で検査した。

## 2. 達成事項

異なる二つの64byteメッセージを構成し、最初の圧縮ブロックで、一方の8ラウンド終了時と他方の9ラウンド終了時が同じ作業状態になることを確認した。次のW語も同じだが次状態は異なる。raw/O2の実Wasmで観測し、完全SHA出力も確認した。

## 3. 未達事項

独立した新規原理、対応するWasm難読化変換器、既存方式を上回る攻撃耐性、公平な三者比較は未達。今回は正しいSHA実行中の反例を作ったのであり、新方式がSHAへ適用できたのではない。

## 4. 規則・反例・適用範囲

検討した限定案: ラウンド番号iを保持せず、**変更していない**8作業語sと現在のW語だけから次のSHA状態を決定する、単一の決定的関数U(s,W)を使う。定数K_iもs,Wから選べると仮定する。メッセージ全体、スケジュール配列、アドレス、呼出し位置、外部カウンタなどをUへ渡す案は対象外。

境界bはラウンド0..b-1を完了した位置を指す。構成した状態は次の通り。全数値は符号なし32bit。

| メッセージ | 境界 | 作業状態a..h | 次のW | 次の作業状態 |
| --- | --- | --- | --- | --- |
| at8 | 8 | (0,0,0,0,0,0,0,0) | 0 | (3624381080,0,0,0,3624381080,0,0,0) |
| at9 | 9 | (0,0,0,0,0,0,0,0) | 0 | (310598401,0,0,0,310598401,0,0,0) |

同じ入力(s,W)を持つ決定的Uが両方の異なる出力を返すことはできない。違いはK8=0xd807aa98とK9=0x12835b01による。sから一意なラウンド番号を求める関数も、この二つの到達状態では定義できない。これは有限実行から得た具体的な反例であり、SHAの状態全域を列挙したものではない。

構成は既存の8ラウンド到達手順を利用する。at8は保存済みのゼロ状態への32byte接頭辞に32byteのゼロを追加した。at9は境界8の状態を (0,0,0,0,0,0,0,-K8 mod 2^32) にする接頭辞を作る。W8=0を与えるとラウンド8後にゼロになる。両メッセージで後半8語はすべてゼロなので、比較する次Wも0である。

**完全な機械状態は同じではない。** メッセージ、スケジュール、ラウンド位置等は異なる。ダイジェストも異なる。ハッシュ衝突・原像攻撃・暗号強度の低下を示す結果ではない。iを含めて別表現E(i,s)へ写す方式や、K_i+W_iを別途供給する通常の共通round関数は、この反例の仮定を満たさない。

## 5. 先行研究・新規性

[NIST FIPS 180-4](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf) の§6.2.2を2026-10-12に本文確認した。W0..15がメッセージ語である点と、K_t、W_tを使うmod2^32の更新式を根拠にする。これは規格の標準式であり、新しい暗号的性質として発明を主張しない。

探索検索語は `"SHA-256" "inverse round" state reversible`、`"obfuscation" "continuation" "data" transformation`、`"obfuscation" "automatic differentiation"`。検索で見つかった非査読の逆ラウンド実験サイトは比較根拠に採用しなかった。CPS変換の検索結果も今回の候補の同一性を示す一次資料として使用していない。新規性の支持材料は得られていない。

| 比較事項 | 判定 |
| --- | --- |
| 数学的原理 | 通常のSHA更新と既存の到達状態構成 |
| 表現 | 元の8語を維持。共同符号化ではない |
| 状態遷移 | 段階を入力から省略する案が一意性を失う |
| 依存構造 | ラウンド定数への依存が残る |
| 解析困難性 | 未評価。正しさの段階で不成立 |
| 一般化 | 上記U(s,W)に限定。すべてのカウンタ除去法を否定しない |

Python3.12.14で二つの入力を生成し、Python hashlibで期待ダイジェストを計算。Node v24.15.0（V8 13.6.233.17-node.48）でWasmを実行し、Node cryptoでも照合した。

- Before/raw観測/O2観測の3本×2メッセージ: 完全ダイジェスト6件一致。
- 観測2本×2メッセージ×境界8,9,10: 作業状態12件一致。
- 同じ状態・同じW・異なる次状態: raw/O2でそれぞれ確認。同じ入力対の2条件であり、独立した反例2組ではない。
- 二つの最終ダイジェストが異なること、入力メモリが変更されないこと、Beforeが観測用領域を書き換えないことも確認。

全3本をwasm-validateで検証。SMTは未実行。今回の新しい完全SHAテストの入力は二つだけであり、既存531入力の回帰試験を再実行したとは報告しない。
