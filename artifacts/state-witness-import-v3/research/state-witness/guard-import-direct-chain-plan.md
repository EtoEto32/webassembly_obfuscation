# 直接反例構成の長い列と代表値の検査

2026-10-24。280否定caseの正式費用比較後に固定する追加検査。小caseの最長3 APIからの一般化を避ける。

既存の1/8/32/96 cellのprivate table遅延chainを同じbinaryのまま使う。host read有無と必須全書込み/任意部分書込みの4契約を試す。初期tableはB、左はA/B segmentをretireし、右はBだけretireする。直接生成器が返した**実際の入力とAPI列**をNode/Wasmtimeで新たに再生する。反例なしの必須write/readなし契約には、既知のseed→step^Nを対照として実行する。この一列の一致を全列同値の証明とはしない。

別のSMT検査で、公開2cell・private1cellの各sortの等式atomについて、任意全書込みによる反例があるのにbaseと一cell変更の候補が全て成功する状態がないことを検査する。memoryはbyte、tableはnull/参照を表す整数である。一般Boolean式については、候補に含まれない二cell同時変更だけで偽になる反例を保存する。有限atom群のUNSATと、任意長の等式連言についての数学的議論を区別する。

性能比較の280caseやその中央値にはこの追加検査を混ぜない。生成器の新しい最短性主張も加えない。
